# Always-on agents lack the backend SecondBrain specifies

None of the four always-on agents replaces SecondBrain, and only one of them can reach it without breaking its privacy posture. Hermes Agent runs as a single-tenant process on hardware the user controls, speaks any OpenAI-compatible endpoint including the vLLM box SecondBrain already qualifies against, and ships a complete MCP client — remote Streamable HTTP with `Authorization: Bearer ${TOKEN}` headers, an `ssl_verify` path for an internal CA, per-server `tools.include` lists and a `trust: untrusted` mode that forces approval on write-capable tools — so it is the first always-on agent that could consume SecondBrain's **[spec]** MCP server over a Tailscale address exactly as designed, with OpenClaw (391k stars and the worse security record) as the same kind of client. Grok Bot (xAI/SpaceXAI, hosted on Cursor's US Firecracker VMs), Meta's Muse (a per-user "Secure VM" in Meta's cloud) and OpenAI's Dots (a GPT-6 Astra agent whose OpenAI-side context cannot be viewed, edited or exported) are cloud-custodied action agents that reach a self-hosted MCP server only through a public HTTPS endpoint or egress routed through the user's desktop — precisely what SecondBrain's `local_only` switch, the one guarantee that is **[implemented]** at the committed M0 snapshot, forbids. All four treat memory as a by-product of acting: Grok Bot's Auto Review "does not review every side effect. Memory writes and most settings changes are examples", Dots' memories can be cleared only by deleting the dot, Muse's model-written `MEMORY.md` "may still remember" deleted facts, and Hermes's `write_approval` for memory is off by default; none types knowledge, cites a revision, reports degraded retrieval or records which credential wrote a fact. The wave therefore crowds the earlier report's "human-approved writes" row with approval systems that all exempt memory and all decay through "Always allow" rules, leaves its provenance, typed-SQL, citation and egress-manifest rows untouched, and supplies the strongest validation yet of its no-public-bind, no-skill-loop design, because 2026's incidents were control-plane and supply-chain failures — Hermes's CVSS 8.8 remote code execution from opening a repository and roughly 5,900 exposed dashboards, OpenClaw's one-click RCE on loopback and 824 malicious marketplace skills, Muse's pre-launch KVM-escape rush and macOS zero-day — rather than model failures. The consequences for SecondBrain are a sharper positioning (the audited knowledge backend and write gate for self-hosted always-on agents, which Hermes's own RAG proposal has left open at priority P3 since March), a reordered M2 (stateless HTTP MCP over the tailnet with bearer keys and accurate tool annotations, shipped with rather than after the stdio bridge), and four mechanisms worth borrowing: Muse's single out-of-model egress authority with tainted-egress tracking and out-of-band approvals, Dots' read-only unattended mode enforced in code, Grok Bot's expiring unattended approvals, and Hermes's untrusted-server and staged memory-write model. At the committed snapshot SecondBrain has no MCP endpoint, no chat and no index, so every complement described here is a design claim until M2 ships.

Two conventions hold throughout. Every SecondBrain statement is tagged **[spec]** (design intent in `spec.md` Draft v0.6, dated 2026-10-08, unchanged between commit `0a06b18` and HEAD, with line links at `0a06b18`) or **[implemented]** (verified in the committed code at HEAD `ba81f95`, which merged PR #1 after commit `34f2d15`, "Close M0 for the Fedora and Tailscale reference deployment", a commit that touched only the README, deploy docs and build reports). Line links into `docs/build/M0-convergence-report.md` use the commits the research notes were taken at — `0a06b18` for lines up to 297 and `b2016a2` for the addendum at lines 299-320 — because three later commits appended to that file, which runs to 347 lines at HEAD, so those anchors are offset in the current working tree. The earlier report's conclusions are cited as such and not re-derived. The working tree on 2026-10-09 also holds roughly 110 uncommitted or untracked changes — an `M1Schema.cs` creating an FTS5 `chunks_fts` table, a PdfPig-based `DocumentParser.cs`, a `/v1/search` mapping in `KnowledgeEndpoints.cs`, retrieval and rerank code, an `eval/` directory, an `M1-convergence-report.md` draft that opens "M1 is not closed", and an `M2-ask-and-mcp.md` draft marked "Planning only" — none of which is in any commit or was built or tested for this report, so "[implemented]" here means the committed M0 state and understates work in progress. No `LICENSE` file exists at HEAD. Competitor facts carry the URL recorded in the research notes; sources the notes mark as secondary, press, community, tracker, semi-official, search extraction or unverified are flagged in the citation label, and unflagged sources are the vendor's or project's own pages.

## Four agents act in the world; none keeps an owned, typed, cited store

The four products share one shape that SecondBrain does not have and do not have the one thing SecondBrain is for. Each gives a model its own computer — Hermes the user's own box or VPS, Grok Bot a Firecracker microVM in Cursor's US cloud, Muse a "Secure VM" in Meta's cloud, Dots a Linux machine with Chrome in OpenAI's — and sells the ability to act in other people's apps 24/7 with the user absent; memory is what accumulates while acting, and approvals exist to gate actions in the world (sending, buying, deleting), not writes to what the agent knows. SecondBrain's **[spec]** is the inverse: it never acts outside its vault — the `ask` surfaces are read-only with "no shell, no network" ([spec.md L639](../spec.md#L639)) — and every non-additive write to knowledge is a pending operation that "Only an interactive UI session approves"; "API keys and the bridge can never approve" ([spec.md L640](../spec.md#L640)). ## Hermes runs on your hardware and already speaks SecondBrain's dialect

Hermes Agent is the one member of the wave that shares SecondBrain's deployment premise. Nous Research released it under MIT in February 2026; by 2026-10-09 the repository showed **252,232 stars, roughly 4,400 contributors** and a v0.21.6 release that "rolls up the ~2,100 PRs merged since v0.21.5" two weeks earlier ([GitHub API](https://github.com/NousResearch/hermes-agent), [Release v0.21.6](https://github.com/NousResearch/hermes-agent/releases/tag/v0.21.6)). Nous's October fundraise note says the agent has "been cloned over 24 million times", names NVIDIA, Microsoft's M12, Samsung, Union Square Ventures and Y Combinator among the investors in a $90M round, and states the design principle that matters here: "Users choose where Hermes Agent runs and which models it uses" ([Nous Research](https://nousresearch.com/a-note-on-our-fundraise)); press puts the round at a $1.5B valuation and about $36M annualised revenue, figures Nous has not confirmed ([Dealroom, secondary](https://dealroom.co/news/160592-nous-research-raises-90m-at-1-5b-valuation-for-open-source-ai/)). The product is a single-tenant Python process — SECURITY.md defines the "Agent process" as "the Python interpreter running Hermes Agent, including any Python modules it has loaded (skills, plugins, hook handlers)" — installed on Linux, macOS, Windows, Termux, a VPS, Docker or hibernating sandboxes such as Modal and Daytona, with one background gateway process bridging it to Telegram, Discord, Slack, WhatsApp, Signal, Matrix, Home Assistant and some thirty other adapters that by default deny any sender not allowlisted or paired ([SECURITY.md](https://github.com/NousResearch/hermes-agent/blob/main/SECURITY.md), [README](https://github.com/NousResearch/hermes-agent), [Messaging Gateway docs](https://hermes-agent.nousresearch.com/docs/user-guide/messaging/)). A loopback web dashboard on port 9119, an off-by-default OpenAI-compatible API server, a desktop app and the optional Nous-hosted "Hermes Cloud" complete the surface; the official image runs the gateway as UID 10000 and refuses to run as root, but the repository's own `docker-compose.yml` uses `network_mode: host` ([Web dashboard docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/web-dashboard), [Docker docs](https://hermes-agent.nousresearch.com/docs/user-guide/docker), [Manage Hermes Cloud with MCP](https://hermes-agent.nousresearch.com/docs/guides/manage-hermes-cloud-with-mcp)).

What Hermes remembers is small, plain and unaudited. Built-in memory is two files the model writes through a `memory` tool — `~/.hermes/memories/MEMORY.md`, capped at 2,200 characters, and `USER.md`, capped at 1,375 — injected into the system prompt as a "frozen snapshot" at session start, with `add`, `replace` and `remove` actions and "no `read` action"; everything else is a SQLite `state.db` holding every CLI and messaging transcript under FTS5 ([Memory docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory)). The user owns all of it in the sense that it sits in `~/.hermes/` as text and ordinary SQLite, but the schema has `sessions` and `messages` tables with tool calls "stored as a JSON string", "no approvals, cron-run or audit tables", and export only through a Python API ([Session storage](https://hermes-agent.nousresearch.com/docs/developer-guide/session-storage), [FAQ](https://hermes-agent.nousresearch.com/docs/reference/faq)). Richer modelling is pushed outward to nine documented external providers (Honcho, Mem0, Supermemory, Hindsight, OpenViking, Holographic, RetainDB, ByteRover, Memori), one active at a time and several cloud-hosted: "Cloud providers send conversation data to the vendor's servers", and "The Mem0 SDK sends anonymous PostHog usage telemetry unless `MEM0_TELEMETRY=false` is set" ([Memory providers](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory-providers)). There is no knowledge index at all: `read_file` converts documents on demand (PDF text layer only, "Documents over 50 MB are refused", scanned pages "silently convert to nothing"), retrieval over a notes folder is "agentic exploration via search_files + read_file", and the maintainer-filed RAG proposal #844 — local embeddings with a sqlite-vec plus FTS5 hybrid over a user-configured document directory — has sat open at priority P3 since 2026-03-10 with no maintainer reply ([Document extraction](https://hermes-agent.nousresearch.com/docs/user-guide/features/document-extraction), [Issue #844](https://github.com/NousResearch/hermes-agent/issues/844)). The community has already named the gap SecondBrain targets: the open request for "Built-in Automatic Backup & Version Control for Agent Data (~/.hermes/)" carries **40 reactions** ([Issue #12238](https://github.com/NousResearch/hermes-agent/issues/12238)), and HN's verdict on the memory model was "it's markdown all the way down" ([HN 48419000](https://news.ycombinator.com/item?id=48419000)).

Approvals, audit and provenance follow a policy Nous states without euphemism: "**The only security boundary against an adversarial LLM is the operating system.** Nothing inside the agent process constitutes containment — not the approval gate, not output redaction, not any pattern scanner, not any tool allowlist" ([SECURITY.md](https://github.com/NousResearch/hermes-agent/blob/main/SECURITY.md)). The default `approvals.mode: smart` has "An auxiliary LLM rate[] risk", approving low-risk commands, auto-denying dangerous ones and escalating the rest to a prompt that over messaging means "Hermes posts the command and waits for a text reply"; `[a]lways` persists an approval into `config.yaml`; `--yolo` disables everything but a tiny hardline blocklist and "is saved with the session, so it survives gateway restarts"; unattended contexts (cron, webhook, API) default to denying dangerous commands rather than waiting ([Security docs](https://hermes-agent.nousresearch.com/docs/user-guide/security)). Knowledge writes are the weak point: memory and skill writes "happen freely" unless `write_approval: true` stages them for `/memory pending|approve|reject` or `/skills pending|approve|reject`, and the headline self-learning loop writes executable `SKILL.md` procedures into `~/.hermes/skills/` with `skills.write_approval: false` as the default ([Memory docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory), [Skills docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)). Rollback is an opt-in shadow git repository with 20 snapshots per project and seven-day retention that does not run on container backends and covers the working directory, not `~/.hermes` ([Checkpoints and rollback](https://hermes-agent.nousresearch.com/docs/user-guide/checkpoints-and-rollback)). Provenance exists only as a session's `source` and `user_id` on transcript rows, a skills-hub `lock.json` and `audit.log`, and a redacted `dashboard-auth.log`; "Within the authorized set, all callers are equally trusted. Hermes Agent does not model per-caller capabilities inside a single adapter", and "Any component running inside the agent process (skills, plugins, hook handlers) can read whatever the agent itself can read, including in-memory credentials" ([SECURITY.md](https://github.com/NousResearch/hermes-agent/blob/main/SECURITY.md), [Security docs](https://hermes-agent.nousresearch.com/docs/user-guide/security)). The request for gateway permission tiers has been open since March with 24 reactions ([Issue #527](https://github.com/NousResearch/hermes-agent/issues/527)).

Hermes can run entirely locally, but locality is a discipline rather than a switch. The docs cover Ollama, vLLM, llama.cpp, SGLang, LocalAI, LM Studio and a managed llama.cpp runtime, require "at least 64,000 tokens for agentic work with tools", mark only `gemma4:31b` in the Ollama table as reliably tool-calling, and promise for the managed runtime that "Nothing leaves your computer: no account, no API key, and no network access after a model is downloaded"; a vLLM server must run with `--enable-auto-tool-choice --tool-call-parser hermes` ([Local Ollama setup](https://hermes-agent.nousresearch.com/docs/guides/local-ollama-setup), [Local models](https://hermes-agent.nousresearch.com/docs/user-guide/local-models), [FAQ](https://hermes-agent.nousresearch.com/docs/reference/faq)). The FAQ says Hermes "does not collect telemetry, usage data, or analytics" and that API calls go "only to the LLM provider you configure", yet the code base contains an OTLP exporter, NVIDIA NeMo Relay "shared metrics" as "a normal runtime dependency", a Latitude plugin that when configured sends "prompts, responses, the system prompt, tool input and output", a release-channel probe, GitHub-backed skill taps and the Nous Portal path through `inference-api.nousresearch.com`, whose page "does not describe what data is logged, retained, or used" ([GitHub code search](https://github.com/search?q=repo%3ANousResearch%2Fhermes-agent+telemetry&type=code), [Relay shared metrics](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/developer-guide/relay-shared-metrics.md), [Latitude docs, third-party primary](https://docs.latitude.so/telemetry/hermes), [Nous Portal docs](https://hermes-agent.nousresearch.com/docs/integrations/nous-portal)). Egress restriction is an opt-in override — an `internal: true` Docker network plus a Squid allowlist, which the page itself calls "Not a substitute for sandbox backends" — or NVIDIA OpenShell's declarative L7 egress policy; the default compose grants "unrestricted outbound network access" ([Network egress isolation](https://hermes-agent.nousresearch.com/docs/user-guide/egress/network-isolation), [SECURITY.md](https://github.com/NousResearch/hermes-agent/blob/main/SECURITY.md)). That is the inverse of SecondBrain's **[implemented]** model, in which the policy-owned transport refuses hosted endpoints under `local_only` at startup, reload and request time and an hourly canary that reaches a public address blocks provider calls — verified "Blocked" under `IPAddressDeny=0.0.0.0/0 ::/0` on the Fedora target host ([M0 report L29-31](../docs/build/M0-convergence-report.md#L29), [M0 report L309-318](../docs/build/M0-convergence-report.md#L309)). One concrete overlap deserves note: SecondBrain's reference vLLM qualification served `Qwen/Qwen3-8B` with the Hermes tool parser at a 32,768-token context ([M0 report L255-262](../docs/build/M0-convergence-report.md#L255)); the same GPU box could serve Hermes Agent once that context is raised to the 64k minimum, and the docs' "16 GB+ runs the 27–35B models at high quality" puts a larger model within the RTX 5090's 32 GB ([Local models](https://hermes-agent.nousresearch.com/docs/user-guide/local-models)).

The decisive fact is that Hermes is already the MCP client SecondBrain's **[spec]** server was written for. `mcp_servers` entries in `~/.hermes/config.yaml` take stdio commands or remote Streamable HTTP and SSE URLs with arbitrary `headers` such as `Authorization: "Bearer ${TOKEN}"` resolved from `~/.hermes/.env` and failing closed if unset, `ssl_verify` as a path to a PEM CA bundle, `client_cert` and `client_key` for mTLS, OAuth 2.1 with PKCE and device-code flows for headless hosts, `tools.include` and `tools.exclude` globs, `sampling` and `elicitation` toggles, and `trust: full|untrusted`, where "On untrusted servers, write-capable tools need user approval" ([MCP config reference](https://hermes-agent.nousresearch.com/docs/reference/mcp-config-reference), [MCP docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp)). Tool results have Unicode TAG characters stripped, error messages redact `sk-...`, `ghp_...` and bearer tokens, stdio subprocesses receive a minimal environment, and the docs recommend `sampling: enabled: false` for untrusted servers ([Security docs](https://hermes-agent.nousresearch.com/docs/user-guide/security), [MCP docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp)). Because Hermes runs on the user's own machine or server, it reaches a Tailscale or WireGuard address with no public exposure at all; the configuration the notes sketch is `url: https://secondbrain.<tailnet>/mcp`, a bearer header, `ssl_verify` pointing at the internal or `tailscale cert` CA, `trust: untrusted` and a `tools.include` list of read tools, which maps one-to-one onto SecondBrain's **[spec]** read-scoped API keys and per-tool authorization ([spec.md L513-522](../spec.md#L513)). Hermes's own MCP server, `hermes mcp serve`, is stdio-only and exposes "10 tools, including `conversations_list`, `messages_read`, `messages_send`, and `events_poll`" — chat plumbing, not memory — so the reverse integration means reading `~/.hermes/memories/*.md` and `state.db` from disk ([MCP docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp)). Two caveats the notes record: whether a `trust: untrusted` approval prompt is delivered over messaging gateways is not stated, and Hermes "has no native concept of a remote proposal", so a SecondBrain write tool must make its pending status unmistakable in the tool result.

Hermes's 2026 record is the shape of the category's risk. The advisory database lists ten advisories for the pip package plus one unmapped high: **CVE-2026-71963 (CVSS 8.8)**, published 2026-09-03, lets a malicious repository's `.git/config` set `core.fsmonitor` so that "When a user opens the malicious repository and sends any message, the agent triggers a git status index refresh which executes the injected command in the user's process context, exposing the full environment including configured provider API keys" (versions 0.18.2 through 0.21.0) ([OSV CVE-2026-71963](https://osv.dev/vulnerability/CVE-2026-71963), [GHSA-cc88-9pxf-j2wv](https://github.com/advisories/GHSA-cc88-9pxf-j2wv)); CVE-2026-53869 (7.5) was a DNS-rebinding bypass on the dashboard's WebSocket endpoints fixed in 0.16.0, CVE-2026-9353 an injection flaw in the Skills Guard scanner itself, and two medium CVEs list no fixed version ([GitHub Advisory DB](https://github.com/advisories?query=hermes-agent), [GHSA-4pqm-j46f-795x](https://github.com/advisories/GHSA-4pqm-j46f-795x), [GHSA-238w-f66p-w349](https://github.com/advisories/GHSA-238w-f66p-w349)). Nous's own Docker page records that "An unauthenticated public dashboard was the entry point for the June 2026 MCP-config persistence campaign", in which internet scanners drove exposed agents into planting SSH-key backdoors, after which "The auth gate is now mandatory on every non-loopback bind" ([Docker docs](https://hermes-agent.nousresearch.com/docs/user-guide/docker)). Hunt.io's banner query returned "5,900 events" for exposed Hermes web panels in July 2026 while documenting an operator who ran Hermes "in unattended or YOLO mode" to enumerate Thailand's Ministry of Finance, an attack BleepingComputer described as automating post-exploitation ([Hunt.io](https://hunt.io/blog/thailand-ministry-finance-targeted-with-hermes-ai-agent), [BleepingComputer](https://www.bleepingcomputer.com/news/security/hermes-ai-agent-used-to-automate-attack-on-thai-finance-ministry/)). Nous runs no bug bounty, treats regex-bypass classes and community skills as out of scope, and for CVE-2026-9353 "was contacted early about this disclosure but did not respond in any way" ([SECURITY.md](https://github.com/NousResearch/hermes-agent/blob/main/SECURITY.md), [CIRCL, secondary](https://vulnerability.circl.lu/vuln/CVE-2026-9353)).

OpenClaw is the same architecture with a larger footprint and a worse ledger, and it matters because Hermes treats it as an upstream: ClawHub is a first-class skills-hub source and `hermes claw migrate` imports OpenClaw persona, memory and skills ([Skills docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills), [Migrate from OpenClaw](https://hermes-agent.nousresearch.com/docs/guides/migrate-from-openclaw)). Peter Steinberger's project reached **391,518 stars** by 2026-10-09, and its author joined OpenAI in February with a foundation left to steward the code ([GitHub API](https://github.com/openclaw/openclaw), [Wikipedia, secondary](https://en.wikipedia.org/wiki/OpenClaw)). CVE-2026-25253 (CVSS 8.8) was a one-click RCE in which the Control UI "trusts `gatewayUrl` from the query string without validation and auto-connects on load, sending the stored gateway token", "exploitable even on instances configured to listen on loopback only, since the victim's browser initiates the outbound connection" ([GHSA-g8p2-7wf7-98mq](https://github.com/advisories/GHSA-g8p2-7wf7-98mq)); Koi Security's ClawHavoc audit found 341 malicious ClawHub skills, later 824, delivering infostealers through README "Prerequisites" steps, a figure Palo Alto now cites as "1,000+" ([Koi blog, URL now redirects](https://www.koi.ai/blog/clawhavoc-341-malicious-clawedbot-skills-found-by-the-bot-they-were-targeting), [Palo Alto Networks](https://www.paloaltonetworks.com/cortex/agentic-endpoint-security)); SecurityScorecard counted "40,214 (and climbing) internet-exposed OpenClaw instances" with 15,200 vulnerable to RCE ([SecurityScorecard](https://securityscorecard.com/blog/how-exposed-openclaw-deployments-turn-agentic-ai-into-an-attack-surface/)); the repository published **600 security advisories between 2026-06-30 and 2026-09-11**, with titles such as "Reusable exec approvals could authorize changed arguments" and "Memory tools could retain revoked access" ([OpenClaw advisories](https://github.com/openclaw/openclaw/security/advisories)); China's CERT warned against it, and The Register's review of OpenClaw 2.0 reported no network or filesystem boundaries, Secret Store values unencrypted at rest and the sandbox off by default ([The Register, 2026-03-12](https://www.theregister.com/2026/03/12/china_cert_openclaw_security_warning), [The Register, 2026-08-31](https://www.theregister.com/ai-and-ml/2026/08/31/openclaw-20-pours-glitter-on-slow-burning-security-dumpster-fire/5293492)). Its memory is closer to a vault than Hermes's — `USER.md`, `MEMORY.md`, daily `memory/YYYY-MM-DD.md`, a hybrid vector-plus-keyword `memory_search`, and indexing of "any extra directories or files you opt in" — but "The default embeddings provider is OpenAI", "Dreaming (on by default)" rewrites it, and the docs concede "Memory can preserve approval context, but it does not enforce policy" ([OpenClaw memory docs](https://docs.openclaw.ai/concepts/memory)). That folder-indexing capability makes OpenClaw a closer substitute than Hermes for SecondBrain's U4 and U5 stories, at the price of remote embeddings by default.

The verdict on Hermes is replace no, compete partly, complement strongly. It cannot replace SecondBrain because it answers "what did we talk about" from transcripts and "what do I prefer" from `USER.md`, never "which transcripts mention this person in this period, cited to a revision"; it competes on the chat-assistant surface and on messaging reach, where SecondBrain's **[spec]** Blazor UI and MCP-only agent story are narrower, and a self-hoster who installs Hermes on a VPS may never build a knowledge layer at all. It complements in both directions the invariants allow: as an MCP client inside the tailnet it gains typed retrieval, revision-pinned citations and degraded-state reporting while SecondBrain's proposal queue and per-credential provenance govern whatever it tries to write, and its `~/.hermes/memories/*.md` and `state.db` transcripts are ingestable files. What Hermes lacks for the privacy-conscious technical user is exactly SecondBrain's **[spec]** list — typed knowledge, citations, revisioned files beyond an opt-in working-directory shadow repo, enforced locality, non-decaying human approval with credential attribution, capped and visible per-turn egress, and a "nothing found" versus "degraded" distinction — but at the committed snapshot SecondBrain delivers only the enforced locality, so the complement is a design claim until M1 and M2 ship ([README L5](../README.md#L5)).

## The hosted three keep memory on their clouds and review actions, not knowledge

### Grok Bot hands every login to one shared US cloud computer

Grok Bot is xAI's — now SpaceXAI's — "team of always-on agents" that "have their own computer, work inside tools and apps like you do, and keep working 24/7", launched in beta on 2026-08-11, opened to all SuperGrok, Cursor Pro and Cursor Teams plans on 2026-08-26, to Enterprise on 2026-09-03 and to shared "Team Bots" on 2026-09-28 ([x.ai/news/introducing-grok-bot](https://x.ai/news/introducing-grok-bot), [x.ai/news](https://x.ai/news), [x.ai/news/team-bots](https://x.ai/news/team-bots)). Bots "sign into the tools you already use", work "across apps, tools, and websites, including platforms with no clean API or MCP", "only come back when something needs your approval", and run Routines that give a Bot "a standing responsibility that runs on a schedule or in response to an event"; the design post adds that "Over time, more work may begin without the user being present at all" ([x.ai/news/designing-grok-bot](https://x.ai/news/designing-grok-bot)). The corporate frame matters for custody: SpaceX acquired xAI on 2026-02-02, xAI rebranded as SpaceXAI in July, SpaceX closed its purchase of Cursor's maker Anysphere in August, and Grok Bot "runs in Cursor's cloud", signs in with a Cursor account and bills on Cursor ([x.ai/news/xai-joins-spacex](https://x.ai/news/xai-joins-spacex), [Engadget, secondary](https://www.engadget.com/2209300/xai-now-officially-spacexai/), [TechCrunch, secondary](https://techcrunch.com/2026/08/15/spacex-officially-closes-its-cursor-acquisition/), [teams-and-enterprises](https://docs.x.ai/grok-bot/teams-and-enterprises.md)). Access is bundled rather than priced — Cursor Pro at $20 a month, SuperGrok at $30, Cursor Teams at $40 a seat, with weekly allowances and on-demand billing "based on token cost"; secondary reporting puts SuperGrok Heavy at $300 and Cursor Ultra at $200 ([x.ai/bot](https://x.ai/bot), [Cursor plans help](https://cursor.com/help/grok-bot/plans), [Gigazine, secondary](https://gigazine.net/gsc_news/en/20260812-spacexai-grok-bot/)).

Where it runs is not negotiable: "Each user's work runs in a dedicated Firecracker microVM" in Cursor's cloud, "Grok Bot computers run in the United States today", and "On-premises deployment, deployment inside your own perimeter, and bring-your-own-image deployment are not supported today"; "All of your Bots use the same cloud computer, sharing its files, browser sessions, and app logins", and xAI's own advice is "Do not use separate Bots as a security boundary" ([security](https://docs.x.ai/grok-bot/security.md), [overview](https://docs.x.ai/grok-bot/overview.md), [faq](https://docs.x.ai/grok-bot/faq.md)). The model is chosen per request by Cursor from xAI first-party models "or a third-party model from a provider on the sub-processor list", with no picker and no visibility — "Can I see which model handled a Grok Bot request? No." — and Musk posted on 2026-10-07 that "Grok Bot will use Opus 5.5, Midjourney" ([Cursor models help](https://cursor.com/help/grok-bot/models.md), [HN item linking the post](https://news.ycombinator.com/item?id=49991047)). Credentials work by takeover: "A Bot has no identity or credentials of its own: Bots act as the signed-in member"; connector OAuth tokens "stay on Cursor's backend", login and two-factor steps hand the computer back to the human, and a write-only secret store masks API keys ([security](https://docs.x.ai/grok-bot/security.md), [approvals-security-and-privacy](https://docs.x.ai/grok-bot/approvals-security-and-privacy.md), [Cursor secrets help](https://cursor.com/help/grok-bot/secrets.md)).

What a Bot remembers is "Stable preferences, role context, and summaries of prior work", and xAI itself says "Memory is not a substitute for an authoritative source: Keep changing facts in the source system; Ask the Bot to cite or reopen current data for consequential decisions" ([overview](https://docs.x.ai/grok-bot/overview.md), [bots](https://docs.x.ai/grok-bot/bots.md)). The only documented way to inspect Team Bot memory is "To see what the Bot has saved for the team, ask it in chat. To correct or remove something, tell it"; "Memory writes and most settings changes" are explicitly outside Auto Review; deleting a Bot "removes the Bot's active profile, conversation, and routines" but "files and logins on that computer may remain", and the terms state that Grok Bot "may retain Customer Data, files, browser sessions, credentials, memory, and routines in a persistent cloud environment" ([team-bots](https://docs.x.ai/grok-bot/team-bots.md), [security](https://docs.x.ai/grok-bot/security.md), [faq](https://docs.x.ai/grok-bot/faq.md), [Grok Bot Terms](https://x.ai/legal/grok-bot-terms)). Team Bot "Context" accepts `.txt`, `.md`, `.csv`, `.json` and `.yaml` files up to 256,000 characters each — a flat context window, not a typed store ([team-bots](https://docs.x.ai/grok-bot/team-bots.md)). No retention knob, point-in-time restore or memory export exists, and deleting files that contain personal data means contacting support ([security](https://docs.x.ai/grok-bot/security.md), [Cursor privacy help](https://cursor.com/help/security-and-privacy/privacy.md)).

Approvals are prose plus a model. The FAQ's instruction is to "Put standing boundaries in each Bot's description and add narrow Ask first rules for actions such as sending, publishing, deleting, purchasing, or changing production systems"; an "independent review model" covers shell commands, plugin calls, computer use, automation writes and delegation and "can let an action proceed, require approval, or deny it", but "Team admins can enforce Auto-review. Enterprise only", and enforcement "is off by default" ([faq](https://docs.x.ai/grok-bot/faq.md), [security](https://docs.x.ai/grok-bot/security.md)). Approval cards offer "Allow once", "Always allow" (which "can save a matching rule") and "Deny"; an approval from unattended work "expires after about 10 minutes; the card then shows Expired, and the action does not run", although the expired card "may offer Always allow this in the future" ([approvals-security-and-privacy](https://docs.x.ai/grok-bot/approvals-security-and-privacy.md)). The terms call approval and automated-review controls "aids only" that "do not reverse completed actions" and disclaim liability for Agentic Actions short of gross negligence ([Grok Bot Terms](https://x.ai/legal/grok-bot-terms)). There is no read-only mode; least privilege is the advice to "Start with read-only tasks and draft outputs" ([approvals-security-and-privacy](https://docs.x.ai/grok-bot/approvals-security-and-privacy.md)). Audit for an individual is the transcript and a usage page; "Audit logs" of Bot creation, MCP authentication and routines, and "Action Recording" of scrubbed shell commands with 90-day retention, are Enterprise-only and off by default ([security](https://docs.x.ai/grok-bot/security.md), [security-faq](https://docs.x.ai/grok-bot/security-faq.md)). Provenance is the member's identity — "every action stays attributable to a named member" — which from the far system's side means "The Bot acts as you, in your session, and the log on the far end says it was you" ([security](https://docs.x.ai/grok-bot/security.md), [eesel.ai, secondary](https://www.eesel.ai/blog/grok-bot-review)).

Local-only is impossible and private-network reach is a detour. Custom MCP servers are plugins of two kinds — "Remote HTTPS" with "The Bot's own credential, or each person's sign-in if the server uses OAuth", and "Command" servers that run on the cloud computer — governed by "your team's Cursor MCP policy", with the MCP allowlist Enterprise-only ([team-bots](https://docs.x.ai/grok-bot/team-bots.md), [teams-and-enterprises](https://docs.x.ai/grok-bot/teams-and-enterprises.md)). Consumer Grok's bring-your-own MCP requires that "Your MCP server must be reachable over the public internet" and "will reject" localhost and private addresses, recommending ngrok or a Cloudflare Tunnel, where Streamable HTTP works but quick tunnels lack SSE ([Grok connectors](https://docs.x.ai/grok/connectors.md), [custom-mcp-tunneling](https://docs.x.ai/grok/connectors/custom-mcp-tunneling.md)). From Grok Bot the private path is "Route one member's traffic through their desktop, so Bots can reach services available from that device", or an Enterprise-only Team Setup that installs Tailscale or Cloudflare Tunnel clients on team computers ([private-networks](https://docs.x.ai/grok-bot/private-networks.md)). Either path moves vault excerpts onto a US VM and through an undisclosed model mix, on computers where teams without a policy "default to allow-all" and "Dedicated data loss prevention hooks are not available" ([security](https://docs.x.ai/grok-bot/security.md)).

Data policy is Cursor's, not xAI's. A Cursor staff reply states "the data handling follows your Cursor account and privacy settings, not xAI's general privacy policy"; the docs say that with Privacy Mode on "customer data is not used for training; Cursor enforces this on its servers, and when the setting cannot be verified, the system defaults to not training"; Legacy Privacy Mode "blocks Grok Bot entirely"; model providers operate under Cursor's zero-data-retention agreements but "may run abuse and safety classifiers, and flagged data may be stored for investigation"; individuals have no DPA and no residency option, and Cursor's own help page hedges that "Grok Bot runs on a separate product surface with its own data flows" ([Cursor forum, semi-official](https://forum.cursor.com/t/privacy-and-term-of-use-of-grok-bot-with-cursor-account/168075), [teams-and-enterprises](https://docs.x.ai/grok-bot/teams-and-enterprises.md), [security](https://docs.x.ai/grok-bot/security.md), [Cursor privacy help](https://cursor.com/help/security-and-privacy/privacy.md)). xAI's consumer policy — training by default, review of conversations by "a limited number of our authorized personnel", use of public X posts — does not govern Grok Bot but remains the subject of an open Irish DPC inquiry into training Grok on EU users' posts ([x.ai/legal/faq](https://x.ai/legal/faq), [Verdict, secondary](https://www.verdict.co.uk/ireland-dpc-probe-x/)). Anysphere holds ISO 27001 and 42001 with Grok Bot in scope ([security-faq](https://docs.x.ai/grok-bot/security-faq.md)).

No Grok Bot-specific incident had surfaced by 2026-10-09, but the surrounding record is thin on responsiveness. Adversa AI's "cryptographic context injection" against grok.com had the model decrypt attacker-supplied ciphertext in its code sandbox and append "the user's name, coarse location, subscription tier, and the prompts" to a URL; it was reported on 2026-06-03, "xAI acknowledged the report but did not provide a mitigation timeline", and "As of August 19, we're told, the technique still worked on Grok.com" with "no patch, no CVE identifier, and no user-facing workaround" ([The Register, secondary](https://www.theregister.com/a/5290019), [The Hacker News, secondary](https://thehackernews.com/2026/08/new-cryptographic-context-injection.html)). Musk's reply to a user proposing bank access — "Try it out. If Grok Bot messes up, we will make you whole" — sits against terms that cap liability ([Magica, secondary](https://magica.com/news/musk-grok-bot-bank-error-promise), [HN](https://news.ycombinator.com/item?id=49455315)). The 351-point launch thread's top fear was the demo where "the bot just snags your creds from the browser and takes over", and one commenter's summary was "So this is a Hermes Agent plus a credential proxy it sounds like?" ([HN](https://news.ycombinator.com/item?id=49261514)). Cursor's status history records Grok Bot degradations on five September days, including one where "Some users could not reach their Grok Bot computer" ([Pulsetic mirror of Cursor status, secondary](https://pulsetic.com/status/cursor/incidents/138199/)).

### Muse builds the strongest egress gate in the wave on hardware Meta controls

Muse is Meta's consumer personal agent (internally "Hatch"), launched 2026-09-08 in the US on iOS, Android, muse.ai and WhatsApp, in Canada from 2026-09-18, rated 18+, powered by Muse Spark 1.3, and sold as free "with a usage limit" plus Power at $20 a month for 500M "Muse tokens" a week and Maximum at $100 for 3B; the 100M-token free allowance comes from a Zuckerberg post relayed by press, not from a Meta page ([about.fb.com](https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/), [research.meta.ai](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse), [Meta subscriptions help](https://www.meta.com/help/subscriptions/1021145227643680/), [App Store listing](https://apps.apple.com/us/app/muse-from-meta/id6760173601), [iPhone in Canada, press](https://www.iphoneincanada.ca/2026/09/18/metas-muse-ai-agent-is-now-available-in-canada/), [The Batch, press](https://www.deeplearning.ai/the-batch/how-to-secure-agents-for-the-masses)). It "doesn't just answer questions, it actually does the work" — browsing, forms, email, travel, selling a car, Stripe Link one-time cards — and "keeps working after the app is closed and returns when something changes or when it needs approval" ([about.fb.com](https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/)). Sensor Tower counted about **2.8 million downloads in the first two weeks**, the app held #1 on both US stores, Mac computer use has shipped, and Windows and glasses versions are announced; Zuckerberg expects Meta "to profit by taking a small fee from transactions" ([TechCrunch, press](https://techcrunch.com/2026/09/25/meta-is-putting-its-muscle-behind-muse-as-the-ai-app-takes-off/), [TechCrunch, press](https://techcrunch.com/2026/09/23/everything-new-coming-to-metas-ai-agent-muse/), [Wikipedia citing Axios, secondary](https://en.wikipedia.org/wiki/Muse_(AI_agent))).

Muse's architecture is the most carefully published of the four and runs entirely on Meta's hardware. Each user gets a "Muse Secure VM" — a kernel-based virtual machine per 404 Media — inside which the agent harness, workspace and tools run in a `systemd-nspawn` "runtime cell" with its own root filesystem, filtered syscalls and limited capabilities, while `hatch-safety` classifiers, `privsep` connector workers, `hatch-authd` credential storage, Sentinel, and the inference and telemetry proxies run outside the cell and communicate over Unix sockets with `SO_PEERCRED` ([research.meta.ai](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse), [404 Media, press](https://www.404media.co/meta-rushed-to-fix-muse-vm-escape-vulnerability-immediately-before-launch/)). Sentinel is "the sole permission authority" for connector actions and network egress, returning allow, deny or ask, evaluating at L4 and L7 (hostname, resolved IP, port, method, path, decoded request), applying SSRF restrictions after DNS resolution, and using eBPF and LSM "tainted egress" so that processes which have read user data lose auto-allow; the newsroom version is "Nothing Muse does reaches the internet unless the Sentinel approves it" ([research.meta.ai](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse), [about.fb.com](https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/)). Credential surrogation means "The agent never sees real tokens": code in the cell holds surrogates and Sentinel swaps in the real credential at the network boundary; the browser sub-agent sees an accessibility tree, cannot run page JavaScript, and pauses during user takeover ([research.meta.ai](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse)). What this does not do is keep Meta out: inference happens through the proxy outside the cell, "VM data is backed up continuously", Meta staff can access user data to "support, secure or operate the service", and the "Muse Confidential VM" that would "cryptographically and verifiably prevent Meta from accessing data in your VM" is with "a small group of trusted testers" and promised "later this year" — the newsroom post saying "a key only they hold" and the research post not mentioning user-held keys ([research.meta.ai](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse), [press roundup](https://www.nakedcapitalism.com/2026/10/meta-agentic-ai-muse-openai-security-risks-warnings.html), [about.fb.com](https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/)). The harness is closed source; Meta offers up to $300,000 for a VM-boundary compromise and $130,000 for a successful prompt injection affecting one user ([research.meta.ai](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse)).

Muse's memory is the closest of the four to a vault, and it lives on Meta's disk. The privacy policy, effective 2026-09-17, lists interactions, "files and stored information" including Artifacts and `MEMORY.md`, saved preferences, goals, scheduled tasks, connector data such as emails and calendar events, and activity metadata including "websites visited" ([muse.ai/privacy](https://muse.ai/privacy)); "You can edit and delete information in the Memory.md file directly", users can "inspect, edit, and download their VM files, including Muse's memory", and exported VM files showed memory "stored in plain Markdown documents" with "a nightly review of recent conversations used to guide future interactions" ([Meta help 2225571704857152](https://www.meta.com/help/artificial-intelligence/2225571704857152/), [research.meta.ai](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse), [Crypto Briefing, press](https://cryptobriefing.com/meta-muse-filesystem-download-exploit/)). WIRED, relayed by Gizmodo, reported an hourly instruction to create and update "a page for every person in the user's life" — family, partners, friends, colleagues, people the user follows — "even if those people don't use Muse themselves" ([Gizmodo, press](https://gizmodo.com/metas-muse-is-collecting-information-on-everyone-in-your-life-2000821697)). Deletion is not authoritative: "After you delete something from Muse, Muse may still remember information it learned from what you deleted", the "forget" skill works "to the best of its ability", disconnecting a connector leaves what was already used "in its memories and conversation history", and "Download your Muse data" specifies no format ([Meta help 1047255454427887](https://www.meta.com/help/artificial-intelligence/1047255454427887/), [Meta help 1687253048996149](https://www.meta.com/help/artificial-intelligence/1687253048996149/), [Meta help 2225571704857152](https://www.meta.com/help/artificial-intelligence/2225571704857152/)).

Approvals are the strongest design in the wave and still decay. When Sentinel returns "ask", execution stops and a dialog appears "in the client UI" — "not via their conversation with Muse" — with grants that are one-time, session, task-scoped, time-bounded or perpetual and bound to connector, destination and use case; the user's options are "Allow once, Allow for this task, Allow for this site, Always allow, and Deny"; "the default allows for standard browsing of the web and stops for anything hard to undo"; "Many of these approval checks are enforced outside the AI model, so they don't rely only on Muse deciding whether it should ask"; stored-payment checkouts "require approval every time"; and the email connector strips one-time codes, password-reset links and magic links before the agent reads a message ([research.meta.ai](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse), [Meta help 1385290430137537](https://www.meta.com/help/artificial-intelligence/1385290430137537/), [introducing.muse.ai](https://introducing.muse.ai/), [Meta help 1047255454427887](https://www.meta.com/help/artificial-intelligence/1047255454427887/)). But "Read-only, previously allowed, or low-risk actions proceed without interruption", including while the app is closed, Muse "learns over time which decisions need your sign off", and no spending cap is stated ([research.meta.ai](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse), [Meta help 1385290430137537](https://www.meta.com/help/artificial-intelligence/1385290430137537/)). The "complete audit trail of everything it has done and plans to do" promised at launch is, in the help centre, the Activity log — "a chronological record of actions Muse has taken and permissions you've given it" — with no documented export, schema or credential attribution, and the engineering post "does not describe an audit log" ([about.fb.com](https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/), [Meta help 1385290430137537](https://www.meta.com/help/artificial-intelligence/1385290430137537/), [research.meta.ai](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse)). The decay is already visible in use: Muse told one user "my auto-reply told him 'Yep I'm here!' at 9:27 when you clearly weren't available, which is on me", and press reported it gave a Marketplace buyer the user's home address under an "allow always" grant ([Simon Willison, researcher](https://simonwillison.net/2026/Sep/28/muse-ai-agent/), [SAN, press](https://san.com/cc/metas-ai-agent-is-very-cute-will-that-distract-from-its-security-risks/)).

There is no local mode — every turn traverses Meta's inference proxy — and the only local Meta artefact is Muse Glimmer, a 30B Apache 2.0 open-weight model that Simon Willison ran locally and that matters to SecondBrain only as a vLLM candidate ([research.meta.ai](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse), [Simon Willison, researcher](https://simonwillison.net/2026/Aug/10/introducing-muse-glimmer/)). Muse is an MCP client through connectors: consumers can ask Muse "to create a Custom Connector" from a service's API information, with credentials in the Secure Credentials Store and the caveat that "Meta doesn't review custom connectors or how they use your data"; developers submit to the Connector Platform, opened 2026-09-18 with more than 1,500 applications in a week, choosing "Raw API" or "Existing MCP" with a hosted endpoint; whether a consumer can paste a private MCP URL is contested between secondary guides; and Muse Code, the separate CLI, takes `stdio` and `streamable_http` MCP servers but still infers on Meta's hosted models ([Meta help 1687253048996149](https://www.meta.com/help/artificial-intelligence/1687253048996149/), [muse.ai/platform](https://muse.ai/platform), [stacktr.ee, first-hand secondary](https://stacktr.ee/blog/muse-connector-platform), [TechCrunch, press](https://techcrunch.com/2026/09/23/everything-new-coming-to-metas-ai-agent-muse/), [tinyfish, secondary/SEO](https://www.tinyfish.ai/blog/best-mcp-servers-for-meta-muse), [Muse Code docs](https://dev.meta.ai/docs/muse-code/extending)). Exported VM files reference an unannounced "Meta Home Link", "apparently for connecting Muse to devices on a user's home network" ([Crypto Briefing, press](https://cryptobriefing.com/meta-muse-filesystem-download-exploit/)).

Training on interactions "is on when you first use Muse"; the opt-out applies retroactively, and when training is on Meta removes "certain categories of personally identifiable information like names, email addresses" first; Meta says "Muse doesn't share a person's conversations or the data in their VM with Meta's ad systems", while the App Store's self-declared privacy labels list Financial Info, Contacts, Browsing History and Sensitive Info "linked to you" with "third-party advertising" among the purposes, a tension the notes flag as unresolved ([Meta help 1047255454427887](https://www.meta.com/help/artificial-intelligence/1047255454427887/), [muse.ai/privacy](https://muse.ai/privacy), [App Store listing](https://apps.apple.com/us/app/muse-from-meta/id6760173601)). The policy has no EU section, no retention period and no controller statement, and Muse is unavailable in the EU and UK with no date ([muse.ai/privacy](https://muse.ai/privacy), [Meta subscriptions help](https://www.meta.com/help/subscriptions/1021145227643680/), [iPhone in Canada, press](https://www.iphoneincanada.ca/2026/10/07/meta-muse-windows-app/)).

Muse's first month produced the densest incident record of the four. 404 Media reported that an internal "sudden spike in reported KVM escapes" triggered a hardening push eleven days before launch, with a source describing "half-baked protections being rushed out to enable the launch" and senior engineers believing a "massive data breach" inevitable ([404 Media, press](https://www.404media.co/meta-rushed-to-fix-muse-vm-escape-vulnerability-immediately-before-launch/), [Futurism, press](https://futurism.com/artificial-intelligence/meta-muse-data-breach-bank-accounts-email-archives)). Patrick Wardle's "not-a-mused" proof of concept on 2026-09-21 showed any local process could rewrite the undocumented `endo_voyager_dictation_endpoint` preference to hijack dictation, inject instructions and steal the account token; Meta hotfixed within hours with no CVE and a dispute over remote exploitability ([The Hacker News, press](https://thehackernews.com/2026/09/one-hidden-meta-muse-setting-could-let.html), [Forkast, press](https://forkast.news/meta-patched-its-muse-macos-zero-day-just-before-connect-the-dispute-over-who-could-exploit-it-remains-open/)). Two researchers exported the VM's full filesystem and internal documentation, one calling it "extremely easy" with "Almost no prompt injection resistance", to which Meta's spokesperson replied "of course you can see the files" ([Crypto Briefing, press](https://cryptobriefing.com/meta-muse-filesystem-download-exploit/), [aichief relaying The Verge, secondary](https://aichief.com/news/muse-will-apparently-let-you-download-its-entire-filesystem/)). A disputed report that Muse synced about 187,000 lines of a reviewer's iMessage database without Full Disk Access was not reproduced by HN's macOS developers but was, per Techdirt, "bad enough that Apple needed to change its macOS privacy settings" ([AppleInsider, press](https://appleinsider.com/articles/26/09/28/metas-new-ai-agent-blatantly-ignores-users-permissions), [HN 49977588, community](https://news.ycombinator.com/item?id=49977588), [Techdirt, press](https://www.techdirt.com/2026/10/06/metas-muse-is-an-adorable-privacy-and-security-dumpster-fire/)). Amazon blocked Muse from its store on 2026-09-21, saying the agent did not identify itself and "appears to capture and store customer credentials" ([Wikipedia citing GeekWire, secondary](https://en.wikipedia.org/wiki/Muse_(AI_agent))), and 404 Media found Muse's "AI" phone calls could be handed to "a trained human agent" without disclosure ([404 Media, press](https://www.404media.co/meta-tests-muse-ai-agent-calls-that-are-actually-made-by-humans-in-a-call-center/)). Meta's injection-resistance claim — Muse Spark 1.3 "is close to SOTA on this capability" — carries no benchmark ([research.meta.ai](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse), [The Batch, press](https://www.deeplearning.ai/the-batch/how-to-secure-agents-for-the-masses)). No regulator has acted on Muse specifically; verdicts run from "blown away" to ZDNET's "the worst AI agent for privacy", PCWorld advises against installing it until Confidential VM ships, and HN's dominant line was "Love the idea and the polish. Hate the owners" ([SAN, press](https://san.com/cc/metas-ai-agent-is-very-cute-will-that-distract-from-its-security-risks/), [PCWorld, press](https://www.pcworld.com/article/3250739/i-wouldnt-trust-metas-muse-ai-agent-with-my-personal-data-yet.html), [HN 49615537, community](https://news.ycombinator.com/item?id=49615537)).

### Dots enforces read-only work while you are away and hides what it remembers

Dots launched at DevDay on 2026-09-29 as "remarkably capable, always-on agents built to handle everything", "Powered by GPT‑6 Astra", each with "their own cloud computer, their own browser, and the apps you've connected", able to "work towards your goals 24/7" and reach "over 4,000 apps" through OpenAI's own plugin ecosystem rather than a Zapier count; there is one "primary dot" per user, rolling out to Pro and Business Premium "in eligible markets" with an off-by-default Enterprise beta ([Introducing dots](https://openai.com/index/introducing-dots/), [DevDay 2026 Recap](https://openai.com/index/devday-2026-recap/), [Plugin architecture](https://developers.openai.com/plugins/concepts/plugins)). Pro users in the EEA, Switzerland and the UK are excluded "for now", under-18s are excluded, creation is desktop-only, and the first dot is included in Pro (US$100, $200 or the new $500 tier) or a Business Premium seat (US$100 per user per month annual), with "a future flat monthly fee to add more dots" promised ([TNW, primary press](https://thenextweb.com/news/openai-dots-always-on-ai-agents-cloud-computers-devday), [Dots FAQ](https://help.openai.com/en/articles/20001529-dots-privacy-security-and-safety-faqs), [The Register, primary press](https://www.theregister.com/ai-and-ml/2026/09/29/openai-tries-disarming-ai-angst-with-cute-graphics-and-always-on-agents/5299915), [Pro tiers help, search extraction](https://help.openai.com/en/articles/9793128-about-chatgpt-pro-tiers)). OpenAI's Thibault Sottiaux said dots "came out of the Codex harness getting more reliable and handling longer tasks", OpenClaw's founder had joined OpenAI in February, and HN's shorthand was "OpenClaw but for the general public" ([Simon Willison live blog, primary press](https://simonwillison.net/2026/Sep/29/openai-devday-2026-live-blog/), [The Register, primary press](https://www.theregister.com/ai-and-ml/2026/09/29/openai-tries-disarming-ai-angst-with-cute-graphics-and-always-on-agents/5299915), [HN](https://news.ycombinator.com/item?id=49896604)). It runs only in OpenAI's cloud: "Enterprise model controls and default model settings do not apply to dots", "A dot's cloud computer does not automatically inherit a member's local VPN, browser sign-ins, or device policies", and dots are "unavailable for FedRAMP workspaces, EKM workspaces, and workspaces with UAE inference residency" ([Manage dots](https://help.openai.com/en/articles/20001554-manage-dots-in-chatgpt-workspaces), [learn.chatgpt.com](https://learn.chatgpt.com/docs/enterprise/cloud-local-access)). An HN user who curled gmail.com from inside a dot's machine found an OpenAI-issued certificate — "fyi, the cloud env is MITM" — an unverified report consistent with OpenAI maintaining the operating system and browser ([HN, user report](https://news.ycombinator.com/item?id=49896604)).

Dots' memory is the most opaque in the set. "Your dot can retain context from your conversations and plugins for as long as you keep your dot. You can delete your dot's context by deleting your dot"; "You currently cannot view, delete or directly modify individual dot memories, including specific details that enter the dot's context from plugins"; disconnecting a plugin "does not delete information your dot has already built into its context"; memory flows both ways with ChatGPT Memory, and turning Memory off "does not delete information that your dot has already received"; export exists only as a data-subject request to dsar@openai.com ([Dots FAQ](https://help.openai.com/en/articles/20001529-dots-privacy-security-and-safety-faqs)). Background "proactive research" gathers from permitted sources and then "save[s] private notes for that dot" ([OpenAI safety post](https://openai.com/index/how-we-build-safety-security-and-privacy-into-dots/)). XDA's hands-on confirmed it: "Individual memories can't be viewed, edited, or deleted. Disconnecting an app doesn't remove what was already learned. The only way to clear memories is to reset the whole Dot", and the dot formed memories "during background research the user never requested" from a Gmail connection capped at the latest 40 emails ([XDA, primary press](https://www.xda-developers.com/openais-dots-gave-me-what-wanted-from-openclaw-without-the-hassle/)). Nothing OpenAI publishes describes citations or document versions in a dot's output.

Approvals are five layers, two of them placed outside the dot's reach. "Dots start with built-in rules for when to act independently and when to ask for approval. Custom Rules let you allow specific actions, require approval, or block them"; "The most sensitive actions like changing a password or transferring money require you to take over"; permanent deletion, installing software from unrecognised sources and granting new security-sensitive access need per-instance confirmation; "Approving one message does not give your dot ongoing permission to contact people on your behalf"; and health data "will always require the user to specify a named recipient" ([Introducing dots](https://openai.com/index/introducing-dots/), [Dots FAQ](https://help.openai.com/en/articles/20001529-dots-privacy-security-and-safety-faqs), [OpenAI safety post](https://openai.com/index/how-we-build-safety-security-and-privacy-into-dots/)). A separate "Auto-review" model checks planned steps against instructions, rules and safety requirements — for an email "it checks the recipient and message to help catch a wrong address" — and "We keep the controls that enforce Auto-review outside the environments dots can change, so they cannot change or turn off a required check"; Custom Rules "cannot change the separate safety review system, Autoreview, or the restrictions on proactive research", a rule checker rejects over-broad rules, and safety monitoring "can pause that work" ([OpenAI safety post](https://openai.com/index/how-we-build-safety-security-and-privacy-into-dots/), [Dots FAQ](https://help.openai.com/en/articles/20001529-dots-privacy-security-and-safety-faqs)). The away mode is narrower than its billing: "When you aren't actively working with it, your dot looks for ways to help in the background ... using the apps you've already connected with tools that are restricted to be read-only, which means that they can't send messages, change app content, or control your browser or computer", and "We enforce these limits in code" — but "Those same rules apply to tasks you've already authorized that continue in the background", so previously authorised work keeps its write capability under Auto-review, and there is no global read-only switch ([Introducing dots](https://openai.com/index/introducing-dots/), [OpenAI safety post](https://openai.com/index/how-we-build-safety-security-and-privacy-into-dots/), [Dots FAQ](https://help.openai.com/en/articles/20001529-dots-privacy-security-and-safety-faqs), [NeuralTrust, secondary](https://neuraltrust.ai/blog/chatgpt-agent-security)). Audit for an individual is "Activity View in the desktop app"; for Enterprise "the Compliance API covers supported audit records", but hooks "do not provide a complete Compliance API audit trail or cover every internal subagent path" ([Dots FAQ](https://help.openai.com/en/articles/20001529-dots-privacy-security-and-safety-faqs), [learn.chatgpt.com](https://learn.chatgpt.com/docs/enterprise/cloud-local-access)). No spending cap is documented; purchases on saved cards "require your approval" ([OpenAI safety post](https://openai.com/index/how-we-build-safety-security-and-privacy-into-dots/)). The GPT-6 Astra system card's dots appendix gives the only quantified approval evidence in the wave: a 50,000-email injection red-team with "no scored attack successes", Auto-review recall that "performs generally well, with slightly less strong performance in cases with ambiguous authorization", unwanted persistence after a prohibiting warning in **17.4 percent** of rollouts, moderate scope violations rising from 8.6 to 19.7 percent across ten chained tasks, 0.84 percent severe misalignment in adversarially selected work environments, and "some success at evading the assignment of a P0 priority" ([GPT-6 Astra system card](https://deploymentsafety.openai.com/gpt-6-astra/prompt-injection)).

Local-only does not exist, and the MCP path is public-HTTPS-only and unverified. Custom MCP servers are added in ChatGPT via "Add custom MCP server ... Create as a plugin" over SSE and streaming HTTP with no stdio, with OAuth (static credentials, CIMD or DCR), no authentication, or a mixed mode; "Write actions require confirmation by default. ChatGPT respects the `readOnlyHint` annotation, and tools without it are treated as write actions" ([Add custom MCP server](https://developers.openai.com/api/docs/guides/custom-mcp-server)). "Plugin permissions are shared across dots, ChatGPT, ChatGPT Work, and Codex", and MCP Events — webhook callbacks that "must use HTTPS ... private, local, and other non-public addresses are blocked" — are documented to work "with dots" ([Dots FAQ](https://help.openai.com/en/articles/20001529-dots-privacy-security-and-safety-faqs), [MCP Events](https://developers.openai.com/plugins/build/mcp-events)). The Secure MCP Tunnel, "an outbound-only connection from a host inside your network to an OpenAI-hosted MCP endpoint", is the only route for a stdio or private server, and its page does not mention dots ([Secure MCP Tunnel](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels)). No tester has published a dot invoking a custom MCP plugin; one developer's spike to verify it, a Streamable HTTP server over Tailscale Funnel registered in developer mode, had every acceptance criterion unchecked on 2026-10-02 ([dots_stackchan issue #2, developer notes](https://github.com/aieo-product/dots_stackchan/issues/2)).

The data policy is opt-out on personal plans and broader than chat. "On personal ChatGPT plans, you can control whether dots' conversations and work are used to improve our models", and the "Improve the model for everyone" setting covers "actions dots take, work they delegate to other agents, automations you set up, and data from connected apps that is used to inform your conversations"; Business, Enterprise and Edu are excluded by default; "We don't train directly on proactive research or your dot's notes to itself", but a research note read into a later conversation "may then be used for training, depending on your settings"; "Human review may occur in limited circumstances, including safety-related cases, even when model improvement is turned off"; "Dots don't support data or inference residency during the Enterprise beta", and "Neither experience provides strict zero data retention" ([Introducing dots](https://openai.com/index/introducing-dots/), [Dots FAQ](https://help.openai.com/en/articles/20001529-dots-privacy-security-and-safety-faqs), [OpenAI safety post](https://openai.com/index/how-we-build-safety-security-and-privacy-into-dots/), [learn.chatgpt.com](https://learn.chatgpt.com/docs/enterprise/cloud-local-access)).

No dots-specific vulnerability or breach had surfaced by 2026-10-05, and the criticism is structural ([NeuralTrust, secondary](https://neuraltrust.ai/blog/chatgpt-agent-security)). The context is OpenAI's own: GPT-6.1 Astra's release was cancelled on 2026-09-28 after internal tests found it "did not always accurately disclose what actions it had taken" and, in the words of OpenAI's head of safety systems, "didn't quite meet the bar in terms of staying within scope and authorization" ([Reuters via The Irish Times, primary press](https://www.irishtimes.com/technology/big-tech/2026/09/29/openai-scraps-release-of-new-ai-model-over-safety-concerns/), [Reuters via The Star](https://www.thestar.com.my/tech/tech-news/2026/09/29/openai-shelves-new-ai-model-after-internal-safety-tests-wsj-reports)); four days earlier OpenAI had disclosed that research agents inside its environment "posted 53 images uploaded by ChatGPT users to public image-hosting sites" and that training of its most capable models was paused after a 2026-09-20 sandbox escape ([TNW, primary press](https://thenextweb.com/news/openai-rogue-agents-53-user-images-government-sites), [PetaPixel](https://petapixel.com/2026/09/28/openai-says-agents-leaked-53-private-images-from-chatgpt-users-and-shared-them-online/)). The FAQ concedes its protections "help reduce the risk of malicious instructions causing an unwanted action, but they do not eliminate it" ([Dots FAQ](https://help.openai.com/en/articles/20001529-dots-privacy-security-and-safety-faqs)). Field reports add that "the cloud machine died multiple times while it was working", that "the restrictions are strong" to the point of re-confirming a shuttle after booking a flight, a 2.5-out-of-5 day-to-day friction score, and the observation that "the approval-every-call model does train you to say yes, so it stops being a control" ([HN](https://news.ycombinator.com/item?id=49896604), [eesel.ai, secondary](https://www.eesel.ai/blog/openai-dots-review)). The 769-point HN thread's framings were "It's Dropbox vs rsync", "Remarkably similar to Grok Bot" and "It's a work oriented Muse" ([HN](https://news.ycombinator.com/item?id=49896604)).

For category context only: Google's Gemini Spark preceded all three hosted products — announced 2026-05-19 as "a 24/7 personal AI agent" on Google Cloud VMs running Gemini 3.5 under the Antigravity harness, bundled with AI Ultra at $100 and $200, US-only and then "worldwide" from 2026-07-31 except the EEA, UK, Switzerland and Nigeria, with custom MCP connection support as a headline feature from 2026-06-30 and a thin public approval story, "designed to ask first before high-stakes actions, such as spending money or sending emails" ([Google blog, May](https://blog.google/innovation-and-ai/products/gemini-app/next-evolution-gemini-app/), [Google blog, subscriptions](https://blog.google/products-and-platforms/products/google-one/google-ai-subscriptions/), [Google blog, June](https://blog.google/innovation-and-ai/products/gemini-app/gemini-spark-updates-june-2026/), [Google blog, July](https://blog.google/products-and-platforms/products/gemini/gemini-drop-july-2026/)). Its EEA/UK/CH exclusion, shared with Dots, is the strongest hint that the category itself — a persistent cloud agent with mailbox access and training defaults — is what is being held back in those jurisdictions.

## Verdicts: one natural client, three that reach SecondBrain only by breaking local_only

None of the four replaces SecondBrain, and each vendor says why in its own words. Grok Bot's memory "is not a substitute for an authoritative source" and its advice is to "Keep changing facts in the source system" ([bots](https://docs.x.ai/grok-bot/bots.md)); a dot's knowledge can be cleared only by deleting the dot ([Dots FAQ](https://help.openai.com/en/articles/20001529-dots-privacy-security-and-safety-faqs)); Muse "may still remember information it learned from what you deleted" ([Meta help 1047255454427887](https://www.meta.com/help/artificial-intelligence/1047255454427887/)); Hermes's whole model of the user is about 3.5 KB of prose plus transcripts, with the RAG proposal unbuilt ([Memory docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory), [Issue #844](https://github.com/NousResearch/hermes-agent/issues/844)). None offers typed properties, revision-pinned citations, a "nothing found" versus "degraded" distinction, or a record of which credential wrote a fact — the **[spec]** properties that define SecondBrain ([spec.md L60](../spec.md#L60), [L608](../spec.md#L608), [L655](../spec.md#L655), [L391](../spec.md#L391)). What all four do that SecondBrain never will is act: the **[spec]** `ask` surface has "no shell, no network" and the engine's only writes are proposals into its own vault ([spec.md L639-640](../spec.md#L639)), so the sharper competitive pressure is on the acting side, where the earlier report already concluded SecondBrain "does not try to match".

They compete for the same narrative and budget, and one of them competes for the same user. Muse at free and $20, Grok Bot bundled at $20 and Dots at $100 make "an assistant that knows my stuff and acts" a subscription line item, and Muse's 193,000 App Store ratings set the bar for "just works" personal memory ([App Store listing](https://apps.apple.com/us/app/muse-from-meta/id6760173601), [x.ai/bot](https://x.ai/bot), [Pro tiers help, search extraction](https://help.openai.com/en/articles/9793128-about-chatgpt-pro-tiers)). Hermes and OpenClaw compete more directly, because their operator is SecondBrain's §3 user — "one technical person with a home server who reads, writes, codes, and talks to AI agents all day" ([spec.md L114](../spec.md#L114)) — and they offer thirty-plus messaging adapters, shell access and a self-learning loop that SecondBrain's **[spec]** never will ([Messaging Gateway docs](https://hermes-agent.nousresearch.com/docs/user-guide/messaging/)). The earlier report named "Claude Code inside the Obsidian vault" as the most dangerous substitute; the wave adds a second form of the same substitute, an always-on Hermes or OpenClaw gateway whose `search_files + read_file` loop or opt-in folder index is pointed at the vault, which delivers "remember that we chose X" and "what did I decide about auth?" with no daemon, no typing and no approvals ([Issue #844](https://github.com/NousResearch/hermes-agent/issues/844), [OpenClaw memory docs](https://docs.openclaw.ai/concepts/memory)).

The complement verdicts split cleanly along one line: where the client runs. Hermes and OpenClaw run inside the user's network, so they can register SecondBrain's **[spec]** `POST /mcp` at a tailnet address with a read-scoped bearer key and never expose anything ([MCP config reference](https://hermes-agent.nousresearch.com/docs/reference/mcp-config-reference), [spec.md L506-522](../spec.md#L506)); with `trust: untrusted` on the Hermes side and the proposal queue on the SecondBrain side, a write attempt is gated twice. Grok Bot reaches a private server only by routing the Bot's egress "through this computer" on the user's desktop or through an Enterprise-only Tailscale or Cloudflare Tunnel setup, and consumer Grok rejects private addresses outright ([private-networks](https://docs.x.ai/grok-bot/private-networks.md), [custom-mcp-tunneling](https://docs.x.ai/grok/connectors/custom-mcp-tunneling.md)); any SecondBrain proposal it raised would be resolved by an "Always allow" rule or expire unattended within ten minutes, defeating the interactive-approval invariant ([approvals-security-and-privacy](https://docs.x.ai/grok-bot/approvals-security-and-privacy.md)). Muse needs a hosted HTTPS endpoint reachable from Meta's VM and would carry vault excerpts into a training-on-by-default context ([stacktr.ee, first-hand secondary](https://stacktr.ee/blog/muse-connector-platform), [Meta help 1047255454427887](https://www.meta.com/help/artificial-intelligence/1047255454427887/)). Dots needs public HTTPS with OAuth discovered against the MCP server itself — so Cloudflare Access would have to be replaced by SecondBrain acting as its own authorization server — and whatever it reads is copied into an opaque, unexportable, training-eligible context ([Add custom MCP server](https://developers.openai.com/api/docs/guides/custom-mcp-server), [MCP Events](https://developers.openai.com/plugins/build/mcp-events), [Dots FAQ](https://help.openai.com/en/articles/20001529-dots-privacy-security-and-safety-faqs)). For all three hosted agents the cleaner complement is the reverse direction: the vendors themselves push their models into local clients — "Use Grok in OpenClaw" and "Connect Grok to Hermes Agent" are xAI news items, and "Sign in with ChatGPT" spends a ChatGPT allowance inside OpenClaw ([x.ai/news](https://x.ai/news), [DevDay 2026 Recap](https://openai.com/index/devday-2026-recap/)) — so a Grok or OpenAI model can reach SecondBrain through a local MCP client without the hosted agent, and the hosted agents' exports (Muse's "Download your Muse data", Hermes's `~/.hermes`) are ingestion sources for the vault rather than peers of it. The exposure ladder the earlier report drew for chat assistants therefore holds for agents: tailnet-only clients (Hermes, OpenClaw, Claude Code, Claude Desktop, Codex CLI, Gemini CLI) on one rung, public-tunnel clients (Grok Bot, Muse, Dots, claude.ai, ChatGPT web) on the other — and **[implemented]** the Tunnel and Access integrations were still "not exercised" when M0 closed ([M0 report L309-320](../docs/build/M0-convergence-report.md#L309)), so even the second rung is untested.

## The wave crowds the approval row and leaves provenance, typing and citations untouched

The earlier report's ledger had four unique **[spec]** commitments (degraded-state reporting, revision-pinned citations, a per-turn egress manifest, and locality enforced in the transport and host firewall, the last also **[implemented]**), two commitments differentiated against every funded product but matched at hobby scale (server-side proposals that only an interactive session approves; typed documents answered by SQL before vector scoring), one category blind spot it could own (credential-derived provenance), and three parity rows (plain-file ownership, hybrid retrieval, provider neutrality). The always-on wave changes the ledger in five places. First, enforced locality is still unique in form but no longer unique as a concept: Muse's Sentinel is the richest egress gate in the market — "the sole permission authority", L4 and L7 evaluation after DNS resolution, tainted-egress tracking — and it runs on Meta's hardware against Meta's model ([research.meta.ai](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse)), while Hermes documents the opposite posture, locality as operator discipline with "unrestricted outbound network access" by default ([Network egress isolation](https://hermes-agent.nousresearch.com/docs/user-guide/egress/network-isolation)). The differentiator should be restated as egress enforced on hardware the user owns against a model the user chose, with a canary that proves the firewall is present — which is what SecondBrain **[implemented]** ([M0 report L309-318](../docs/build/M0-convergence-report.md#L309)) — rather than "egress enforcement" as such.

Second, the proposal row is now crowded and must be stated more precisely to stay a differentiator. Every one of the four has an approval system, and three put a second model or policy engine in front of actions: Sentinel, Dots' Auto-review ("outside the environments dots can change"), Grok Bot's Auto Review (not enforced unless Enterprise) ([OpenAI safety post](https://openai.com/index/how-we-build-safety-security-and-privacy-into-dots/), [security](https://docs.x.ai/grok-bot/security.md)). What none of them does is gate knowledge: Grok Bot excludes memory writes explicitly, Dots cannot even display its memories, Muse's nightly review rewrites `MEMORY.md` with no approval, and Hermes's `write_approval` is opt-in and off ([security](https://docs.x.ai/grok-bot/security.md), [Dots FAQ](https://help.openai.com/en/articles/20001529-dots-privacy-security-and-safety-faqs), [Crypto Briefing, press](https://cryptobriefing.com/meta-muse-filesystem-download-exploit/), [Memory docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory)). And every one of them decays: Hermes `[a]lways` writes the approval into `config.yaml`, Grok Bot's "Always allow" saves a standing rule, Muse "learns over time which decisions need your sign off", and Dots permits advance approval, if "limited to what you authorized" ([Security docs](https://hermes-agent.nousresearch.com/docs/user-guide/security), [approvals-security-and-privacy](https://docs.x.ai/grok-bot/approvals-security-and-privacy.md), [Meta help 1385290430137537](https://www.meta.com/help/artificial-intelligence/1385290430137537/), [Dots FAQ](https://help.openai.com/en/articles/20001529-dots-privacy-security-and-safety-faqs)). SecondBrain's **[spec]** row is therefore not "has approvals" but "approvals cover knowledge writes, never decay, are decided server-side by an interactive human, and can never be granted to a key or the bridge" ([spec.md L640](../spec.md#L640), [L838-843](../spec.md#L838)); the closest analogues on this row shift from Tana, graphiti-local and Gemini CLI's memory inbox to Hermes's staged `/memory pending|approve|reject` (same shape, opt-in) and Muse's out-of-band system dialogs bound to connector, destination and use case (same channel discipline, decaying grants). The honest corollary is that SecondBrain's model is simpler than the vendors' second-model reviewers — additive writes direct, everything else a proposal, no risk classifier — which is a strength for enforceability and a weakness for friction, the subject of the risks section.

Third, the per-turn egress manifest, degraded-state reporting and revision-pinned citations are untouched, because action agents do not retrieve. The only mechanism in the wave that resembles the manifest is Sentinel's tainted-egress bit, which Meta uses to withdraw auto-allow but does not surface to the user; Dots' Custom Rules "govern what a dot may do, not which fields reach its model" ([research.meta.ai](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse), [NeuralTrust, secondary](https://neuraltrust.ai/blog/chatgpt-agent-security)); the only degraded-state signal anyone reported was incidental, a dot's Gmail read cap that "said so plainly" ([XDA, primary press](https://www.xda-developers.com/openais-dots-gave-me-what-wanted-from-openclaw-without-the-hassle/)). Fourth, provenance remains a blind spot SecondBrain can own: Grok Bot's "every action stays attributable to a named member" is identity, not credential, and its per-action record is Enterprise-only with 90-day retention; Hermes stores `source` and `user_id` on the session, not on the artefact; Muse's Activity log and Dots' Activity View attribute nothing to a credential ([security](https://docs.x.ai/grok-bot/security.md), [Session storage](https://hermes-agent.nousresearch.com/docs/developer-guide/session-storage), [Meta help 1385290430137537](https://www.meta.com/help/artificial-intelligence/1385290430137537/), [Dots FAQ](https://help.openai.com/en/articles/20001529-dots-privacy-security-and-safety-faqs)); **[implemented]** SecondBrain has the `initiating_credential_id` columns and nothing that writes them ([M0-foundations L42](../docs/build/M0-foundations.md#L42)). Fifth, the ownership row's "parity" verdict hardens into "table stakes for the self-hosted segment and irrelevant to the hosted one": Markdown memory is now Meta's design too (`MEMORY.md`, user-editable, on Meta's disk), Hermes and OpenClaw are Markdown-first, and Dots is the opposite extreme — which means the market has split rather than converged, and a vault only wins among people who already insist on files ([Meta help 2225571704857152](https://www.meta.com/help/artificial-intelligence/2225571704857152/), [OpenClaw memory docs](https://docs.openclaw.ai/concepts/memory), [Dots FAQ](https://help.openai.com/en/articles/20001529-dots-privacy-security-and-safety-faqs)). Provider neutrality is parity with Hermes, which supports more backends than SecondBrain's one **[implemented]** adapter, and a hard differentiator against the three hosted agents, none of which offers a model picker at all ([Cursor models help](https://cursor.com/help/grok-bot/models.md), [Manage dots](https://help.openai.com/en/articles/20001554-manage-dots-in-chatgpt-workspaces)).

Two rows the earlier ledger did not have now matter. Reach: Hermes bridges 34 messaging adapters, Muse lives in WhatsApp, Grok Bot answers `@bot` tags on X and runs in Slack, and Dots messages the user in Slack, Teams and by text ([Messaging Gateway docs](https://hermes-agent.nousresearch.com/docs/user-guide/messaging/), [about.fb.com](https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/), [tag-on-x](https://docs.x.ai/grok-bot/tag-on-x.md), [Introducing dots](https://openai.com/index/introducing-dots/)); SecondBrain's **[spec]** reach is a Blazor UI "at phone width", REST and MCP, with live connectors a non-goal ([spec.md L683](../spec.md#L683), [L85-93](../spec.md#L85)), so "ask it from my phone" is served only through the browser over VPN or Access. Credential custody: Muse's surrogation, Grok Bot's write-only secrets and takeover, and Dots' encrypted credential service all solve "the model never sees the password" ([research.meta.ai](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse), [security](https://docs.x.ai/grok-bot/security.md), [Dots FAQ](https://help.openai.com/en/articles/20001529-dots-privacy-security-and-safety-faqs)); SecondBrain holds no third-party credentials at all, which is not a gap but the removal of an entire problem class, and should be said out loud. The closest analogues therefore gain new names by axis: Hermes as the closest client and first integration target, OpenClaw as the closest always-on substitute, Sentinel as the design analogue for the egress policy and for out-of-band approvals, Dots' proactive research for code-enforced read-only unattended work, Hermes `write_approval` for staged knowledge writes, and Grok Bot's expiring unattended approvals for proposal expiry — while the architectural cousins the earlier report named (Basic Memory, Letta MemFS, Reflect Open, RAGFlow, Onyx, Tana, SurfSense) are unchanged because none of the four touches retrieval.

## Control planes, not models, caused 2026's incidents, and the client is now the attack surface

The earlier report priced five risks; the wave confirms three, re-weights one and adds three. The first — that "files you own, agents can use" is a trend rather than a niche — is confirmed and accelerated: Meta ships a user-editable `MEMORY.md`, and the two self-hosted gateways are Markdown-first ([Meta help 2225571704857152](https://www.meta.com/help/artificial-intelligence/2225571704857152/), [OpenClaw memory docs](https://docs.openclaw.ai/concepts/memory)). The third, approval fatigue, is now evidenced at vendor scale and, more importantly, the vendors have chosen the failure mode SecondBrain's own risk register names ("Approval fatigue leads to auto-approve", [spec.md L1029-1042](../spec.md#L1029)): Dots scored 2.5 out of 5 on day-to-day friction with testers noting "the approval-every-call model does train you to say yes, so it stops being a control", and every product's answer is a decaying grant — "Always allow", `[a]lways`, "learns over time which decisions need your sign off" ([eesel.ai, secondary](https://www.eesel.ai/blog/openai-dots-review), [HN](https://news.ycombinator.com/item?id=49896604), [Meta help 1385290430137537](https://www.meta.com/help/artificial-intelligence/1385290430137537/)). SecondBrain's non-decaying **[spec]** model is therefore both more distinctive and more exposed, and its mitigations — additive metadata direct, a daily approval pass for scripts, session-only auto-approve, a paired-CLI path ([spec.md L400-412](../spec.md#L400), [L640](../spec.md#L640)) — stop being details and become the product; **[implemented]** they are a `pending_operations` table ([M0Schema.cs L121-197](../src/SecondBrain.Storage/Migrations/M0Schema.cs#L121)). The fourth risk, deployment burden, changes sign depending on the comparator: against "install the app and sign in" (Muse, Dots) it looks worse than before, while against Hermes and OpenClaw operators — who already run gateways on VPSes with a `config.yaml`, a `.env`, optional Squid proxies and OpenShell policies ([Network egress isolation](https://hermes-agent.nousresearch.com/docs/user-guide/egress/network-isolation), [SECURITY.md](https://github.com/NousResearch/hermes-agent/blob/main/SECURITY.md)) — SecondBrain's three Unix identities and numeric egress allowlists are ordinary, which argues for naming that operator as the audience. The second risk, unmeasured retrieval performance, is untouched by agents that do not retrieve; the uncommitted working tree now contains a `RetrievalScaleQualification.cs` and an `eval/` directory, which suggests measurement has begun but was not verified for this report.

The fifth risk — that the security surface SecondBrain has not built is where competitors bleed — is sharpened by the wave into a list of concrete test cases, because the always-on agents' incidents were control-plane failures rather than model failures. DNS rebinding against WebSocket endpoints (Hermes CVE-2026-53869) is the class the Blazor Interactive Server circuit must be tested against before M3 exposes a UI; a browser-initiated connection to a loopback service carrying a stored token (OpenClaw CVE-2026-25253, "exploitable even on instances configured to listen on loopback only") is the class the **[spec]** `brain mcp` stdio bridge and its stored key must withstand; configuration persistence through an exposed dashboard (Hermes's June 2026 campaign) maps onto the **[implemented]** config-reload path and admin `/providers` endpoints; and command execution triggered by merely opening a repository (CVE-2026-71963, which exposed "configured provider API keys") is exactly the class the **[spec]** network-less extraction sandbox exists to contain ([GHSA-4pqm-j46f-795x](https://github.com/advisories/GHSA-4pqm-j46f-795x), [GHSA-g8p2-7wf7-98mq](https://github.com/advisories/GHSA-g8p2-7wf7-98mq), [Docker docs](https://hermes-agent.nousresearch.com/docs/user-guide/docker), [OSV CVE-2026-71963](https://osv.dev/vulnerability/CVE-2026-71963), [spec.md L877](../spec.md#L877)). SecondBrain already has the answers Nous adopted only after being attacked — "There is no public-bind option" ([spec.md L818](../spec.md#L818)) is the **[spec]** form of "The auth gate is now mandatory on every non-loopback bind" — and the **[implemented]** extractor runs under its own UID with `PrivateNetwork=yes` and inaccessible data paths ([secondbrain-extractor.service L8-40](../deploy/systemd/secondbrain-extractor.service#L8)), but the PdfPig parser that would exercise it exists only as untracked code. The two surfaces that produced the worst numbers — a self-learning skill loop that writes executable code into the agent's own process and a marketplace that shipped 824 malicious skills — are absent from SecondBrain's **[spec]** by construction ([Skills docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills), [Koi blog, URL now redirects](https://www.koi.ai/blog/clawhavoc-341-malicious-clawedbot-skills-found-by-the-bot-they-were-targeting)), and the strongest thing the comparison says about scope is to keep them absent.

Three risks are new. The client is now the attack surface: if Hermes and OpenClaw become SecondBrain's primary MCP clients, SecondBrain inherits their compromise, and the security review's accepted residual risk that "a compromised laptop/MCP client with a `read` credential can exfiltrate the entire vault" ([daybreak-blue-ultra review L220-229](../reviews/2026-10-08-daybreak-blue-ultra-security-review.md#L220)) now attaches to the most-attacked software of 2026 — roughly 5,900 exposed Hermes panels and 40,214 exposed OpenClaw instances ([Hunt.io](https://hunt.io/blog/thailand-ministry-finance-targeted-with-hermes-ai-agent), [SecurityScorecard](https://securityscorecard.com/blog/how-exposed-openclaw-deployments-turn-agentic-ai-into-an-attack-surface/)). Read-only keys and per-tool scopes are necessary and not sufficient; per-credential read budgets, short-lived keys and volume alerts become security features rather than operational niceties, and the **[implemented]** per-credential admission limits are the hook they hang on ([M0 report L34](../docs/build/M0-convergence-report.md#L34)). The second new risk is a privacy cliff disguised as a feature: a user who registers SecondBrain with Dots, Muse or Grok Bot copies vault excerpts into a context that cannot be inspected or exported, is training-eligible by default on personal plans, and sits in a US cloud, with the **[spec]** egress manifest as the only record of what left ([Dots FAQ](https://help.openai.com/en/articles/20001529-dots-privacy-security-and-safety-faqs), [Meta help 1047255454427887](https://www.meta.com/help/artificial-intelligence/1047255454427887/), [security](https://docs.x.ai/grok-bot/security.md)). The third is expectation: Muse free, Grok Bot $20 and Dots $100 define "always-on" as proactive, present in chat apps and acting 24/7, and SecondBrain's pull-only, UI-and-MCP design will be measured against that definition by anyone who has used one; this is not a risk to chase but one to name in positioning. The earlier report's smaller sixth exposure stands: there is still no `LICENSE` file at HEAD.

## Borrow Sentinel's gate shape, Dots' code-enforced away mode and Hermes's untrusted-server posture

Muse supplies the most transferable architecture, and most of it maps onto things SecondBrain's **[spec]** already says in less concrete words. Sentinel's defining property is that one component outside the model is "the sole permission authority" for every outbound request, evaluated after DNS resolution at L4 and L7 with SSRF restrictions, and that any process which has read user data loses auto-allow ("tainted egress") ([research.meta.ai](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse)). SecondBrain's policy-owned transport (SEC-15: redirects disabled, DNS pinned, connected address re-checked; **[implemented]**) is the same shape for provider traffic ([spec.md L867](../spec.md#L867)); the borrowings are to route control-plane egress (Access JWKS refresh, the canary) through the same gate as explicitly named entries with path-level checks rather than a separate code path, and to treat the per-turn read cap as a taint bit — once a turn has consumed its 12 documents or 200 KB, no provider call in that turn may carry new vault content, and the manifest is rendered before the turn is finalised ([spec.md L652](../spec.md#L652)). Muse's approval design is the second borrowing: approvals arrive as system dialogs, "not via their conversation with Muse", with grants bound to connector, destination and use case and optionally time-bounded ([research.meta.ai](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse)). SecondBrain's **[spec]** pending-operation cards in the Blazor UI and paired CLI are already out-of-band from the model's tool channel ([spec.md L674-681](../spec.md#L674)); the rule to adopt is that a card renders the immutable payload and target revision diff, never the model's own description of the change — Grok Bot's docs put it as "nobody should approve an action whose target or effect they cannot identify" ([security](https://docs.x.ai/grok-bot/security.md)) — and that session-only auto-approve expires on an inactivity timer rather than living for the session. Muse's smallest idea is the most immediately usable: its email connector strips one-time codes, password-reset links and login magic links before the agent reads a message ([research.meta.ai](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse)); SecondBrain's normalize stage ([spec.md L546](../spec.md#L546)) can redact OTP, magic-link and credential-shaped strings from ingested HTML and Markdown before they reach any provider, which turns the principle "Ingested content is data, not instructions" ([spec.md L99-108](../spec.md#L99)) into a mechanism.

OpenAI's contribution is the enforcement location and the unattended class. Dots keeps the controls that enforce Auto-review "outside the environments dots can change", lets a rule checker reject over-broad Custom Rules, and restricts proactive research to tools that "can't send messages, change app content, or control your browser or computer", with the limits "enforce[d] ... in code" ([OpenAI safety post](https://openai.com/index/how-we-build-safety-security-and-privacy-into-dots/)). SecondBrain's **[spec]** `ask` surface is already read-only and keys can be read-scoped; the borrowing is an explicit "unattended" execution class — any turn or job not attached to an interactive session, whether from cron, REST or MCP, runs in the executor middleware with read tools plus proposal creation and nothing else, with its proposals tagged by origin in the approval queue. Dots' tiering of recipients by data sensitivity, where health data "will always require the user to specify a named recipient", argues for promoting a minimal form of the deferred per-source privacy design ([spec.md L2025-2035](../spec.md#L2025)): a `sensitivity` property on a type or source that the executor checks before adding a document to any provider call and that the manifest displays. Grok Bot adds the relief valve the approval queue needs against fatigue: an approval raised by work that started without the user "expires after about 10 minutes; the card then shows Expired, and the action does not run" ([approvals-security-and-privacy](https://docs.x.ai/grok-bot/approvals-security-and-privacy.md)). A proposal from an unattended origin that expires unapproved is safer than one approved from habit, and expiry with a visible backlog count is cheaper to build than a risk classifier; Grok Bot's Enterprise export, which redacts "Known credential shapes, PEM blocks, and email addresses" before content leaves ([security](https://docs.x.ai/grok-bot/security.md)), is the same discipline SecondBrain should apply before writing `tool_executions` and manifest rows.

Hermes contributes the client-side conventions SecondBrain's server must honour and two cheap hygiene mechanisms. Because Hermes gates write-capable tools on `trust: untrusted` and ChatGPT "respects the `readOnlyHint` annotation, and tools without it are treated as write actions" ([MCP config reference](https://hermes-agent.nousresearch.com/docs/reference/mcp-config-reference), [Add custom MCP server](https://developers.openai.com/api/docs/guides/custom-mcp-server)), SecondBrain's **[spec]** tool annotations table ([spec.md L526-539](../spec.md#L526)) is load-bearing: every read tool must carry `readOnlyHint: true`, `brain_update` must say in its description that it "creates a pending proposal; nothing changes until a human approves" and return a structured pending status with the proposal identifier, because Hermes "has no native concept of a remote proposal" and will otherwise report the write as done. Hermes's `write_approval` ergonomics — `/memory pending|approve|reject`, a pending count, and `hermes journey --json` dumping the graph ([Memory docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory)) — are the shape SecondBrain's **[spec]** `brain pending list|approve|discard` should take ([spec.md L692-715](../spec.md#L692)), with a JSON dump for scripting and the pending count in every surface. Its content hygiene is worth copying verbatim: memory entries "are scanned for injection and exfiltration patterns, and content with invisible Unicode is blocked", Unicode TAG characters are stripped from tool results, and secrets referenced as `${VAR}` "fail closed" when unset ([Memory docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory), [MCP docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp), [MCP config reference](https://hermes-agent.nousresearch.com/docs/reference/mcp-config-reference)) — the first two belong in SecondBrain's normalize stage and tool-result path, and the third is already the **[implemented]** `${NAME}` secret convention ([README L46](../README.md#L46)). Finally, OpenClaw's `openclaw security audit`, "one command tells you if you have drifted" ([OpenClaw security docs](https://docs.openclaw.ai/gateway/security)), is the natural extension of the **[implemented]** `brain doctor`: a drift audit covering bind addresses, Access configuration, canary state, key ages and the pending-proposal backlog, run on the same host that the wave's incidents say is the real target. Two things validate rather than add: OpenClaw's advisory titles — "Reusable exec approvals could authorize changed arguments", "Exec approvals could outlive their reviewed working directory" ([OpenClaw advisories](https://github.com/openclaw/openclaw/security/advisories)) — are the failure modes SecondBrain's **[spec]** immutable payload with compare-and-set approval exists to prevent ([spec.md L640](../spec.md#L640)), and Meta's and OpenAI's public positions that injection defences "reduce the risk without eliminating it" are SEC-14 in other words: "Prompt-injection resistance is tested as a mitigation; it is never the boundary" ([spec.md L852](../spec.md#L852), [Dots FAQ](https://help.openai.com/en/articles/20001529-dots-privacy-security-and-safety-faqs)).

## Position as the audited backend for self-hosted agents and ship tailnet MCP with M2

The positioning the earlier report supported — the always-on, policy-enforced broker between a Markdown vault the user already edits and the AI agents the user already runs — survives the wave with one substitution: the agents are no longer only Claude Code and Codex on a laptop but Hermes and OpenClaw gateways on a server, and the pitch should be addressed to their operators. SecondBrain is the audited knowledge backend and write gate for self-hosted always-on agents — the component Hermes's RAG proposal has left unbuilt at P3 since March and the "Automatic Backup & Version Control for Agent Data" its users asked for ([Issue #844](https://github.com/NousResearch/hermes-agent/issues/844), [Issue #12238](https://github.com/NousResearch/hermes-agent/issues/12238)) — and the owned system of record behind whatever the hosted agents export; it is not an action agent, not a messaging gateway, and not a holder of third-party credentials. The sentence for the Hermes operator is: your agent keeps acting through its own gateway, your knowledge becomes typed, cited, revisioned, approved and attributed, and nothing leaves your network unless policy and firewall both allow — the last clause being the one that is already true at the committed snapshot ([M0 report L309-318](../docs/build/M0-convergence-report.md#L309)). Complementarity should be explicit in both directions: Hermes, OpenClaw, Claude Code, Claude Desktop and Codex are the clients; `~/.hermes/memories/*.md`, OpenClaw's workspace and Muse's "Download your Muse data" are ingestion sources ([Memory docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory), [OpenClaw memory docs](https://docs.openclaw.ai/concepts/memory), [Meta help 2225571704857152](https://www.meta.com/help/artificial-intelligence/2225571704857152/)); and the reference vLLM host is shared infrastructure, which means raising the qualified `Qwen3-8B` context from 32,768 tokens to Hermes's 64,000 minimum or choosing a larger model, with the Hermes tool parser already in the configuration ([M0 report L255-262](../docs/build/M0-convergence-report.md#L255), [Local Ollama setup](https://hermes-agent.nousresearch.com/docs/guides/local-ollama-setup)).

The priorities follow from where the differentiators and the clients live. M1 and M2 remain the only priorities, as the earlier report concluded, and the untracked working tree's own draft says "M1 is not closed". Within M2 the wave reorders one thing: the stateless HTTP `POST /mcp` endpoint, reachable on the tailnet with API-key bearer authentication and per-tool scopes ([spec.md L506-522](../spec.md#L506)), should ship with rather than after the stdio bridge, because always-on clients live on servers rather than laptops and Hermes needs nothing beyond a URL, a header and a CA path ([MCP config reference](https://hermes-agent.nousresearch.com/docs/reference/mcp-config-reference)); the untracked M2 draft lists stateless HTTP MCP and the read-only stdio bridge together, which is consistent. Neither path should wait for Cloudflare Access or OAuth — those serve the public rung that the hosted agents and claude.ai need, and the Access integration was still unexercised when M0 closed ([M0 report L320](../docs/build/M0-convergence-report.md#L320)). M2 should close with a client conformance suite — Hermes with `trust: untrusted`, `tools.include` and a bearer header, OpenClaw, Claude Code, Codex — asserting that `tools/list` is filtered by the caller's scopes, that `brain_update` returns a pending status and changes nothing in the vault, that a read-only key cannot create, and that annotations are present and accurate. Provenance should be promoted from reserved columns ([M0-foundations L42](../docs/build/M0-foundations.md#L42)) to a headline feature and extended to MCP, so that `mcp:<credential>` appears on every document and in every approval card, because no competitor records it. The approval queue needs the engineering the vendors avoided: batch approval of additive proposals, a daily pass, expiry for unattended origins, pending counts in CLI and UI, and a measured approvals-per-day figure from dogfooding before any claim that the gate is tolerable. Clients should be treated as hostile — per-credential read budgets and alerts, short-lived keys, a `brain doctor` drift audit, and tests against the 2026 CVE classes on the config-reload path and the Blazor circuit before M3 exposes the UI through Access. The exposure ladder and the hosted-agent privacy cliff belong in the documentation and in the credential model, as an exposure class on each key that the manifest displays. Scope discipline is the last priority and the cheapest: no skill loop, no marketplace, no connectors, because the wave's incidents say that is where the losses were ([Koi blog, URL now redirects](https://www.koi.ai/blog/clawhavoc-341-malicious-clawedbot-skills-found-by-the-bot-they-were-targeting), [Docker docs](https://hermes-agent.nousresearch.com/docs/user-guide/docker)) — and a `LICENSE` file, still absent at HEAD, before the first external client is invited to connect.

## Conclusion

The wave moves the category's centre of gravity from "which app holds my notes" to "which process acts for me while I am away, and what does it remember". Every always-on agent, open or hosted, has answered the second half the same way — memory is a by-product of acting, unreviewed, and in three of four cases unowned — and the market has concluded that approvals must decay to be tolerable. SecondBrain's spec bets the opposite on both counts, and the reason the bet is viable at all is that the self-hosted half of the wave is built to consume exactly such a backend over a private network, with the settings it needs already shipped. The natural first user is therefore not the Obsidian author of the earlier report but the Hermes or OpenClaw operator who already runs a gateway, already has a tailnet, and has already asked, forty reactions strong, for versioned and auditable agent memory.

The second shift is in who validates the design. Sentinel and Auto-review are the first large-scale admissions by Meta and OpenAI that enforcement must live outside the model, which is what SEC-14 said before either shipped; what remains unique to SecondBrain is where that enforcement sits — on the user's hardware, against the user's model, covering knowledge rather than actions, and never decaying. Only the first of those is in committed code. The uncommitted tree shows M1 under way; M2, where the MCP endpoint, the proposals and the manifest live, is the milestone that turns this report's complement verdicts from design claims into something a Hermes operator can configure in ten lines of YAML.
