# SecondBrain Promises Enforcement No Competitor Ships

Across roughly sixty products in five clusters, no competitor combines the guarantees SecondBrain's spec v0.6 makes — a plain-Markdown vault with a disposable index, typed documents answered by SQL before any vector scoring, retrieval that reports its own degradation, citations pinned to a document revision, assistant writes that land as proposals only an interactive human session can approve, per-tool MCP scopes with a read-only bridge, a `local_only` switch enforced by a policy-owned transport plus a host-firewall canary, and network-less sandboxed parsing — and the competitors' own 2026 incident records (Mem0's 97.8%-junk memory audit, Graphiti's 41% wrongful fact invalidation, zero-click connector exfiltration in ChatGPT, Copilot and Gemini, Limitless's regional account deletions after Meta bought it) are the strongest evidence that those guarantees address real failures. But as of the 2026-10-09 snapshot (commits `0a06b18`/`b2016a2`), SecondBrain has implemented none of its knowledge features: the repository is a hardened authentication, privacy and durability shell with **750 passing tests, 53 lines of UI, and no ingestion, search, chat, MCP, backup or purge code**, so today it trails every competitor on every user-visible capability and is at best at parity on what it has shipped (provider neutrality, hardened deployment, enforced `local_only`). Its closest analogues are Basic Memory (Markdown + SQLite + MCP), Letta's MemFS and Reflect Open on ownership; Tana, graphiti-local and Gemini CLI's memory inbox on human-approved writes; SurfSense 2.x and Windows Recall on egress posture; Onyx, RAGFlow and Heptabase on read-only agent access; and the "Claude Code inside the Obsidian vault" pattern (Copilot v4, Local REST API's built-in MCP) as the most dangerous substitute because it delivers agentic vault editing today without a daemon. The comparison exposes five risks — the window for a "files-you-own" differentiator is narrowing as that becomes a trend rather than a niche, the exact-vector performance targets and the approval model are entirely unproven, the deployment burden is far above any peer, the security surface will grow sharply when parsers, MCP and the Blazor UI land, and private-network-only placement cuts off every vendor-cloud client — and it implies a positioning as the narrow, verifiable, policy-enforced broker between an Obsidian-style vault and AI agents, with M1 (ingest and search) and M2 (ask and MCP) as the only priorities that matter until the design becomes a product.

Two conventions hold throughout. Every SecondBrain claim is tagged **[spec]** (design intent in `spec.md` Draft v0.6, dated 2026-10-08) or **[implemented]** (verified in code, deployment artifacts, README or the M0 convergence report at the snapshot), and repository citations are links into the repo with line numbers at commit `0a06b18`; competitor claims carry the source URL recorded in the research notes, with third-party or pre-2025 sources flagged. The repository has moved since the notes were taken — commit `34f2d15` ("Close M0 for the Fedora and Tailscale reference deployment") and the merge of PR #1 landed afterwards, 95 files held uncommitted changes when this report was written, and no `LICENSE` file exists at the repo root — so the "implemented" column is pinned to the snapshot and may understate current state, though nothing in the later commit messages suggests any knowledge feature shipped.

## Spec promises eight rare guarantees; the repo ships hardened plumbing and a login page

The product as specified is a single-user "personal knowledge daemon": one process on the user's Linux server, reached over a WireGuard-based private network or through a Cloudflare Tunnel behind Cloudflare Access, with three doors (watched folders, REST, MCP) feeding one pipeline into a Markdown vault, a small SQLite state store and a disposable search index ([spec.md L16](../spec.md#L16)). Every item carries a registry-backed type with schema-validated properties so "who, when, and which kind" are answered by query rather than similarity, no model vendor is built in, and an instance-wide switch can forbid anything not local ([spec.md L18](../spec.md#L18), [spec.md L60](../spec.md#L60)). Retrieval applies filters first to build a SQL candidate set, then runs FTS5 BM25 and exact in-memory cosine over that set, fuses with RRF, optionally reranks, and returns eight chunks with neighbour expansion; there is no approximate index in v1, and exceeding the one-million-chunk candidate cap yields `degraded: exact-cap` rather than a silent fallback ([spec.md L577-590](../spec.md#L577)). Every response names its degradation reasons (`vector-pending`, `embed-unavailable`, `rerank`, `exact-cap`, `coverage-partial`) ([spec.md L608](../spec.md#L608)), and the chat contract forbids reporting "not in your brain" for a failed search ([spec.md L635-636](../spec.md#L635)). Every assistant write is a pending operation with an immutable payload that only an interactive UI session or paired CLI can approve — API keys and the MCP bridge can never approve — and each turn is capped at 12 newly retrieved documents and 200 KB of tool-result bytes with a per-turn egress manifest showing which documents went to which provider ([spec.md L640](../spec.md#L640), [spec.md L652](../spec.md#L652)). The MCP server authorizes per tool, not per route, with the stdio bridge `brain mcp` read-only by default and `brain_update` always a proposal ([spec.md L506-522](../spec.md#L506)). `local_only` is enforced before every provider call through one policy-owned transport (redirects disabled, DNS pinned, connected address re-checked), backstopped by systemd `IPAddressDeny` or a Compose egress network and an hourly canary whose success under `local_only` refuses provider calls ([spec.md L61-65](../spec.md#L61), [spec.md L867-869](../spec.md#L867)). Extraction runs in a separate pre-provisioned service under its own UID with no network, no secrets and no store access, fed open descriptors over a socket ([spec.md L877](../spec.md#L877)).

What exists is a strict subset of that design. The README's own one-line state reads: "M0 now connects validated YAML configuration, two crash-safe SQLite stores, provider-neutral model roles, privacy transport, credentials, browser sessions, admission limits, source registration, deployment, and the `brain` CLI. Ingestion, extraction beyond ping/descriptor probes, search, and chat land in later milestones" ([README.md L5](../README.md#L5)). The mapped HTTP surface is `/health`, `/ready`, the `/auth/*` login, session, step-up and key endpoints, `POST/GET /sources`, and admin `/providers` and `/diagnostics`; no `/documents`, `/search`, `/query`, `/ask`, `/chat`, `/mcp`, `/pending`, `/jobs` or `/maintenance/*` route exists ([AuthEndpoints.cs L26-85](../src/SecondBrain.Server/Auth/AuthEndpoints.cs#L26), [SourceEndpoints.cs L13-18](../src/SecondBrain.Server/Sources/SourceEndpoints.cs#L13), versus the spec's endpoint table at [spec.md L449-480](../spec.md#L449)). The state schema already carries `conversations`, `turns`, `pending_operations`, `payloads`, `embedding_spaces`, `jobs` and `usage` tables ahead of any code that populates them, but there is no `chunks` table, no FTS5 virtual table and no vector array; a grep for `fts5` across `src/` returns nothing ([M0Schema.cs L9-331](../src/SecondBrain.Storage/Migrations/M0Schema.cs#L9)). The type registry knows `note`, `article` and `file`, not `transcript` or `calendar_event` ([TypeRegistry.cs L122-136](../src/SecondBrain.Core/Domain/TypeRegistry.cs#L122)). The extractor answers exactly two operations, `ping` and `probe_descriptor`, over a 65,536-byte frame that the M1 plan itself says "cannot carry arbitrary full-text output" ([ExtractorSocketServer.cs L163-199](../src/SecondBrain.Extractor/ExtractorSocketServer.cs#L163), [M1-ingest-and-search.md L106](../docs/build/M1-ingest-and-search.md#L106)). The only `FileSystemWatcher` in the codebase watches the configuration file ([ReloadingConfiguration.cs L14-32](../src/SecondBrain.Infrastructure/Configuration/ReloadingConfiguration.cs#L14)). The Blazor UI is five `.razor` files totalling 53 lines: a login form and a page that says you are signed in ([Home.razor](../src/SecondBrain.Server/Components/Pages/Home.razor#L1)). The `brain` CLI has `init`, `login`, `doctor`, `keys`, `providers`, `sessions`, `maintenance rotate-keys` and `serve`; `add`, `search`, `query`, `ask`, `chat`, `get`, `pending`, `mcp`, `stats` and every `sources` subcommand from §12 are absent ([Program.cs L65-176](../src/SecondBrain.Cli/Program.cs#L65), [spec.md L692-715](../spec.md#L692)). No `ModelContextProtocol`, `Markdig`, `PdfPig`, `Anthropic`, `OllamaSharp` or `AesGcm` reference exists anywhere in `src/` ([Directory.Packages.props L8-39](../Directory.Packages.props#L8)).

What has been built is built to a high standard for what it is. The twelve M0 gates pass with named tests — `PrivacyPolicyTests.RefusesHostedAtStartup/AtReload/AtRequest`, `RedirectIsFailure`, `CanaryBlocksProviderCallsAndNextFailureClearsState`, `Authz_ScopeMatrix`, `SymlinkOutsideRootsIsDenied`, `CrashBetweenStoresRecovers`, `AppliedIsFinalizedOnce`, nine `Sessions_*` tests and the Access JWKS tests ([M0-convergence-report.md L25-38](../docs/build/M0-convergence-report.md#L25)) — and the suite stood at **750/750 deterministic tests** at the 2026-10-09 rereview across seven test projects, with 13,076 lines of test code against 12,645 lines of product code ([M0-convergence-report.md L226-237](../docs/build/M0-convergence-report.md#L226)). The Compose project runs the daemon as UID 1654 with a read-only root filesystem, all capabilities dropped, `no-new-privileges`, a 2 GB memory cap and a `NET_ADMIN`-only egress helper that installs default-deny IPv4/IPv6 rules; the extractor runs with `network_mode: none` ([compose.yaml L15-166](../deploy/compose.yaml#L15)); the systemd units carry `ProtectSystem=strict`, an empty `CapabilityBoundingSet`, `IPAddressDeny=any` and `PrivateNetwork=yes` for the extractor ([secondbrain.service L9-47](../deploy/systemd/secondbrain.service#L9), [secondbrain-extractor.service L8-40](../deploy/systemd/secondbrain-extractor.service#L8)). The live vLLM qualification against an RTX 5090 host serving `Qwen/Qwen3-8B` and `Qwen/Qwen3-Embedding-0.6B` passed on 2026-10-09, but the gate "checks configured-role transport/reachability and `/ready`; broader model-quality or native-tool inference evaluation belongs to later milestones" ([M0-convergence-report.md L255-291](../docs/build/M0-convergence-report.md#L255), [M0-convergence-report.md L97](../docs/build/M0-convergence-report.md#L97)). Of the 21 user stories, none is end-to-end satisfiable today; only the Ops/Config preconditions (refusing to start with a non-local binding, credential revocation plumbing) exist ([spec.md L118-138](../spec.md#L118)). No benchmark, seed corpus or `eval/questions.jsonl` exists, so every §17 latency and scale target is aspirational at this commit ([spec.md L957-969](../spec.md#L957)).

## Self-hosted RAG platforms win on breadth and lose on ownership, enforcement and attack surface

The self-hosted "chat with your documents" cluster is where SecondBrain is furthest behind on visible features and furthest ahead on design intent. Open WebUI has **154,118 stars**, thirteen vector-database backends and a release every few weeks ([GitHub API](https://api.github.com/repos/open-webui/open-webui), [env reference](https://docs.openwebui.com/reference/env-configuration)); AnythingLLM has 66,856 stars, twenty-plus LLM providers, desktop and Docker builds, an Android app and one-click cloud templates ([GitHub API](https://api.github.com/repos/Mintplex-Labs/anything-llm), [README](https://github.com/Mintplex-Labs/anything-llm)); RAGFlow has 91,912 stars and a DeepDoc parser with layout analysis, OCR and table recognition ([GitHub API](https://api.github.com/repos/infiniflow/ragflow), [README](https://github.com/infiniflow/ragflow)); Onyx advertises 50+ connectors and "1M+ queries per week" ([README](https://github.com/onyx-dot-app/onyx), [onyx.app](https://www.onyx.app/)). Against a login page, none of this is a contest. The relevant comparison is structural, and on structure every platform in this cluster stores the user's corpus in service databases that are the system of record: AnythingLLM in SQLite plus LanceDB plus parsed JSON copies ([Desktop storage](https://docs.anythingllm.com/installation-desktop/storage)), Open WebUI in `webui.db` plus a vector store with knowledge export only as a zip of `.txt` files ([env reference](https://docs.openwebui.com/reference/env-configuration), [Knowledge docs](https://docs.openwebui.com/features/workspace/knowledge/)), LibreChat in MongoDB plus pgvector plus Meilisearch ([docker-compose.yml](https://github.com/LibreChat-AI/LibreChat/blob/main/docker-compose.yml)), Onyx in Postgres plus OpenSearch plus MinIO ([docker-compose.yml](https://github.com/onyx-dot-app/onyx/blob/main/deployment/docker_compose/docker-compose.yml)), and RAGFlow in Elasticsearch or Infinity plus Postgres plus MinIO plus NATS plus Kvrocks, with knowledge-base backup an open request since 2024 ([FAQ](https://ragflow.io/docs/faq), [issue #3178](https://github.com/infiniflow/ragflow/issues/3178)). SecondBrain's **[spec]** "files first, state small, index disposable" principle ([spec.md L99-108](../spec.md#L99)) has no equivalent here; the closest are the folder-as-source patterns — Open WebUI's in-app SHA-256 "Sync directory" since v0.9.6 and its oikb companion daemon with 44 connectors ([Knowledge docs](https://docs.openwebui.com/features/workspace/knowledge/), [oikb docs](https://docs.openwebui.com/ecosystem/knowledge-base-sync)), PrivateGPT's `make ingest /path -- --watch` ([Ingestion docs](https://docs.privategpt.dev/api-guide/ingestion)), and the dormant GPT4All's `QFileSystemWatcher` collections ([database.cpp](https://github.com/nomic-ai/gpt4all/blob/main/gpt4all-chat/src/database.cpp), [last release 2025-02-25](https://github.com/nomic-ai/gpt4all/releases)) — and even those treat the index, not a revisioned vault, as canonical. AnythingLLM's "live document sync" cannot watch a directory, checks hourly, declares files stale after seven days, does not sync manually uploaded files on Docker, and warns of "Corruption of local database" ([Live document sync](https://docs.anythingllm.com/beta-preview/active-features/live-document-sync)). **[implemented]** SecondBrain has source registration under allowed roots but "no watcher" ([M0-convergence-report.md L101](../docs/build/M0-convergence-report.md#L101)), so on folder sync it is currently behind Open WebUI and PrivateGPT and will reach parity, not lead, when M1 ships U1/U2/U9 ([spec.md L996](../spec.md#L996)).

On retrieval the cluster splits. Hybrid keyword-plus-vector search is native in RAGFlow, whose similarity weight sets "Vector = 0.3, Full-text = 0.7" and whose metadata conditions mean "retrieval only searches content that meets the metadata conditions" ([Search settings](https://github.com/infiniflow/ragflow/blob/main/docs/guides/search/search_settings.md), [Metadata management](https://github.com/infiniflow/ragflow/blob/main/docs/guides/dataset/metadata_management.md)); it is available but **off by default** in Open WebUI (`ENABLE_RAG_HYBRID_SEARCH` False, `RAG_TOP_K` 3) and runs in-database only on pgvector since v0.10.0 ([env reference](https://docs.openwebui.com/reference/env-configuration), [v0.10.0 notes](https://github.com/open-webui/open-webui/releases/tag/v0.10.0)); kotaemon and Onyx are hybrid with reranking and tag filters ([kotaemon README](https://github.com/Cinnamon/kotaemon), [Onyx File connector](https://docs.onyx.app/admins/connectors/official/file)); AnythingLLM is vector-only with 4-6 chunks and hybrid search is an open request with 14 upvotes ([RAG doc](https://docs.anythingllm.com/chatting-with-documents/rag-in-anythingllm), [issue #4338](https://github.com/Mintplex-Labs/anything-llm/issues/4338)); LibreChat is pgvector semantic search returning "top 4 results" ([RAG config](https://www.librechat.ai/docs/configuration/rag_api)). So **[spec]** hybrid-with-RRF would be parity with RAGFlow and Open WebUI, not a differentiator. What is absent everywhere is the two things SecondBrain's retrieval contract puts first: typed document properties (people, time, type) as SQL filters applied before scoring, and a degraded-state flag; the survey behind this report found no documentation set in the cluster that distinguishes "nothing found" from "retrieval degraded", a finding by absence rather than a sourced claim. Citation precision is strongest in RAGFlow ("traceable citations", chunk metadata) and kotaemon (highlighted PDF preview) ([RAGFlow README](https://github.com/infiniflow/ragflow), [kotaemon README](https://github.com/Cinnamon/kotaemon)), while Open WebUI and Onyx cite documents via chips and citation-id packets ([v0.11.4 notes](https://github.com/open-webui/open-webui/releases/tag/v0.11.4), [Onyx core concepts](https://docs.onyx.app/developers/core_concepts)); none resolves a citation to an immutable revision plus excerpt as SecondBrain specifies ([spec.md L655](../spec.md#L655)). A secondary August 2026 test reported AnythingLLM at a 6% hallucination rate versus 11% for PrivateGPT and 14% for Open WebUI on a 5,047-page corpus, but its methodology is unverified ([PromptQuorum](https://www.promptquorum.com/power-local-llm/anythingllm-vs-privategpt-vs-openwebui-rag)).

On agent access the cluster has converged on read-only MCP servers. Onyx exposes "Search your knowledge base", "Search the web" and "Fetch full page content" over HTTP with a personal access token and a one-line `claude mcp add` ([MCP server overview](https://docs.onyx.app/overview/onyx_anywhere/mcp_server)); RAGFlow's Go API serves `ragflow_retrieval`, `ragflow_list_datasets` and `ragflow_list_chats` over Streamable HTTP with a 60-second timeout ([MCP tools](https://github.com/infiniflow/ragflow/blob/main/docs/develop/mcp/mcp_tools.md), [use as MCP server](https://github.com/infiniflow/ragflow/blob/main/docs/develop/mcp/use_ragflow_as_mcp_server.md)); Dify publishes apps as MCP servers whose URL "contains authentication credentials, so treat it like an API key" ([Publish as MCP server](https://github.com/langgenius/dify-docs/blob/main/en/self-host/use-dify/publish/publish-mcp.mdx)). Open WebUI is an MCP client only, Streamable-HTTP-only, admin-only, and says "OpenAPI remains the preferred integration path" ([MCP docs](https://docs.openwebui.com/features/extensibility/mcp)); AnythingLLM's Docker MCP client supports tools but not resources, prompts or sampling ([MCP on Docker](https://docs.anythingllm.com/mcp-compatibility/docker)); PrivateGPT 1.0 takes a different shape entirely, implementing the Claude API so that `private-gpt run claude-code` routes Claude Code's requests through the self-hosted instance ([Claude Code integration](https://docs.privategpt.dev/integrations/claude-code)). None exposes a `remember`/`update` tool, let alone one whose effect is a human-approved proposal; SecondBrain's **[spec]** `brain_remember` (direct create for write credentials) and `brain_update` (always a proposal) would be the only write-capable MCP knowledge server in this group ([spec.md L513-522](../spec.md#L513)) — and **[implemented]** it is the only one with no MCP endpoint at all.

Privacy is where the cluster's "local" claims are weakest and SecondBrain's shipped code is strongest. Open WebUI's `OFFLINE_MODE` only "Disables Open WebUI's network connections for update checks and automatic model downloads", `ENABLE_VERSION_UPDATE_CHECK` and `ENABLE_COMMUNITY_SHARING` default to true, and the offline tutorial concedes that "preventing external network access requires separate network controls" ([env reference](https://docs.openwebui.com/reference/env-configuration), [Offline mode](https://docs.openwebui.com/tutorials/maintenance/offline-mode)). AnythingLLM ships PostHog telemetry on by default and still reaches `cdn.anythingllm.com` and GitHub with telemetry off ([README](https://github.com/Mintplex-Labs/anything-llm)); Onyx's "anonymous telemetry is enabled by default" even though it supports air-gapped deployment ([Data processing](https://docs.onyx.app/security/self_hosted/data_processing)). SecondBrain's **[implemented]** policy-owned transport refuses hosted endpoints under `local_only` at startup, reload and request time, treats a redirect as failure, and blocks provider calls when the canary reaches a public address, with the canary verified "Blocked" under `IPAddressDeny=0.0.0.0/0 ::/0` on the Fedora target host ([M0-convergence-report.md L30-32](../docs/build/M0-convergence-report.md#L30), [M0-convergence-report.md L309-318](../docs/build/M0-convergence-report.md#L309)). That is a genuine, shipped differentiator in this cluster.

The cluster's security record is the strongest argument for SecondBrain's narrowness. Open WebUI's advisory feed returned at least 2,000 published advisories, 158 of them in 2026 (1 critical, 66 high), including session-token theft by any website via a community-stats handler and knowledge-base exposure through the built-in knowledge tool ([advisories](https://github.com/open-webui/open-webui/security/advisories)); it now hands models a shell through "Open Terminal" ([v0.11.4 notes](https://github.com/open-webui/open-webui/releases/tag/v0.11.4)). AnythingLLM's 25 advisories include RCE via ripgrep argument injection in an agent filesystem skill (CVE-2026-48116), stored XSS from "LLM-driven prompt injection" (CVE-2026-41318) and anonymous embed-widget visitors receiving the owner's private memories ([advisories](https://github.com/Mintplex-Labs/anything-llm/security/advisories)). RAGFlow logged four critical RCE or auth-bypass advisories in ten months, including Zip-Slip RCE in a parser and a CVSS 9.8 predictable-token bypass ([advisories](https://github.com/infiniflow/ragflow/security/advisories), [strix.ai](https://www.strix.ai/cve/CVE-2025-69286)); LibreChat's June 2026 batch had a critical "Server Secrets Exfiltration via MCP Server URL Injection" and recurring "Incomplete Fix" entries ([advisories](https://github.com/LibreChat-AI/LibreChat/security/advisories)); Onyx had a critical cross-user OAuth-token leak via its MCP server endpoints ([advisories](https://github.com/onyx-dot-app/onyx/security/advisories)). Parser RCEs are exactly the class SecondBrain's **[spec]** sandbox is designed to contain, and the **[implemented]** extractor already runs under its own UID with `PrivateNetwork=yes` and inaccessible data paths ([secondbrain-extractor.service L8-40](../deploy/systemd/secondbrain-extractor.service#L8)) — but it parses nothing yet, so the containment is unproven against real PDF and DOCX libraries. Resource footprint cuts the same way: Onyx Standard needs 4 vCPU, 10 GB RAM and "32 GB + ~2.5x indexed data" of disk ([Resourcing](https://github.com/onyx-dot-app/documentation/blob/main/snippets/resourcing-overview.mdx)), RAGFlow recommends 16 GB RAM and 50 GB disk and does not run its Go backend on macOS ([README](https://github.com/infiniflow/ragflow)), while SecondBrain's **[spec]** budget is a heap under 1 GB plus the vector array on a single SQLite/FTS5 process ([spec.md L957-969](../spec.md#L957)). Licensing is a governance risk rather than a cost: Open WebUI moved from BSD-3 to a branding-restricted license with a CLA at v0.6.6 on April 19, 2025, which is not OSI-approved ([License FAQ](https://docs.openwebui.com/license/), [LICENSE](https://github.com/open-webui/open-webui/blob/main/LICENSE)), and Dify's license reserves the producer's right to "adjust the open-source agreement to be more strict or relaxed" ([LICENSE](https://github.com/langgenius/dify/blob/main/LICENSE)); SecondBrain, for its part, has no license file at all. Net: in this cluster SecondBrain is behind on everything a user sees, at parity on hybrid retrieval and folder sync once M1 lands, and uniquely positioned on ownership, typed filters, degraded reporting, proposal-gated writes and enforced locality — of which only enforced locality exists in code.

## Open-source second brains already own the Markdown niche but none brokers agents safely

This is the cluster SecondBrain most resembles and the one where its ownership story is least unusual. Plain Markdown on disk is kept by Obsidian, whose Bases views store everything "in your local Markdown files and their properties" ([Bases help](https://obsidian.md/help/bases)); by Basic Memory, "Just files plus a local SQLite index. No servers required" ([README](https://github.com/basicmachines-co/basic-memory)); by the archived Reor ([README](https://github.com/reorproject/reor)); and by Logseq OG, while Logseq's DB version moved graphs into SQLite with an export-only "Markdown Mirror" ([forum](https://discuss.logseq.com/t/whats-new-with-logseq-db-may-16th-2026/35020), [split announcement](https://logseq.io/p/e3YDyX5AYr)). Everything in this cluster that runs as an always-on server stores knowledge in a database instead: Khoj in Postgres/pgvector ([docker-compose.yml](https://github.com/khoj-ai/khoj/blob/master/docker-compose.yml)), Open Notebook in SurrealDB ([README](https://github.com/lfnovo/open-notebook)), Karakeep in SQLite plus Meilisearch plus asset blobs ([env docs](https://github.com/karakeep-app/karakeep/blob/HEAD/docs/docs/03-configuration/01-environment-variables.md)), SiYuan in `.sy` JSON plus a SQLite index ([README](https://github.com/siyuan-note/siyuan)), Trilium in a server-side database with Markdown only as import/export ([README](https://github.com/TriliumNext/Trilium)). SecondBrain's **[spec]** proposition — an always-on daemon whose source of truth is still a Markdown folder ([spec.md L229-233](../spec.md#L229)) — therefore sits in an empty cell of this matrix, and the research sweep found no open-source project "combining a Markdown vault, typed metadata queries, an always-on daemon, scoped MCP tools and write approvals"; the GitHub search for "second brain mcp" returns a long tail of hobby servers at 17 stars or fewer ([search](https://github.com/search?q=second+brain+mcp&type=repositories&s=stars&o=desc)). **[implemented]** the daemon exists and is hardened, but it does not yet read or write a vault, so the cell is occupied by a design, not a product.

Obsidian is a complement rather than a competitor, and the most important partner. Its core ships no AI, LLM or MCP feature, none appears on the roadmap or changelog, and the company states "We do not collect any telemetry data" ([roadmap](https://obsidian.md/roadmap), [changelog](https://obsidian.md/changelog/), [privacy](https://obsidian.md/privacy)). What it does ship are primitives: YAML properties and Bases (August 2025) with formulas and filters, a CLI since 1.12 (February 2026) pitched for "agentic coding tools" with `base:query` producing JSON or CSV — but "Obsidian must be running. The CLI connects to the running Obsidian instance" — and a Headless sync client that can "give agentic tools access to a vault without access to your full computer" but offers no API or MCP of its own ([Bases help](https://obsidian.md/help/bases), [CLI help](https://obsidian.md/help/cli), [Headless help](https://obsidian.md/help/headless)). A SecondBrain vault that writes Obsidian-compatible frontmatter — the **[spec]** managed note format already uses `id`, `type`, `title`, `created`, `updated`, `tags`, `aliases`, `source`, `occurred_at` and `props` ([spec.md L344-357](../spec.md#L344)) — would be queryable by Bases on the desktop and by SQL on the server. The pressure comes from the plugin ecosystem, which is where users are actually getting agentic vault editing today. Copilot for Obsidian has **2,427,070 downloads** and its v4.0.0 rewrite (2026-08-11) runs "Claude Code, Codex, and opencode" natively inside Obsidian so they "plan, search your vault by meaning, use tools, and write results back to your notes", at $14.99/month for Plus ([release 4.0.0](https://github.com/logancyang/obsidian-copilot/releases/tag/4.0.0), [plugin stats](https://github.com/obsidianmd/obsidian-releases/blob/master/community-plugin-stats.json), [pricing](https://www.obsidiancopilot.com/en/pricing)); `claude-sidebar` ("Run Claude Code in your sidebar") has 85,085 downloads ([plugin stats](https://github.com/obsidianmd/obsidian-releases/blob/master/community-plugin-stats.json)). The Local REST API plugin (777,605 downloads, v5.4.0 on 2026-10-06) now ships its own Streamable-HTTP MCP server with `vault_write/append/patch/delete/move`, JsonLogic `search_query` over frontmatter and `command_execute`, behind a single API key with no read-only mode or scopes ([README](https://github.com/coddingtonbear/obsidian-local-rest-api), [plugin stats](https://github.com/obsidianmd/obsidian-releases/blob/master/community-plugin-stats.json)); its successor niche churns, with `obsidian-mcp-tools` archived on 2026-05-13 and `istefox/obsidian-mcp-connector` offering per-client tokens and tool profiles ([obsidian-mcp-tools](https://github.com/jacksteamdev/obsidian-mcp-tools), [obsidian-mcp-connector](https://github.com/istefox/obsidian-mcp-connector)). This pattern gives users most of U4/U5 today — "remember that we chose X" from Claude Code, "what did I decide about auth?" from Claude Desktop — at the cost of coarse authorization, a desktop that must be running and bound to 127.0.0.1, and no retrieval guarantees. It is the closest substitute for SecondBrain's value and the one improving fastest. Smart Connections (1.23 million downloads) shows the ecosystem's commercial drift: it moved from GPLv3 to a non-compete "Smart Plugins License" on December 9, 2025 and put cloud and local model integrations behind paid Pro plugins, drawing a 30-comment "Thoughts on recent changes" thread ([issue #1293](https://github.com/brianpetro/obsidian-smart-connections/issues/1293), [issue #1269](https://github.com/brianpetro/obsidian-smart-connections/issues/1269)); its "Suggestions don't edit your notes" stance is the only no-write posture in the plugin set ([smartconnections.app](https://smartconnections.app/)).

Basic Memory is the single closest architectural cousin. It stores Markdown with frontmatter plus observations and wikilink relations, indexes into local SQLite, runs "Hybrid full-text plus vector ranking, using FastEmbed embeddings" with an optional cross-encoder reranker that "fails loudly instead of falling back silently", needs no LLM in the server, and exposes `write_note`, `edit_note`, `delete_note`, `search_notes`, `build_context` and schema tools over stdio MCP with read-only and destructive hints ([README](https://github.com/basicmachines-co/basic-memory), [MCP tools reference](https://docs.basicmemory.com/raw/reference/mcp-tools-reference.md)). Its "fail loudly" reranker and tool annotations are the nearest existing analogue to SecondBrain's **[spec]** degraded-state reporting and per-tool scopes, but the scope model is advisory, `delete_note` "removes a directory and its contents" with no confirmation parameter, local stdio has no auth layer, and 2026 saw documented data-loss bugs — concurrent-session rollbacks destroying writes (fixed v0.22.1), autosave files overwriting a note's entity row, `replace_section` duplicating content while reporting success ([MCP tools reference](https://docs.basicmemory.com/raw/reference/mcp-tools-reference.md), [releases](https://github.com/basicmachines-co/basic-memory/releases)). It has no ingestion pipeline, no PDF/transcript/calendar typing, and date-only temporal filters; versions and audit trails are cloud features at $15/seat/month ([pricing](https://basicmemory.com/pricing)); telemetry to Umami is on unless `BASIC_MEMORY_NO_PROMOS=1` ([README](https://github.com/basicmachines-co/basic-memory)). Its 4,123 stars under AGPL-3.0 ([GitHub](https://github.com/basicmachines-co/basic-memory)) also calibrate expectations: the "files you own plus MCP" niche is real but small.

The rest of the cluster shows the churn and the gaps SecondBrain can exploit. Khoj (37,610 stars, AGPL) deprecated its cloud on April 15, 2026, has shipped no release since 2.0.0-beta.28 on 2026-03-26, now headlines a different product (Pipali), ships opt-out telemetry on by default, is an MCP client but not a server, and shows note-level rather than passage-level references ([deprecation banner source](https://github.com/khoj-ai/khoj/blob/master/src/interface/web/app/components/deprecationBanner.tsx), [release](https://github.com/khoj-ai/khoj/releases/tag/2.0.0-beta.28), [telemetry docs](https://docs.khoj.dev/miscellaneous/telemetry), [mcp.py](https://github.com/khoj-ai/khoj/blob/master/src/khoj/processor/tools/mcp.py), [chat docs](https://docs.khoj.dev/features/chat)). SurfSense (16,340 stars) abandoned its hosted product in September 2026 for an "air gapped" desktop app with a SQLite index, bundled llama.cpp, "No telemetry or crash reporting", and "Outbound connections are off by default, with an egress panel", deleting cloud data on 2026-10-18 and selling "No egress at all" only to Enterprise ([README](https://github.com/MODSetter/SurfSense), [sunset page](https://www.surfsense.com/sunset), [pricing](https://www.surfsense.com/pricing)) — the nearest open-source privacy posture to SecondBrain's, implemented as a UI toggle rather than a transport policy, and its export "does not include original uploads, generated artifacts, tool calls, agent steps, or live citation links" ([sunset page](https://www.surfsense.com/sunset)). Open Notebook (39,995 stars, MIT) is structurally the most similar always-on server — Docker, REST API, an `open-notebook-mcp` package, 24 providers, full-text plus vector search with cited answers — but it exposes UI and API "on all interfaces with no password by default", locks knowledge in SurrealDB, and carried critical SSTI RCE plus high LFI, path-traversal and SurrealDB-injection advisories in April 2026 ([README](https://github.com/lfnovo/open-notebook), [MCP doc](https://github.com/lfnovo/open-notebook/blob/HEAD/docs/5-CONFIGURATION/mcp-integration.md), [advisories](https://github.com/lfnovo/open-notebook/security/advisories)). Karakeep (29,551 stars) is the best-engineered capture pipeline — browser extensions, mobile share, RSS, importers, full-page archiving, a 29-tool MCP server and API keys with "no access, read-only, or read & write" scopes — but has no chat or citation layer, stores content in SQLite/Meilisearch, and defaults its AI configuration to OpenAI ([docs intro](https://docs.karakeep.app/), [MCP README](https://github.com/karakeep-app/karakeep/blob/HEAD/apps/mcp/README.md), [karakeep.app](https://karakeep.app/), [env docs](https://github.com/karakeep-app/karakeep/blob/HEAD/docs/docs/03-configuration/01-environment-variables.md)). The general PKM apps are moving fastest toward agent operation with the least control: Trilium's built-in MCP (v0.103.0, May 2026) exposes "the same tools that are supported by the internal chat" and its docs state "Currently there is no permission management implemented for note tools" ([MCP.md](https://github.com/TriliumNext/Trilium/blob/HEAD/docs/User%20Guide/User%20Guide/AI/MCP.md), [LLM docs](https://docs.triliumnotes.org/user-guide/llm)); SiYuan's built-in MCP gained OAuth 2.1 in v3.8.6 and lets "Agent and MCP tools … manage Bazaar packages" ([releases](https://github.com/siyuan-note/siyuan/releases)). Reor, the one desktop app that validated "plain Markdown + local vectors", was archived on 2026-03-07 ([GitHub](https://github.com/reorproject/reor)).

The verdict for this cluster: SecondBrain's ownership model is parity with Obsidian, Basic Memory and (locally) Letta, not a differentiator; its always-on reachability is parity with Khoj, Open Notebook and Karakeep; its typed-document SQL layer is matched in spirit only by Obsidian Bases, Logseq DB properties and SiYuan databases, none of which an AI answer path uses as a pre-filter; and its **[spec]** per-tool scopes, proposal-gated writes, revision-pinned citations and degraded reporting are unmatched. The market signal is unambiguous — users want Claude Code and Codex inside their Markdown vault — and "the infrastructure gap is a trustworthy, always-on, scoped broker between vault and agents", which is precisely the role SecondBrain targets and has not yet built.

## Agent memory layers monetize extraction, and unreviewed writes are their loudest failure

The agent-memory cluster is where SecondBrain's write-approval and provenance design looks least like a nicety and most like a response to the field's dominant failure mode. The six in-depth systems split three ways: LLM-extracted "memory items" in a vector or vendor database (Mem0, Supermemory), LLM-extracted temporal knowledge graphs (Zep/Graphiti, Cognee), and plain Markdown edited by the agent (Letta's git-backed MemFS, Basic Memory). Only the Markdown systems give the user an owned, readable, versioned artefact, and none of the six requires a human to approve an agent's write, overwrite or delete. Mem0 — 66.9k stars, $24M raised by October 2025, and the self-described "Memory Layer for AI Agents" ([GitHub](https://github.com/mem0ai/mem0), [TechCrunch](https://techcrunch.com/2025/10/28/mem0-raises-24m-from-yc-peak-xv-and-basis-set-to-build-the-memory-layer-for-ai-apps/)) — keeps OSS memory as vector-store rows plus a SQLite history table whose default path is `:memory:`, so history is lost at process exit unless configured ([storage.py](https://github.com/mem0ai/mem0/blob/main/mem0/memory/storage.py)); it removed all OSS graph-store drivers ("~4000 lines") with "no OSS replacement", making graph memory a hosted Pro feature ([OSS graph memory page](https://docs.mem0.ai/open-source/graph_memory/overview)); its hosted MCP exposes `update_memory`, `delete_memory`, `delete_all_memories` and `delete_entities` to any connected client with no approval flow ([Mem0 MCP](https://docs.mem0.ai/platform/mem0-mcp)); and its PostHog telemetry defaults on ([telemetry.py](https://github.com/mem0ai/mem0/blob/main/mem0/memory/telemetry.py)). Issue #4573, opened 2026-03-27, audited 10,134 Mem0 entries from a 32-day run and found **97.8% junk** — 52.7% system-prompt restatements, 5.2% hallucinated user profiles, 2.1% security or privacy leaks, 2,468 exact-hash duplicates, and 808 entries asserting "User prefers Vim" from a recall-then-re-extract feedback loop ([issue #4573](https://github.com/mem0ai/mem0/issues/4573)). The caveat that a 2B-parameter extractor ran for twenty of those days does not rescue the design point: unreviewed extraction at scale produced a corpus the user could no longer trust. Graphiti (31.6k stars) has the richest temporal provenance in the field — bi-temporal `created_at/valid_at/invalid_at/expired_at` edges, invalidated edges retained, facts tied to source episodes ([Facts](https://help.getzep.com/facts.md), [How graph creation works](https://help.getzep.com/how-graph-creation-works.md)) — yet issue #1728 (2026-08-04) reports that "Edge invalidation searches the whole graph, so unrelated facts retire each other", with **41% of a 3,950-fact graph invalidated** and three of four audited retirements wrong, no maintainer response at the time of research ([issue #1728](https://github.com/getzep/graphiti/issues/1728)); its OSS MCP server has no authentication and exposes `clear_graph` ([Graphiti MCP README](https://github.com/getzep/graphiti/tree/main/mcp_server)), and Zep's self-hosted Community Edition "is no longer supported" ([getzep/zep](https://github.com/getzep/zep)). Letta's MemFS is the closest in spirit to SecondBrain on file ownership — "Every memory edit is committed to the git repository" of Markdown files — but "The repository belongs to the agent and is hosted by Letta for cloud agents", local-mode remote sync returns 501, the open-source Docker image "is no longer supported as a backend", and the optional "Agent reviews before applying" step "does not ask for your approval" ([MemFS concepts](https://docs.letta.com/concepts/memfs), [Letta Code self-hosting](https://docs.letta.com/letta-code/selfhosting), [Letta Code memory](https://docs.letta.com/letta-code/memory)); issue #4930 documents "a harmful reflection stayed in memory for about 14 seconds before a watcher reverted it" under auto-merge and asks for traceability trailers because commit attribution per agent is undocumented ([issue #4930](https://github.com/letta-ai/letta-code/issues/4930)). Cognee (31.9k stars, $7.5M seed in February 2026) keeps engine-owned Kuzu/LanceDB/SQLite files, shipped six releases with breaking changes in five weeks, exposes `forget` over an MCP endpoint with "no client login", and sells "provenance on every answer" as an Enterprise bullet ([cognee.ai blog](https://www.cognee.ai/blog), [releases](https://github.com/topoteretes/cognee/releases), [cognee-mcp README](https://github.com/topoteretes/cognee/tree/main/cognee-mcp), [pricing](https://www.cognee.ai/pricing)). Supermemory is the strongest on revision provenance — `version`, `isLatest`, `parentMemoryId`, `history[]`, `documentIds`, `isInference` ([memory entries API](https://supermemory.ai/docs/api-reference/content-management/list-memory-entries-with-history.md)) — and its review queue is the nearest commercial analogue to `brain_update`, but it gates only inferred memories, "the API does not verify a human is behind the call", the self-hosted server is "built from a separate non-public codebase", and MCP and connectors are cloud-only ([Memory review](https://supermemory.ai/docs/recall/memory-review.md), [Self-hosting overview](https://supermemory.ai/docs/self-hosting/overview.md), [Supermemory MCP](https://supermemory.ai/docs/supermemory-mcp/mcp.md)).

The pattern across the cluster is that hosted "memory APIs" monetise extraction and retrieval per token or credit while the open-source cores thin out — Mem0's graph removal, Zep's CE deprecation, Supermemory's closed server, Letta's retired V1 server — so "Self-hosters are increasingly left with libraries, not products." Benchmarks do not settle anything: Mem0's own paper shows full-context prompting (72.90) beating every memory system including Mem0 (66.88) on LoCoMo ([arXiv HTML](https://arxiv.org/html/2504.19413v1)); Zep's rebuttal accuses Mem0 of mis-attributing speakers and reports Zep at 75.14 versus Mem0g at 68.44 ([Zep blog](https://www.getzep.com/blog/lies-damn-lies-statistics-is-mem0-really-sota-in-agent-memory/)); an audit found 6.4% of the LoCoMo answer key wrong and the judge accepting up to 63% of intentionally wrong answers ([Penfield Labs](https://dev.to/penfieldlabs/we-audited-locomo-64-of-the-answer-key-is-wrong-and-the-judge-accepts-up-to-63-of-intentionally-33lg)); and Letta showed that gpt-4o-mini with plain grep/search/open file tools scores 74.0% ([Letta blog](https://www.letta.com/blog/benchmarking-ai-agent-memory/)). Two further findings matter for positioning. First, per-memory authorship by agent or credential is a blind spot across the category — Mem0's `actor_id`, Cognee's pipeline-conditional provenance graph, GitHub Copilot's cited memories and Anthropic Managed Agents' session-attributed `memver_` versions are the only partial cases ([storage.py](https://github.com/mem0ai/mem0/blob/main/mem0/memory/storage.py), [Memory Provenance](https://docs.cognee.ai/guides/memory-provenance.md), [Copilot Memory](https://docs.github.com/en/enterprise-cloud@latest/copilot/concepts/agents/copilot-memory), [Managed Agents memory](https://platform.claude.com/docs/en/managed-agents/memory)) — so SecondBrain's **[spec]** `<door>:<credential name>` provenance on every document ([spec.md L391](../spec.md#L391)), already reserved as `initiating_credential_id` columns in the **[implemented]** schema ([M0-foundations.md L42](../docs/build/M0-foundations.md#L42)), can be claimed as a first-class property. Second, the only systems that put a human in front of an agent's write are hobby- or experiment-scale: graphiti-local ("You approve what they learn"; six read-only MCP tools; a review file where a human marks each fact accept/refuse before a checksum-sealed snapshot is promoted) and Gemini CLI's experimental Auto Memory, where "nothing applies until approved via `/memory inbox`" ([graphiti-local](https://github.com/renezander030/graphiti-local), [Auto Memory](https://geminicli.com/docs/cli/auto-memory/)). Zep Cloud's per-connection read-only toggle and account kill switch ("Writes are allowed by default") are the only brakes among funded products ([Memory MCP server](https://help.getzep.com/v3/memory-mcp-server)).

The vendor-native layer narrows what a third-party brain is for without replacing it. Claude Code's auto memory is "plain markdown you can edit or delete at any time" under `~/.claude/projects/<project>/memory/`, but only the first 200 lines or 25 KB of `MEMORY.md` load per conversation and it is per-repository and per-machine ([Claude Code memory](https://code.claude.com/docs/en/memory)); the Anthropic API memory tool "operates client-side: Claude requests file operations, and your application executes them" ([Memory tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool)), which makes SecondBrain a candidate `/memories` backend rather than a competitor; Cursor removed its Memories feature in 2.1.17 and told users to export to `.mdc` rules ([Cursor forum](https://forum.cursor.com/t/memories-not-showing/143820)); Windsurf's memories "apply only to the legacy Cascade agent" ([Devin docs](https://docs.devin.ai/desktop/cascade/memories)). These withdrawals within months are concrete evidence of the lock-in risk a user-owned vault avoids. Technical users say the same thing on Hacker News: in the 312-comment Claude Memory thread, "The memory layer should exist locally, with these external servers acting as nothing else but LLM request fulfillment", and in a Claude Code thread, "Honestly? It just _has_ to be local", with the standing counter-argument that hand-kept Markdown "becomes a coordination mechanism you have to keep in sync manually" ([HN: Claude Memory](https://news.ycombinator.com/item?id=45684134), [HN: Stop Claude Code from forgetting](https://news.ycombinator.com/item?id=46426624)) — the sync burden is the problem an MCP server over one vault removes.

MCP itself constrains and enables the design in specific ways. The current revision really is `2026-07-28`: it removed protocol-level sessions and the `initialize` handshake, made `server/discover` mandatory, replaced server-initiated requests with Multi Round-Trip Requests, dropped SSE resumability, and formally deprecated the HTTP+SSE transport, Roots, Sampling, Logging and Dynamic Client Registration ([2026-07-28 changelog](https://modelcontextprotocol.io/specification/latest/changelog), [release post](https://blog.modelcontextprotocol.io/posts/2026-07-28/)); SecondBrain's **[spec]** `POST /mcp` "per the MCP revision of 2026-07-28" with no protocol sessions, exact-match `Origin`, signed cursors and `server/discover`-first is consistent with all of that ([spec.md L506-511](../spec.md#L506)). Authorization is OAuth 2.1 "at the transport level" only, stdio servers "SHOULD NOT follow this specification, and instead retrieve credentials from the environment", scope names are entirely server-defined, and `tools/list` "MAY vary by the authorization presented on the request — for example, returning only the tools the caller's granted scopes permit" ([Authorization](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization), [Tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools)). Human-in-the-loop confirmation is a client-side SHOULD ("there SHOULD always be a human in the loop with the ability to deny tool invocations"), and clients must treat tool annotations as untrusted ([Tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools)). Three implications follow: SecondBrain's read/write/infer/admin scope matrix is an application-layer design that the protocol now sanctions (a read-only bridge key legitimately sees only read tools) but every competitor's "authorization" is likewise application-level, because no MCP memory server inherits per-tool permissions from the protocol; a server-side proposal queue is strictly stronger than the client-side confirmation the spec asks for, which matters because Claude's Research "can invoke connector tools without further approval" and Gemini CLI's `trust` flag bypasses prompts ([custom connectors](https://support.claude.com/en/articles/11175166-getting-started-with-custom-connectors-using-remote-mcp), [Gemini CLI MCP](https://geminicli.com/docs/tools/mcp-server/)); and the new local-server security guidance — "The stdio transport is not a sandbox", "Binding to 127.0.0.1 is not an authentication boundary" — argues for keeping `brain mcp` a pure stdio forwarder of a stored key ([Local Server Security](https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/local-server-security)). Governance moved to the Linux Foundation's Agentic AI Foundation on 2025-12-09 with 146 members by February 2026 ([AAIF Q1 update](https://aaif.io/blog/aaifs-first-quarter-success-story-new-members-technical-wins-and-open-governance)); the registry "is currently in preview", "does not support private servers" and is "not designed for self-hosting" ([Registry about](https://modelcontextprotocol.io/registry/about)), while third-party look-alikes such as `com.saastemly/mem0-cloud` already appear under familiar names ([registry search](https://registry.modelcontextprotocol.io/v0/servers?search=mem0&limit=20)) — a trust hazard that favours a bridge users install from their own daemon over registry discovery. **[implemented]** none of this exists in SecondBrain's code: no MCP package is referenced and the stdio bridge, per-tool scopes and `brain_update` proposals are M2 work ([spec.md L997](../spec.md#L997)).

## Commercial PKM tools changed names, owners or prices within eighteen months

The commercial cluster beats SecondBrain on polish, mobile apps, zero setup and in some cases citation precision, and it demonstrates the continuity risk that a self-hosted vault is designed to escape. Google's NotebookLM, renamed Gemini Notebook on 2026-07-16 with "more than 30 million people and over 600,000 organizations" using it ([Google blog](https://blog.google/innovation-and-ai/products/gemini-notebook/notebooklm-gemini-notebook/)), remains the only commercial product documented as linking inline citation numbers to the specific passage in a source ([Google blog](https://blog.google/technology/ai/notebooklm-goes-global-support-for-websites-slides-fact-check/), [Bowdoin KB](https://bowdoin.teamdynamix.com/TDClient/1814/Portal/KB/ArticleDet?ID=171371)); that is parity with SecondBrain's **[spec]** excerpt-level citation, and SecondBrain's revision pinning and degraded flag would be the only additions. But Gemini Notebook is a closed notebook: per-notebook source caps run from 50 on the free tier to 600 on the $200 Ultra tier ([Google help](https://support.google.com/notebooklm/answer/16213268)), there is no bulk export beyond copy-paste workarounds and scraping extensions ([Supademo](https://supademo.com/blog/how-to-export-notes-from-notebooklm), [nlmtools](https://www.nlmtools.com/blog/notebooklm-export-sources)), the only API is an enterprise `v1alpha` Discovery Engine surface ([Google Cloud docs](https://cloud.google.com/agentspace/notebooklm-enterprise/docs/api-notebooks)), the model is Google's with no user choice, and the Ultra plan was repriced from $250 to $100/$200 in May 2026 ([Engadget](https://www.engadget.com/2176060/the-google-ai-ultra-plan-now-starts-at-100-a-month)). Notion AI has the most complete official MCP — hosted, OAuth, search, read, create and update pages and databases, managed per workspace ([Notion developers](https://developers.notion.com/docs/mcp)) — and a clear policy that "Notion and its AI Subprocessors do not use Customer Data to train any models", but non-Enterprise plans let "LLM providers … retain Customer Data for 30 days or fewer", embeddings are created with OpenAI's API and stored in Turbopuffer ([Notion AI security practices](https://www.notion.com/help/notion-ai-security-practices)), full AI now requires the $20/member Business plan ([Notion pricing](https://www.notion.com/pricing)), and whole-workspace export flattens databases to a single view, converts callouts to HTML, expires after seven days and "can take up to 30 hours" ([Notion export help](https://www.notion.com/help/export-your-content)). That 30-day provider retention is exactly the dimension SecondBrain's **[spec]** `local_only` transport and per-turn egress manifest control ([spec.md L652](../spec.md#L652), [spec.md L858-863](../spec.md#L858)); no commercial product in the set discloses or caps per-request data exposure to the model.

Three commercial products are SecondBrain's genuine analogues on specific axes. Tana is the only one whose write-safety story resembles the proposal gate: extracted decisions and tasks "land as proposals you approve, so a human stays in the loop", and MCP lets Claude Code "read and write your Tana knowledge through the same proposal review" ([Tana blog](https://tana.inc/blog/best-second-brain-apps-2026)); its typed nodes with `parent.field` search expressions give real who/when/type querying ([Tana April 2026](https://outliner.tana.inc/blog/tana-current-april-2026)). Yet Tana split into two products in March 2026 with "no forced migration", raised its early-bird Pro to $20 against a $30 list price, offers vendor models only (GPT-5.4 default, Claude 4.6, Gemini 3.1 Pro) with local models "On the horizon", and had to plan trash restore partly because MCP usage "can lead to accidental deletions" ([Tana March 2026](https://outliner.tana.inc/blog/tana-current-march-2026), [Tana pricing](https://tana.inc/pricing), [Tana April 2026](https://outliner.tana.inc/blog/tana-current-april-2026)) — proposals for extraction, apparently, did not stop deletions through MCP. Heptabase offers the only read-only MCP mode in the commercial set ("A read-only connection can browse and read content, but writing tools will not appear in its tool list"), exposes both `search_by_keyword` and `search_by_semantic`, exports all notes as Markdown plus an `All-Data.json` backup, is "cash-flow positive since our first year", and pledges to open-source the product if it shuts down ([Heptabase MCP](https://support.heptabase.com/en/articles/12679581-how-to-use-heptabase-mcp), [Heptabase sustainability](https://support.heptabase.com/en/articles/10364279-how-sustainable-is-heptabase-can-i-easily-export-my-data-and-move-on)); its model menu is tier-gated (Gemini-only at $8.99, GPT/Claude/Gemini from $17.99) ([Heptabase pricing](https://heptabase.com/pricing)). Reflect pivoted on 2026-07-14 to "Reflect Open", a free, open-source, local-first Mac app that stores "ordinary Markdown files on your computer", syncs via iCloud Drive or Git, calls AI only with the user's own OpenAI, Anthropic, Google or OpenRouter key, never sends notes marked Private to AI, and ships a CLI (`reflect search`, `reflect show`) that the FAQ suggests pointing Claude Code at ([Reflect blog](https://reflect.app/blog/reflect-open)) — the closest commercial-origin product to SecondBrain's ownership model, with no daemon, no REST or MCP surface, no typed documents and no hybrid search. Reflect's earlier end-to-end-encrypted design made its API "write-only and append-only" because servers could not read note contents ([Reflect API post](https://reflect.app/blog/reflect-update-api)), a useful contrast: SecondBrain gets server-side search and MCP by locating privacy in network placement (WireGuard/Tailscale, `local_only`) rather than in E2E encryption.

The rest of the set confirms three structural gaps SecondBrain targets. On agent write safety, most official MCP servers hand agents unrestricted mutation: Fabric's 19 tools include `fabric-delete-item`, `fabric-move-items` and `fabric-edit-memory` ([Fabric MCP guide](https://fabric.so/guide/ai-tools/MCP-setup)); Capacities' AI Chat Connectors request "read and write access to your Capacities space" for ChatGPT, Claude, Cursor, LM Studio and others, scoped to one space but with no proposal layer ([Capacities docs](https://docs.capacities.io/reference/ai-chat-connectors)); Readwise's MCP has read and write tools and, usefully, `reader_export_documents` that "triggers an export of your Reader documents as a ZIP of Markdown files" ([readwise.io/mcp](https://readwise.io/mcp)); Evernote's MCP (read and create) is open to all paid users ([Evernote help](https://help.evernote.com/hc/en-us/articles/51596325640339-Evernote-MCP-Model-Context-Protocol)). On model choice, no cloud product runs a local model: BYO keys exist at Reflect Open, Saner.ai and Readwise (OpenAI key for custom Ghostreader prompts) ([Saner.ai pricing](https://www.saner.ai/pricing), [Readwise update](https://readwise.io/reader/update-aug2026)); Evernote's v11 assistant was "developed in close collaboration with OpenAI" ([TechRadar](https://www.techradar.com/pro/evernote-unveils-its-biggest-update-yet-and-unsurprisingly-theres-ai-involved)); Mem meters usage on a seven-rung ladder from Free to $199/month where the free tier allows 25 new notes a month ([Mem pricing](https://get.mem.ai/pricing)); and Capacities' LM Studio connector is the only route to a fully local model over a commercial PKM, working by letting a local client read cloud-stored notes ([Capacities docs](https://docs.capacities.io/reference/ai-chat-connectors)). SecondBrain's **[implemented]** provider layer already binds chat, enrich and embed roles to a self-hosted vLLM server through a policy-owned transport ([M0-convergence-report.md L291](../docs/build/M0-convergence-report.md#L291)), which has no commercial equivalent. On structured questions, only the object and outliner tools — Tana supertags/fields, Capacities typed objects with "smart queries", Notion databases — have properties an AI can filter on; NotebookLM, Mem, Readwise, Recall, Fabric and Evernote answer who/when/type questions by LLM reading or semantic similarity, and "none document SQL-style pre-filtering before ranking" ([Capacities pricing](https://capacities.io/pricing), [Fabric MCP guide](https://fabric.so/guide/ai-tools/MCP-setup), [Mem API guide](https://get.mem.ai/guides/mem-api-mcp-custom-workflows)).

Continuity is the cluster's defining risk and the vault's defining advantage. Limitless was acquired by Meta on 2025-12-05, stopped selling the Pendant the same day, wound down the Rewind desktop app and web/desktop recording, required remaining users to accept new terms, and ended service in the EU, UK, Brazil, Israel, South Korea, Turkey and China with a 2025-12-19 export deadline before accounts were "permanently deleted" ([limitless.ai](https://www.limitless.ai/), [TechInformed](https://techinformed.com/meta-acquires-limitless-pendant-users-moved-to-free-unlimited-plan/)); Bee was bought by Amazon ([Entrepreneur](https://www.entrepreneur.com/business-news/amazon-acquires-bee-startup-behind-eavesdropping-wearable/494971)). Evernote under Bending Spoons restructured to Starter at $99/year with a 1,000-note cap and Advanced at $249.99/year in July 2026, and a 12,000-note user calling AI search "useless and irrelevant" announced a migration ([Evernote compare plans](https://evernote.com/compare-plans), [TidBITS Talk](https://talk.tidbits.com/t/evernote-2026-price-tiers-floored-me/33792)). Notion removed its $10 AI add-on in May 2025 and introduced credit metering in May 2026 ([coworker.ai](https://coworker.ai/blog/notion-ai-pricing), [Airframe](https://www.airframe.ai/product/notion-com-product-agents/analysis)); Mem relaunched as 2.0 in October 2025 and replaced a flat $12 plan with the $29-recommended ladder by August 2026 ([Mem blog](https://get.mem.ai/blog/mem-2-dot-0), [usagepricing](https://www.usagepricing.com/blueprint/mem)); Capacities raised then cut its top tier within two months ([CostBench](https://costbench.com/changelog/capacities-price-decrease-2026-04/)). Within eighteen months every product examined in depth changed its name, owner, pricing model or core architecture at least once. Microsoft Recall is the one mainstream product with SecondBrain-like local guarantees — snapshots "stored locally on the device", "No internet or cloud connections are required", encrypted with TPM keys inside a VBS enclave, opt-in and off by default — but it is Windows Copilot+-only, screenshot-based, still "(preview)", exportable only in the EEA with a one-time key, and actively blocked by Signal, Brave and AdGuard ([Microsoft Support](https://support.microsoft.com/en-us/windows/privacy-and-control-over-your-recall-experience-d404f672-7647-41e5-886c-a3c59680af15), [The Register](https://theregister.com/2025/06/16/microsoft_snapshot_export_recall), [The Register](https://www.theregister.com/2025/07/23/brave_browse_block_microsoft_recall/)). Capital, meanwhile, is flowing to meeting capture and agent memory rather than PKM: Granola raised a $125M Series C at a $1.5B valuation in March 2026 and launched an MCP server in February ([Reworked](https://www.reworked.co/digital-workplace/granola-raises-125m-launches-enterprise-context-tools/)). For SecondBrain the practical reading is that Readwise, Granola, Karakeep and a pendant's export are upstream feeds, Obsidian is the editor, and the durable vendor-neutral sink they all lack is the product.

## General assistants cap corpora at 5 to 600 files, train by default, and reach only public endpoints

None of the general-purpose assistants can hold a technical user's corpus, and all of them matter to SecondBrain as MCP clients rather than as rivals. ChatGPT Projects cap files at 5 (Free), 25 (Go/Plus) and 40 (Pro/Business/Enterprise), a limit OpenAI support called "not ideal, agreed" in May 2026 ([OpenAI community thread](https://community.openai.com/t/chatgpt-projects-20-file-limit/1064482)); Claude Projects have no file-count limit but "their total content must fit within Claude's context window" at 30 MB per file, after which paid plans switch to RAG that "can expand capacity by up to 10x" using a search tool the user cannot force ([What kinds of documents](https://support.claude.com/en/articles/8241126-what-kinds-of-documents-can-i-upload-to-claude-ai), [What are Projects](https://support.claude.com/en/articles/9517075-what-are-projects), [RAG for Projects](https://support.claude.com/en/articles/11473015-retrieval-augmented-generation-rag-for-projects)); Perplexity Spaces hold 50 files on Pro and 500 on Max, and "For long files, the system extracts the most important parts" ([What are Spaces](https://intercom.help/perplexity-ai/en/articles/10352961-what-are-spaces), [File Uploads](https://intercom.help/perplexity-ai/en/articles/10354807-file-uploads)); Copilot Notebooks allow at most 300 files per notebook ([Office Watch](https://office-watch.com/2026/copilot-notebooks-explained/)); Gemini Notebook runs from 50 to 600 sources per notebook ([Gemini Notebook plans](https://support.google.com/gemininotebook/answer/16213268)). Every vendor describes retrieval as the model choosing relevant chunks; none exposes a filter-then-score query over typed properties, dates or people, and none reports index health. Vendor memory is a preferences store, not a knowledge store: OpenAI's FAQ says memory "should not be relied on to store exact templates or large blocks of verbatim text" and its June 2026 "Dreaming" update made the summary "continuously rewrite itself in the background" ([OpenAI Memory FAQ, not fetched directly](https://help.openai.com/en/articles/8590148-memory-faq), [Calmara, secondhand](https://calmara.app/blog/migrate-chatgpt-memory-before-it-rewrites-itself)); Claude saves memory as editable topics, "focuses on work-related topics", and "export" means asking Claude to write its memories out verbatim ([How does Claude's memory work](https://support.claude.com/en/articles/11817273-how-does-claude-s-memory-work), [Import and export memory](https://support.claude.com/en/articles/12123587-import-and-export-your-memory-from-claude)); Gemini's Memory requires a Google AI plan and "is only available in the US" ([Memory availability](https://support.google.com/gemini/answer/16598625?hl=en&co=GENIE.Platform%3DDesktop)). An independent July 2026 portability test of seven memory products found "all 7 lock you in": ChatGPT's account ZIP "covers conversations only. Saved memories have no export", Claude exports memory "as a text summary", and Gemini's saved info is "not separately exportable" ([Stan Tyan](https://dev.to/stantyan/i-tested-7-ai-memory-products-for-portability-all-7-lock-you-in-31pm)). Project knowledge files are excluded from Claude member exports ([claude.com import docs, from search extraction](https://claude.com/docs/third-party/claude-desktop/import)). SecondBrain's **[spec]** vault plus rebuildable index has no corpus cap and its full export is a maintenance endpoint ([spec.md L478](../spec.md#L478)); **[implemented]** it has neither a corpus nor an export yet.

The data-use defaults are what a privacy-conscious single user would object to, and they are uniform. Anthropic's August 28, 2025 consumer-terms change uses Free/Pro/Max chats and Claude Code sessions for training when the setting is on, retains opted-in data for five years and otherwise 30 days, and excludes Team, Enterprise and API customers ([Anthropic](https://www.anthropic.com/news/updates-to-our-consumer-terms)); Google's Keep Activity, on by default, uses chats "to improve services, including training generative AI models", keeps them 18 months by default, and human-reviewed samples are "retained for up to three years" and not removed by deleting activity ([Gemini Apps Privacy Hub](https://support.google.com/gemini/answer/13594961)); Perplexity's "AI Data Retention is enabled by default" for Free, Pro and Max, the opt-out is forward-only, and "Previously collected training data cannot be deleted or removed" ([Perplexity Data Collection](https://intercom.help/perplexity-ai/en/articles/11564572-data-collection-at-perplexity)); OpenAI's consumer and Team logs sat under a court preservation order from May 13, 2025 until the going-forward duty was lifted on October 9, 2025, with already-preserved logs remaining accessible ([CyberInsider](https://cyberinsider.com/us-court-orders-openai-to-preserve-all-chatgpt-logs-indefinitely/), [Mashable via Yahoo](https://www.yahoo.com/news/articles/judge-lifts-order-requiring-openai-151518813.html)). Contractual no-training, zero retention and residency exist only on enterprise or API tiers a home user cannot buy at single-seat scale. SecondBrain's **[implemented]** `local_only` transport and **[spec]** egress manifest address the one dimension none of these policies govern — what leaves the machine per request — rather than what the vendor promises to do afterwards.

The incident record is the sharpest argument for SecondBrain's read-caps and proposal design. Across 2025-2026 every major assistant's connector or browser surface fell to a zero-click or one-click prompt-injection exfiltration: EchoLeak against Microsoft 365 Copilot via a crafted email (CVE-2025-32711) ([Simon Willison](https://simonwillison.net/2025/Jun/11/echoleak/)); AgentFlayer, where a poisoned Google Drive document made ChatGPT search Drive for secrets and leak them through image URLs, with the first mitigation bypassed via Azure Blob URLs ([Cyber Security News](https://cybersecuritynews.com/chatgpt-0-click-connectors-vulnerability)); Gemini's calendar-invite "Invitation Is All You Need" achieving smart-home control and email exfiltration ([SafeBreach](https://www.safebreach.com/blog/invitation-is-all-you-need-hacking-gemini/)); Comet reading Gmail and leaking a one-time password on the strength of hidden Reddit-comment instructions, with an incomplete first fix ([Brave](https://brave.com/blog/comet-prompt-injection/)); and "Tainted Memories", a CSRF that injects persistent instructions into ChatGPT memory "across all devices", which OpenAI said it could not reproduce ([The Register](https://www.theregister.com/2025/10/27/atlas_vulnerability_memory_injection/)). Anthropic's own numbers for Claude for Chrome — 23.6% attack success without mitigations, 11.2% with — show the class is unsolved ([Anthropic](https://claude.com/blog/claude-for-chrome)), and the "lethal trifecta" framing (private data, untrusted content, an exfiltration channel) rates guardrails with "95% detection" as "a failing grade in web security" ([Simon Willison](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/)). SecondBrain's **[spec]** per-turn read caps, egress manifest, read-only `ask` surface and proposal-gated writes answer the exfiltration and consequential-action legs structurally ([spec.md L639-652](../spec.md#L639)), and its own spec concedes that prompt-injection resistance "is tested as a mitigation (§20); it is never the boundary" ([spec.md L852](../spec.md#L852)) — but it inherits the untrusted-content leg from whatever enters its inbox, and memory-as-injection-target (Tainted Memories) is the exact failure a human-approved, revisioned write path prevents.

Which assistants can actually reach a SecondBrain is the decisive practical finding. Claude's custom connectors run on Free (one connector), Pro, Max, Team and Enterprise with OAuth or fixed request headers for "API keys, bearer tokens, or other fixed credentials", but the server "must be reachable over the public internet from Anthropic's IP ranges", the connection "originates from Anthropic's cloud" for every client including mobile, local servers are "not available in Cowork or claude.ai", and Research can invoke connector tools without approval ([custom connectors](https://support.claude.com/en/articles/11175166-getting-started-with-custom-connectors-using-remote-mcp)). Claude Code speaks stdio, HTTP (recommended) and deprecated SSE with `--header "Authorization: Bearer ..."`, OAuth discovery, per-tool `mcp__<server>__<tool>` allow/deny/ask rules and a 25,000-token default MCP output limit ([Claude Code MCP](https://code.claude.com/docs/en/mcp)); Claude Desktop runs local servers as `.mcpb` extensions with keychain-stored secrets ([local MCP on Desktop](https://support.claude.com/en/articles/10949351-getting-started-with-local-mcp-servers-on-claude-desktop)); Codex CLI, the IDE extension and the ChatGPT desktop app support STDIO and Streamable HTTP with `bearer_token_env_var`, while "ChatGPT web" uses only remote MCP tools from installed plugins ([Codex MCP docs](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)); ChatGPT web's developer mode for custom connectors is plan-gated in ways sources dispute, with OpenAI's own article describing full MCP for Business, Enterprise and Edu ([OpenAI developer-mode article, not fetched directly](https://help.openai.com/de-de/articles/12584461-developer-mode-apps-and-full-mcp-connectors-in-chatgpt-beta), [Hjarni](https://hjarni.com/mcp-fix/chatgpt-mcp-connectors-not-showing)); Gemini CLI supports stdio, SSE and streamable HTTP with `includeTools`/`excludeTools`, but "was replaced by Antigravity CLI on June 18th, 2026" for unpaid and Google One users ([Gemini CLI MCP](https://geminicli.com/docs/tools/mcp-server/)); Le Chat lets even Free users "connect to any remote MCP server" ([Mistral](https://mistral.ai/news/le-chat-mcp-connectors-memories)); Microsoft 365 Copilot takes custom MCP connectors only through tenant admins (GA February 2026) ([Microsoft release communications](https://www.microsoft.com/releasecommunications/api/v2/m365/501585)); Perplexity's help center has no MCP article ([Perplexity Connectors](https://www.perplexity.ai/help-center/en/collections/18799295-connectors-integrations)). The consequence for a WireGuard/Tailscale-only daemon — SecondBrain's **[spec]** default, with "no public-bind option" ([spec.md L818](../spec.md#L818)) — is that Claude Code, Claude Desktop, Codex/ChatGPT desktop and Gemini CLI can reach it because they run on the user's machine, while claude.ai, Claude mobile, ChatGPT web, Le Chat and M365 Copilot cannot. The Cloudflare Tunnel plus Access path opens the vendor-cloud route, but Access sits in front of `/mcp`, so Claude's and Codex's OAuth discovery flows (RFC 9728/8414, DCR) would have to traverse Access or SecondBrain would need to become the authorization server; the simplest vendor-cloud path is a fixed header carrying a service token. Any phone use through a vendor app therefore requires the public endpoint, and **[implemented]** the Access and Tunnel integrations were "not exercised" at the snapshot ([M0-convergence-report.md L309-320](../docs/build/M0-convergence-report.md#L309)).

Continuity churn in this cluster is faster than anywhere else. ChatGPT Atlas launched October 21, 2025 and shut down August 9, 2026 ([Wikipedia: ChatGPT Atlas](https://en.wikipedia.org/wiki/ChatGPT_Atlas)); Copilot Pro "lasted less than a year" before Microsoft 365 Premium replaced it ([Office Watch](https://office-watch.com/2026/microsoft-365-plans-overview/)); GPT-4o and three sibling models were pulled from ChatGPT on February 13, 2026 ([YourStory](https://yourstory.com/ai-story/openai-retiring-gpt-4o-older-models-chatgpt)); Anthropic's 2026 API deprecations retire Opus 4 and Sonnet 4 on June 15 and Opus 4.1 on August 5 ([Anthropic model deprecations](https://platform.claude.com/docs/en/about-claude/model-deprecations)). SecondBrain's **[spec]** answer is U13 — move the chat role to another provider by editing one line and older turns still read correctly — plus a portable transcript format ([spec.md L118-138](../spec.md#L118), [spec.md L997](../spec.md#L997)), and **[implemented]** the model catalog already refuses "unqualified model-name entries or built-in defaults" so a retirement is a configuration event rather than a silent behaviour change ([README.md L46](../README.md#L46)). The per-assistant verdict: Claude is the most natural client (every surface, OAuth or header credentials, local `.mcpb`, Cowork folder access with "Deleting anything needs your approval" ([Cowork](https://claude.com/product/cowork))); ChatGPT offers the richest consumer connectors with the weakest memory portability and the most contested MCP gating; Gemini complements only through Gemini CLI on paid tiers; Copilot's strengths are enterprise-only; Perplexity has cited search and cheap Spaces but trains by default and has no documented MCP client path.

## Four differentiators are unique, three are parity, and everything visible is behind

Pulling the five clusters together yields a ledger that is cleaner than the product-by-product detail suggests. Four of SecondBrain's **[spec]** commitments have no documented equivalent anywhere in the roughly sixty products surveyed: retrieval that reports its own degradation and refuses to call a failed search "not in your brain" ([spec.md L608](../spec.md#L608), [L636](../spec.md#L636)); citations that resolve to a document revision and a hashed excerpt and still resolve to `deleted` or `changed` after the source moves ([spec.md L655](../spec.md#L655)); a per-turn egress manifest with read caps on what reaches the model ([spec.md L652](../spec.md#L652)); and locality enforced in the transport and the host firewall rather than in configuration ([spec.md L867-869](../spec.md#L867)) — of which only the last is **[implemented]**. Two more are differentiated against every funded competitor but matched at hobby or experiment scale: server-side write proposals that only an interactive human session can approve (nearest: Tana's proposals and Heptabase's read-only mode commercially, graphiti-local and Gemini CLI's memory inbox in open source), and typed documents answered by SQL before vector scoring (nearest: Tana and Capacities properties, Obsidian Bases, Graphiti's bi-temporal edges, none of which pre-filter an AI answer path). Credential-derived provenance on every write is a category blind spot SecondBrain can own by finishing what its schema already reserves. Three commitments are parity, not advantage: plain-file ownership (Obsidian, Basic Memory, Letta local mode, Reflect Open, Claude Code's own auto memory); hybrid keyword-plus-vector retrieval (RAGFlow, Open WebUI, kotaemon, Onyx, Basic Memory, Hindsight); and provider neutrality with local-model support (AnythingLLM, Open WebUI, Khoj, Open Notebook, Jan, Cognee, Mem0 OSS), where SecondBrain's one **[implemented]** adapter is behind on breadth and ahead only on the refusal to ship unqualified defaults. Everything a user can see or touch — ingestion of any format, folder sync, search, chat, citations in a UI, mobile layout, connectors, OCR, transcription, backup — is behind every competitor, because none of it exists.

The closest analogues, by axis, are therefore: Basic Memory on architecture (Markdown plus SQLite index plus hybrid search plus MCP tools with hints, minus ingestion, typing, enforced scopes and approvals); Letta MemFS and Reflect Open on file ownership with BYO models; Open WebUI plus oikb and PrivateGPT `--watch` on watched-folder ingestion; RAGFlow on hybrid retrieval with metadata pre-filtering and chunk-level citations; Onyx and RAGFlow on read-only MCP knowledge servers reachable from Claude Code; Tana on human-approved writes through MCP and typed structure, at the price of a cloud, credits and vendor models; SurfSense 2.x on egress-off-by-default posture; Windows Recall on local-only guarantees for a personal archive; and Gemini Notebook on passage-level citation quality. No single product sits on more than two of these axes at once, which is the whole positioning argument — and also the whole execution risk, because combining them is what the remaining four milestones have to do.

## The comparison exposes five risks the spec does not fully price

The first risk is that the differentiator most visible to users — "files you own, agents can use" — is becoming a trend rather than a niche, so the window in which SecondBrain's ownership story alone earns attention is closing. Reflect open-sourced a local Markdown app in July 2026 ([Reflect blog](https://reflect.app/blog/reflect-open)); Letta made git-backed Markdown the memory substrate for all its agents in February 2026 ([context repositories](https://www.letta.com/blog/context-repositories)); Anthropic formalised file-based memory in Claude Code's docs ([Claude Code memory](https://code.claude.com/docs/en/memory)); Copilot v4 put Claude Code and Codex inside Obsidian in August 2026 ([release 4.0.0](https://github.com/logancyang/obsidian-copilot/releases/tag/4.0.0)); and the Local REST API plugin absorbed the Obsidian MCP server role in May 2026 ([README](https://github.com/coddingtonbear/obsidian-local-rest-api)). Each of these ships monthly. SecondBrain's **[implemented]** state is 39 commits over two calendar days by one author ([M0-convergence-report.md L251](../docs/build/M0-convergence-report.md#L251)), with no M2, M3 or M4 build plan written and every M1 test "planned, not an existing or passing test" ([M1-ingest-and-search.md L8](../docs/build/M1-ingest-and-search.md#L8)). The differentiation that survives this trend is enforcement, provenance and structure, not ownership.

The second risk is that the performance and retrieval claims are entirely unmeasured while competitors run on battle-tested engines. The **[spec]** targets are 100k documents and 1M chunks with hybrid search p95 under 400 ms unfiltered and structured query p95 under 50 ms, holding "4 GB at 1M" of 1024-dimensional vectors in memory for exact scoring ([spec.md L957-969](../spec.md#L957)); the round-one review computed that scanning one such vector set in 300 ms "requires roughly 13.7 GB/s of reads" and that the duplicate embedding cache doubles memory to 8.192 GB ([astra-ultra review #36](../reviews/2026-10-08-astra-ultra-spec-review.md#L182)), and the round-two review warned that row-id growth could reach "about 41 GB of slots after reaching ten million historical IDs" before v0.6 adopted a dense slot map ([round-2 review #18](../reviews/2026-10-08-astra-ultra-spec-review-round-2.md#L64)). No benchmark, seed corpus or `eval/questions.jsonl` exists ([spec.md L1012-1016](../spec.md#L1012)). Open WebUI moved hybrid search into the database on pgvector precisely to stop "loading an entire collection into memory" ([v0.10.0 notes](https://github.com/open-webui/open-webui/releases/tag/v0.10.0)); RAGFlow leans on Elasticsearch because it "meets RAGFlow's core hybrid search requirements" ([FAQ](https://ragflow.io/docs/faq)). The spec's escape hatch — an approximate index that "slots in behind the same interface" ([spec.md L1029-1042](../spec.md#L1029)) — is sound, but the exact-scoring promise should be measured at 100k chunks in M1 before it is marketed.

The third risk is that the approval model, the spec's core safety claim, is also its most likely usability failure, and the evidence from competitors is mixed. The spec's own risk register names "Proposal friction for scripts" and "Approval fatigue leads to auto-approve" ([spec.md L1029-1042](../spec.md#L1029)). Tana, the one commercial product with proposals, still needed trash restore because MCP "can lead to accidental deletions" ([Tana April 2026](https://outliner.tana.inc/blog/tana-current-april-2026)); Letta's agent-to-agent review "does not ask for your approval" and shipped a harmful merge anyway ([Letta Code memory](https://docs.letta.com/letta-code/memory), [issue #4930](https://github.com/letta-ai/letta-code/issues/4930)); Supermemory's review covers only inferred memories ([Memory review](https://supermemory.ai/docs/recall/memory-review.md)); Gemini CLI's inbox is experimental and off by default ([Auto Memory](https://geminicli.com/docs/cli/auto-memory/)). Nobody has demonstrated a proposal queue that a single user tolerates daily. SecondBrain's mitigations — additive metadata stays direct, creates by write credentials are direct, scripts run under a paired CLI session or queue "for a daily approval pass", auto-approve is session-only and limited to `notes/` in turns with no retrieved content ([spec.md L400-412](../spec.md#L400), [L640](../spec.md#L640)) — are reasonable but **[implemented]** only as a `pending_operations` table.

The fourth risk is deployment burden far above every peer, which narrows the audience to a sliver of the already-narrow self-hoster segment. Running SecondBrain requires root provisioning of three Unix identities, a hand-written YAML config with explicit provider, model, capability and limit declarations, an egress helper with `NET_ADMIN`, allowlists that "accept numeric IPv4:port pairs only, with no hostname or subnet wildcard", and a separate GPU host running two vLLM containers with roughly 38 GB of image and weights downloaded in advance ([deploy/README.md L33-47](../deploy/README.md#L33), [deploy/README.md L85-87](../deploy/README.md#L85), [deploy/vllm/README.md L3-18](../deploy/vllm/README.md#L3)); the first systemd install on the Fedora target needed executables relabelled `bin_t` for SELinux, the Server publish merged beside the CLI, and a longer extractor timeout before `/ready` stopped returning 503 ([M0-convergence-report.md L303-307](../docs/build/M0-convergence-report.md#L303)). AnythingLLM "runs locally by default with zero setup friction" ([README](https://github.com/Mintplex-Labs/anything-llm)), Jan "runs 100% offline on your computer" as a desktop app ([README](https://github.com/janhq/jan)), Basic Memory is `uv tool install` plus a folder ([README](https://github.com/basicmachines-co/basic-memory)). The project is explicit that the burden is a fail-closed security choice, and the hardening is real, but the competitors' resource complaints (Onyx's 10 GB, RAGFlow's 16 GB) are about RAM, not about needing sudo and a firewall helper.

The fifth risk is that the security surface SecondBrain has not yet built is exactly where competitors bleed, and the project's own review process has already shown defects slipping through. Parsers produced RAGFlow's Zip-Slip RCE and Open Notebook's LFI and path-traversal advisories ([RAGFlow advisories](https://github.com/infiniflow/ragflow/security/advisories), [Open Notebook advisories](https://github.com/lfnovo/open-notebook/security/advisories)); MCP OAuth produced LibreChat's critical secrets exfiltration, Onyx's critical cross-user token leak and Dify's XSS ([LibreChat advisories](https://github.com/LibreChat-AI/LibreChat/security/advisories), [Onyx advisories](https://github.com/onyx-dot-app/onyx/security/advisories), [Dify advisories](https://github.com/langgenius/dify/security/advisories)); rendered content produced AnythingLLM's prompt-injection-to-XSS and Open WebUI's DOCX-preview session theft ([AnythingLLM advisories](https://github.com/Mintplex-Labs/anything-llm/security/advisories), [Open WebUI advisories](https://github.com/open-webui/open-webui/security/advisories)). SecondBrain's sandbox, per-tool scopes and `HtmlSanitizer` plan address each class on paper, but the M1 parser transport, the M2 MCP endpoint and the M3 Blazor UI that render ingested HTML are all unbuilt, and the M0 code — a far smaller surface — needed ten review fixes on 2026-10-08 and five more defects corrected in those fixes on 2026-10-09, after which "There was no second independent review" ([M0-convergence-report.md L140-151](../docs/build/M0-convergence-report.md#L140), [L245](../docs/build/M0-convergence-report.md#L245)). The repository's roughly 26,000 lines of C# plus a 2,078-line spec and three reviews arrived in two days with explicit references to agent-driven workflows ([README.md L187](../README.md#L187), [M0-convergence-report.md L245-246](../docs/build/M0-convergence-report.md#L245)); that velocity is an asset for catching up and a liability if the surface grows faster than independent review, which is the pattern behind Open WebUI's 158 advisories in a single year. A sixth, smaller exposure sits alongside these: the repository has no license file, so the "never lock the user in" goal ([spec.md L75-81](../spec.md#L75)) is not yet backed by terms, while the cluster's licensing drift (Open WebUI, Smart Connections, Dify) shows users now check.

## Position as the enforced broker between vault and agents, and ship M1 and M2 before anything else

The positioning that the comparison supports is narrow and specific: SecondBrain is the always-on, policy-enforced broker between a Markdown vault the user already edits and the AI agents the user already runs. It is not a chat UI (Open WebUI and AnythingLLM win that on breadth and will keep winning), not a research notebook (Gemini Notebook and Open Notebook own the sources-to-artifacts workflow), not a memory API (Mem0, Supermemory and Zep monetise extraction the spec explicitly refuses to do without review), and not an editor (a stated non-goal, and Obsidian is unassailable). Its user is the person in the spec's §3 — one technical person who "reads, writes, codes, and talks to AI agents all day" ([spec.md L114](../spec.md#L114)) — which is also the person Copilot v4, claude-sidebar and the Local REST API MCP are already serving on the desktop. The pitch to that person is what those tools cannot say: reachable from any device without the laptop running, every write by an agent is a proposal with the credential that made it, every answer says whether retrieval was healthy and cites a revision, and nothing leaves the network unless policy and firewall both allow it. Complementarity should be explicit in the product: Obsidian edits the same folder and queries the same frontmatter through Bases; Readwise, Karakeep, Granola and pendant exports are feeds into the inbox; Claude Code, Claude Desktop, Codex and Gemini CLI are the clients; vendor memory keeps casual preferences while SecondBrain keeps "remember that we chose exact vector scoring because X" with provenance (U4, [spec.md L118-138](../spec.md#L118)). Technical users already draw that line between preferences they will leave with a vendor and knowledge they insist on owning ([HN: Claude Memory](https://news.ycombinator.com/item?id=45684134)).

The priorities follow from where the differentiators live. Every unique guarantee except enforced locality is in M1 and M2 — typed SQL queries, hybrid retrieval with degraded reporting, suppression and purge lineage, then the assistant loop with caps and manifest, proposals, revision-pinned citations, and MCP with per-tool scopes and the read-only bridge ([spec.md L996-997](../spec.md#L996)) — so until those ship the comparison is design against product and SecondBrain loses it on every axis a user can observe. M1 should resolve its five blocking decisions (parser selection and a bounded result transport that replaces the 65,536-byte frame, hard-link policy, seed corpus with recorded embeddings, events-versus-polling, explicit unsupported outcomes) ([M1-ingest-and-search.md L174-178](../docs/build/M1-ingest-and-search.md#L174)) and measure exact-vector latency at 100k chunks on the reference hardware before any public claim, since competitors publish no retrieval architecture and a measured recall@8 and claim-support number would be a credible differentiator rather than a target. The vault format should be Obsidian-compatible by construction so the same files are queryable by Bases on the desktop and by `/query` on the server; Basic Memory shows this costs nothing and buys the ecosystem ([README](https://github.com/basicmachines-co/basic-memory)). M2 should ship the stdio bridge first, because Claude Code, Claude Desktop and Codex can reach a private address today while the Cloudflare Access route for claude.ai and mobile needs a service-token design that the Access integration, still unexercised at the snapshot, must prove ([M0-convergence-report.md L320](../docs/build/M0-convergence-report.md#L320)). The approval queue needs the same engineering attention as the security boundary: a daily approval pass, batch approve of additive proposals, and a paired-CLI path for scripts are the difference between the gate that competitors lack and the gate users switch off, and Tana's trash-restore lesson says deletions through MCP must stay proposals even when creates are direct ([Tana April 2026](https://outliner.tana.inc/blog/tana-current-april-2026)). Provenance should be promoted from a schema column to a headline feature, since no competitor records which credential wrote a memory. Scope discipline matters more than feature parity: the advisory streams of Open WebUI, AnythingLLM and LibreChat track their expansion into terminals, agent filesystem skills, embed widgets and MCP OAuth, and the spec's "The brain indexes and answers; connectors are read-only and deferred" ([spec.md L1029-1042](../spec.md#L1029)) is the right instinct to keep. A single-host deployment profile that preserves fail-closed egress but removes the GPU-host and three-identity prerequisites for first run would widen the audience without weakening the guarantee, and a license file is overdue. Backups, enrichment, calendar and transcript types, SBOM and signed releases (M4) are real but second-order; the retrieval evaluation harness is not, because it is the only way to turn "grounded or silent, and honest when degraded" ([spec.md L99-108](../spec.md#L99)) from a principle into evidence.

## Conclusion

The comparison inverts the asymmetry one expects between a two-day-old repository and a market of sixty products: the competitors have products and lack guarantees, and SecondBrain has guarantees and lacks a product. What validates the spec is not SecondBrain's code but the competitors' incident record — Mem0's 97.8% junk audit, Graphiti's wrongful invalidations, Letta's auto-merged harmful reflection, AgentFlayer and Tainted Memories, Limitless's deleted regional accounts, Cursor's withdrawn memories — each of which maps onto a specific SecondBrain commitment (approved writes, provenance, revisioned files, read caps and manifest, owned files, no built-in vendor). The spec reads less like a feature list than like a design written against the 2025-2026 failure modes of this category, and that is its strongest claim to relevance.

Two things have changed in the understanding of the project. Ownership, the differentiator that looks most obvious from the outside, is the one the market is converging on and the one SecondBrain should stop leading with; enforcement, provenance and typed structure are what remain scarce, and they are precisely the parts that do not exist yet. And the real competitor is not any product in the five clusters but a pattern — Claude Code running inside an Obsidian vault — that already delivers the experience without the daemon and improves every month. SecondBrain's bet is that users will trade that convenience for a server that can prove what it did, what it sent, and who asked; the next two milestones decide whether that bet is ever testable.
