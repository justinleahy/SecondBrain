# Extractor descriptor protocol

The dedicated sandbox listens on `/run/secondbrain/extractor.sock`; directory provisioning, socket activation, `0660` permissions, and the M0 `ping`/`probe_descriptor` contracts are preserved. Requests carry one read-only regular-file descriptor as SCM_RIGHTS on the first prefix byte, never a pathname. Default request deadline is now 120 seconds. Frames remain limited to 65,536 bytes and unknown JSON members are rejected.

Real extraction uses `{"version":1,"id":"request-id","operation":"extract_v2","format_hint":".md"}`. The hint distinguishes plain text from Markdown; PDF, DOCX and HTML are selected from physical bytes regardless of the hint. Responses are ordered version-2 frames `{id,sequence,final,data,version}` with base64 data holding at most 32,768 bytes of a single UTF-8 serialized `ExtractionResult`. The client requires consecutive sequence numbers, matching identity/version, no response descriptors, at most 1,024 frames and 20 MiB serialized output. Lossless text is bounded at 10 MiB UTF-8; metadata, pages, status, tags and links are validated again in the daemon adapter.

Each extraction runs in a disposable subprocess with an empty inherited environment except its private TMPDIR and disabled diagnostics. The worker receives its descriptor over a private socket, creates a separate Unix session/process group, and uses private scratch. At most two parser workers run concurrently, each with a 256 MiB managed GC heap ceiling set before runtime startup. Each worker sets a kernel CPU-time limit of 120 seconds before receiving parser input; the long-lived supervisor has no cumulative CPU-time limit. The supervisor kills the process group and process tree on deadline and cleans scratch. The service continues accepting independent requests. Deployment still must provide the dedicated UID, no network/store/secret access, memory/CPU/process limits and service-level restart behavior. Unit/transport tests do **not** establish the actual systemd or Compose isolation gate.

Supported formats:

- Markdown and UTF-8 text preserve original decoded text. Markdown frontmatter has 64 KiB, 1,000 event/node and depth-8 bounds; aliases are rejected; tags/aliases and links are limited to 200. Authored `id`/`source` are ignored. Frontmatter title/type, aliases, declared creation/update times and props are returned separately; aliases never become tags. Article published_at/author/url fields may appear at the top level or under props.
- PDF text layers retain page markers and offsets; no text produces `needs_ocr`. Pages are limited to 2,000. No OCR, actions, embedded files or attachments are executed. Streaming Flate preflight limits decoded bytes and ratio before PdfPig buffer allocation; LZW streams fail explicitly because this adapter cannot safely bound their decoder. Other supported filters have output checks. Decoded filter output is also bounded cumulatively; complete PDF token/font allocation behavior still needs adversarial host qualification.
- HTML is parsed without a resource loader or scripting, with active/script/style/navigation elements excluded. Offline DOM traversal enforces 100,000 nodes/depth 64 and emits text, title and raw links. This is a basic content projection, **not complete readability scoring or a lossless HTML-to-Markdown converter**.
- DOCX reads only `word/document.xml`, ignoring relationships and resources. Archive members are limited to 1,000, total declared decoded bytes to 10 MiB and ratio to 100:1 (1 KiB small-entry allowance). XML rejects DTDs/entities, has a 10 MiB character limit, 100,000 nodes and depth 64, preserving paragraphs, table-row breaks and tabs. Full style/list/heading-to-Markdown fidelity is not yet implemented.
- WebVTT and SubRip produce plain cue text plus speaker/time/offset segments. WebVTT voice changes within a cue produce separate segments, and overlapping times remain intact. SubRip without explicit voice tags retains an unknown speaker. Markup is stripped and entities decoded; no referenced resource is loaded. At most 20,000 segments and 256 characters per speaker are admitted. Malformed timing returns `malformed_transcript`, and the daemon independently validates every segment's ordinal, time range and UTF-16 text boundaries.

Malformed input returns `malformed_document`; named work bounds return `bound_exceeded` plus `bound`. Provider/OCR support is never fabricated. Logs exclude raw document contents.

Dependency decisions: PdfPig 0.1.13 is pinned for managed PDF text/page extraction and its pluggable filter boundary; AngleSharp 1.5.0 is pinned for standards-based offline HTML parsing; existing YamlDotNet 18.1.0 is reused with low-level event validation before representation-model conversion. DOCX uses built-in ZipArchive and hardened XmlReader, avoiding another document package. All parser dependencies live only in the sandbox; Infrastructure links only the framing/SCM_RIGHTS source. Context7 documentation was retrieved from `/uglytoad/pdfpig`, `/anglesharp/anglesharp`, `/aaubry/yamldotnet`, and `/dotnet/docs`. AngleSharp was raised to the patched 1.5.0 following [GHSA-pgww-w46g-26qg](https://github.com/AngleSharp/AngleSharp/security/advisories/GHSA-pgww-w46g-26qg) (versions through 1.4.1 affected). Initial online package vulnerability-feed verification was unavailable in the restricted environment and restore used command-only `NuGetAudit=false`; no repository audit setting was disabled.

The reusable deployment check is `python3 deploy/tests/extractor-isolation.py --engine podman --image <built-extractor-image>`, or `sudo python3 ... --engine docker` for the CI host fixture. It verifies the actual image with the shipped read-only/network/user/capability/resource settings, descriptor-only Markdown, malformed PDF recovery, 8 MiB output and worker environment. CI runs it after the extractor image build. This does not replace distinct sync/daemon UID staging races or the installed systemd profile qualification.

The Markdown result also reports bounded frontmatter offsets and whether a marked SecondBrain enrichment section can be replaced. This inspection stays in the sandbox. The daemon verifies the returned range against the exact staged text and replaces only its strict generated block, then asks the sandbox to validate the resulting file before journaled write-back. Unmarked authored fields named `secondbrain_enrichment` are preserved by refusing write-back.
