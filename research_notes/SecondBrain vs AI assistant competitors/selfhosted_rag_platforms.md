# Self-hosted open-source "chat with your documents" / RAG platforms as SecondBrain competitors (state as of 2026-10-09)

All GitHub figures (stars, forks, pushed date, open-issue counts, release dates, advisory lists) were read from the GitHub REST API on 2026-10-09 unless stated otherwise. Figures from third-party review sites are marked as secondary. Anything dated before 2025 is flagged "(pre-2025, possibly stale)". Reddit could not be read (search budget exhausted and reddit.com blocks fetches), so "community complaints" lean on GitHub issue reactions, published security advisories, release notes and one Hacker News thread.

## Key Question 0: Per-platform profiles — what each platform is and how it compares to SecondBrain on each dimension

### Takeaway
Every platform in scope is a multi-purpose chat UI or RAG engine first and a personal knowledge store second: none keeps the user's content as the canonical plain-text vault, none types documents into note/article/transcript/event with SQL-answerable who/when questions, none distinguishes "nothing found" from "retrieval degraded", none meters per-turn data exposure to the model, and none gates assistant writes behind human-approved proposals. The closest functional overlaps are Open WebUI (directory sync + oikb daemon + hybrid BM25/vector + MCP client), RAGFlow and Onyx (both expose read-only MCP servers over hybrid indexes), and PrivateGPT 1.0 (local-first API layer with folder `--watch` ingestion). SecondBrain's distinctive claims are therefore (a) plain-Markdown vault + disposable index, (b) typed/structured retrieval before vector scoring, (c) degraded-state and egress reporting, (d) proposal-gated writes, (e) policy-enforced `local_only` with a host-firewall canary, and (f) sandboxed parsing — none of which the surveyed products document.

It's a mathematical process using the 'Cosine Distance' formula" — [Why does the LLM not use my documents](https://docs.anythingllm.com/chatting-with-documents/rag-in-anythingllm). ## Key Question 1: Which platforms are usable as a long-lived personal "second brain" (persistent, growing corpus, folder sync, re-indexing on edits) versus session-oriented "upload a file and chat" tools?

### Takeaway
Persistent corpora exist in all the server products, but keeping a growing local folder in sync with automatic re-indexing is only a first-class feature in Open WebUI (in-app SHA-256 "Sync directory" since v0.9.6 plus the oikb daemon), PrivateGPT (`make ingest --watch`), GPT4All (folder collections watched via `QFileSystemWatcher`, but the project is dormant) and, partially, AnythingLLM (beta per-file "watch", hourly checks, no directory watching, Docker cannot watch local uploads). Onyx and RAGFlow re-sync remote connectors on intervals but have no local-folder watcher; LibreChat, kotaemon, LM Studio and Jan are upload-per-chat/agent/project tools.

### Cited Findings
- Open WebUI: "Add Content > Sync directory mirrors a local folder incrementally ... only new, modified, and deleted files are touched"; "The in-app sync runs in the browser, which is slow for large folders"; oikb recommended "for large or frequently changing libraries" — [Knowledge docs](https://docs.openwebui.com/features/workspace/knowledge/). oikb "keeps it fresh on a schedule, on every push or on demand" with a long-running daemon and 44 connectors — [oikb docs](https://docs.openwebui.com/ecosystem/knowledge-base-sync). Notes provide persistent, editable documents injected whole into context — [Notes docs](https://docs.openwebui.com/features/notes)
- AnythingLLM: watched files "checked **hourly** if it is stale" (stale = 7 days); "You currently _cannot_ watch an entire directory"; Docker: "Manually uploaded files **are not synced**"; corruption warnings — [Live document sync](https://docs.anythingllm.com/beta-preview/active-features/live-document-sync); folder drag-and-drop imports only top-level files as of v1.16.0 — [v1.16.0](https://github.com/Mintplex-Labs/anything-llm/releases/tag/v1.16.0)
- PrivateGPT: `make ingest /path/to/folder -- --watch` "re-ingest on file changes"; `watchdog` dependency — [Ingestion docs](https://docs.privategpt.dev/api-guide/ingestion); [pyproject](https://github.com/zylon-ai/private-gpt/blob/main/pyproject.toml)
- GPT4All: collections bound to folders with `QFileSystemWatcher::directoryChanged` scanning — [database.cpp](https://github.com/nomic-ai/gpt4all/blob/main/gpt4all-chat/src/database.cpp); last release 2025-02-25 — [Releases](https://github.com/nomic-ai/gpt4all/releases)
- RAGFlow: external data sources sync "when the next refresh interval arrives", optional deletion sync; S3 ETag-based incremental sync; no local folder source listed — [Data source sync](https://github.com/infiniflow/ragflow/blob/main/docs/guides/data_source/add_to_knowledge_base_and_sync.md); [Release notes](https://ragflow.io/docs/release_notes)

- Quivr V2 targets "continuous content streams" with durable ingestion but is "evaluation stage ... Do not run it in production yet" — [README](https://github.com/QuivrHQ/quivr)

### Inferences
- For a single user with a Markdown vault, the only turnkey competitors to SecondBrain's watched-folder/inbox model are Open WebUI + oikb daemon and PrivateGPT `--watch`; both re-embed changed files but neither versions documents or distinguishes note types.
- AnythingLLM's per-file watch with hourly polling and 7-day staleness is designed for remote sources (web pages, Confluence) rather than an actively edited local vault.

### Gaps
- Whether Open WebUI's in-app sync or oikb preserves document revision history (not documented; the knowledge export converts files to `.txt`).

## Key Question 2: Which support hybrid search with metadata filters, and which cite sources precisely enough to verify a claim?

### Takeaway
Hybrid (keyword + vector) retrieval is native in RAGFlow (with metadata filters pushed into the index), Open WebUI (BM25 + vector + optional rerank, default off, no metadata filters beyond scoping), kotaemon (full-text + vector + rerank), Onyx (hybrid index with tag filters from file metadata) and Quivr V2 (Weaviate lexical + vector); AnythingLLM and LibreChat are vector-only with fixed top-k. Chunk-level verifiable citations are strongest in RAGFlow ("traceable citations", chunk metadata, chunk visualization) and kotaemon (PDF highlight preview); Open WebUI and Onyx cite documents via citation chips/ids; AnythingLLM shows retrieved chunks; GPT4All shows only file titles; LM Studio and Jan document no citations.

### Cited Findings
- RAGFlow: hybrid weights ("Vector = 0.3, Full-text = 0.7"), similarity threshold, "Show chunk metadata" — [Search settings](https://github.com/infiniflow/ragflow/blob/main/docs/guides/search/search_settings.md); "retrieval only searches content that meets the metadata conditions" — [Metadata management](https://github.com/infiniflow/ragflow/blob/main/docs/guides/dataset/metadata_management.md); "traceable citations to support grounded answers" — [README](https://github.com/infiniflow/ragflow); MCP `ragflow_retrieval` returns chunks "supplemented with dataset names, document names, and available document metadata" — [MCP tools](https://github.com/infiniflow/ragflow/blob/main/docs/develop/mcp/mcp_tools.md)
- Open WebUI: `ENABLE_RAG_HYBRID_SEARCH` default `False`, `RAG_HYBRID_BM25_WEIGHT` 0.5, local CrossEncoder or external reranker, `RAG_TOP_K` 3 — [Env reference](https://docs.openwebui.com/reference/env-configuration); v0.10.0 in-database hybrid search on pgvector — [v0.10.0](https://github.com/open-webui/open-webui/releases/tag/v0.10.0); citation chips and source panel fixes — [v0.11.4](https://github.com/open-webui/open-webui/releases/tag/v0.11.4); a local reranker crashed the server on Apple Silicon before v0.11.4 — [v0.11.4](https://github.com/open-webui/open-webui/releases/tag/v0.11.4)

### Inferences
- None of the surveyed products resolves a citation to an immutable document revision plus excerpt the way SecondBrain specifies; RAGFlow's chunk metadata and kotaemon's highlighted PDF preview are the closest to "verify a claim at the source".

## Key Question 3: Which can enforce fully-local operation, and how (settings only, or network-level)?

### Takeaway

### Cited Findings

- Onyx: "anonymous telemetry is enabled by default but can be turned off at deployment time"; air-gapped deployment supported; embeddings/reranking local — [Data processing](https://docs.onyx.app/security/self_hosted/data_processing); [README](https://github.com/onyx-dot-app/onyx)

### Inferences

### Gaps
- Telemetry defaults for RAGFlow, LibreChat, Dify, kotaemon and PrivateGPT were not found in primary docs.

## Key Question 5: What do power users complain about (search quality, ingestion failures, resource usage, security issues, update churn)?

### Takeaway
Primary-source evidence (issue reactions, advisories, release notes, one HN thread) shows: AnythingLLM users want hybrid search, local rerankers, fine-grained access control and a movable storage folder; Open WebUI users want "data sources", a mobile app and separate extraction settings, and have hit upgrade regressions (web search broken after v0.9.6, Edit/Continue broken) plus an exceptionally large advisory stream; RAGFlow users report heavy resource needs, memory leaks and critical RCEs; Onyx needs 10-16 GB RAM for the Standard edition and a forced index migration; LibreChat has recurring "incomplete fix" advisories and SSRF into its own RAG API; PrivateGPT went silent for 22 months and then broke API compatibility. Reddit sentiment could not be sampled.
