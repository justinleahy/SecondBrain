## What is SecondBrain, who is it for, and what problem does it solve?

### Takeaway
[spec] SecondBrain is a single-user, self-hosted "personal knowledge daemon": one process on the user's own Linux server that ingests files, API posts, and MCP tool calls into a Markdown vault plus a small SQLite state store and a disposable search index, and answers questions from that material with citations, over a private network. [implemented] Today the daemon starts hardened, authenticates, enforces privacy/limits, and persists through crash-safe stores, but does not yet ingest, search, or chat.

### Cited Findings
- [spec] One-paragraph definition: "a personal knowledge system that runs as one daemon on your own Linux server and is reached over a WireGuard-based private network from a laptop or a phone, and from anywhere else through a Cloudflare Tunnel that Cloudflare Access protects. Knowledge goes in through three doors — watched folders on the server, a REST API, and MCP tools — and every door feeds the same pipeline into a Markdown vault, a small durable state store, and a disposable search index." — [spec.md:16](spec.md#L16)
- [spec] "Every item carries a content type with structured fields, so questions about who, when, and which kind are answered by query rather than by similarity. No model vendor is built in: four roles bind to any provider, including the vLLM server on your network, and an instance-wide switch can forbid anything that is not local." — [spec.md:18](spec.md#L18)
- [spec] Document status: "Draft v0.6 — contracts reconciled after the round-two review; ready for M0", dated 2026-10-08, owner Justin Leahy; supersedes v0.5/v0.4/v0.3 which are archived with their reviews — [spec.md:5-9](spec.md#L5)
- [spec] Primary user (§3): "one technical person with a home server who reads, writes, codes, and talks to AI agents all day and wants one place where all of it accumulates and stays queryable from any device on their private network." — [spec.md:114](spec.md#L114)

  - Ops: U18 daemon restarts mid-import and finishes without duplicates or stale chunks; U20 revoking a credential stops its running turn at the next tool call, cancels queued searches, can never approve; U21 a crafted PDF makes the sandboxed extractor fail, the daemon keeps serving, the file shows as failed.

### Inferences
- The product is positioned as infrastructure for one technical person rather than a consumer note app: the spec optimizes for enforcement (authorization, privacy, deletion) and agent interoperability (MCP) over editing UX (explicitly a non-goal).
- Of the 21 user stories, none is end-to-end satisfiable today; the implemented surface covers only the Ops/Config preconditions (U12's refusal to start with a non-local binding, U20's credential revocation plumbing) rather than any capture-or-answer story.

### Gaps
- The spec does not name competing products or a market positioning statement; comparison framing must come from the differentiator list, not from the spec's own words.

## What are the product differentiators as designed?

### Takeaway
[spec] The design's distinguishing commitments are: a never-public-bound single daemon reached over WireGuard/Tailscale or Cloudflare Tunnel+Access; three doors into one pipeline; files-first storage with a rebuildable index; typed documents so who/when/which-type questions are SQL not similarity; exact (not approximate) hybrid retrieval with explicit degraded states; a chat assistant whose writes are human-approved proposals with per-turn exposure caps and an egress manifest; a scoped, read-only-by-default MCP server; vendor-neutral model roles with a local vLLM reference; a `local_only` switch enforced by a policy-owned transport plus a firewall canary; a no-network extraction sandbox; and a logical purge with lineage plus encrypted backups. Most of these are [spec] only today (see the matrix section).

### Cited Findings
**Deployment posture**
- [spec] D2: "One daemon on a Linux server, reached over a WireGuard-based private network and, from outside it, through a Cloudflare Tunnel behind Cloudflare Access; Docker or systemd" — [spec.md:51](spec.md#L51)
- [spec] D9: listener scheme configurable (HTTP, or HTTPS with Tailscale/internal-CA/Cloudflare origin cert); "binds only to loopback and the private-network interface; public reach only through the tunnel; every request authenticated, and public-origin requests must carry a valid Cloudflare Access assertion" — [spec.md:58](spec.md#L58)
- [spec] SEC-1: "There is no public-bind option." SEC-3: every request whose Host is the public hostname must carry `Cf-Access-Jwt-Assertion`, validated against the team domain, audience, and published keys "before any other authentication runs" — [spec.md:818-820](spec.md#L818)
- [spec] Components: one ASP.NET Core daemon (REST, Blazor UI, MCP endpoint, file download path, folder watchers, job workers, scheduler, policy layer; "the only process that opens state.db and index.db"), Engine (Core), Storage, Providers, CLI `brain`, MCP stdio bridge `brain mcp`, Web UI, Extraction sandbox, cloudflared — [spec.md:209-219](spec.md#L209)

**Three doors, one pipeline**
- [spec] ING-1: "Every door produces a Document with a source, a credential-derived provenance, and bytes or text, then enqueues the pipeline. No door has its own parsing or indexing logic." — [spec.md:389](spec.md#L389)
- [spec] ING-3: provenance is `<door>:<credential name>` (e.g. `mcp:claude-code-bridge`, `api:nightly-transcripts`, `folder:inbox`); a client-asserted name is stored as `claimed_client` and never used for authorization — [spec.md:391](spec.md#L391)
- [spec] ING-4: small text captures become keyword-searchable synchronously (target < 1 s); embedding attempted within `ingest.sync_embed_deadline_ms` (default 3000) else `indexed_partial` with `vector: pending` — [spec.md:392](spec.md#L392)
- [spec] Pipeline: `stage → admit → extract → classify → normalize → chunk → embed → index → enrich` — [spec.md:546](spec.md#L546)
- [spec] ING-12 mutation-policy matrix governs every door: creates and additive metadata are direct for write credentials; body/type/property changes, tag removal, and deletion are proposals; "only an interactive session, in the browser or a paired CLI, approves" (D10) — [spec.md:59](spec.md#L59), [spec.md:400-412](spec.md#L400)
- [spec] Formats at v1: `.md .markdown .txt .pdf .html .htm .docx .vtt .srt .ics`; `.csv .json .yaml` as plain text up to 1 MB — [spec.md:425](spec.md#L425)

**Storage model and ownership**
- [spec] D3: "Vault files (authored content) + durable state store (authored non-file state) + disposable index" — [spec.md:52](spec.md#L52); D4: SQLite WAL for both, FTS5 for keywords, vectors as BLOBs held in memory for exact scoring — [spec.md:53](spec.md#L53)
- [spec] Three-store table: vault authoritative; `state.db` authoritative and small (sources, identities, revisions, overrides, suppressions, conversations, credentials, journal…); `index.db` disposable, "Rebuilt from vault plus state with `POST /v1/maintenance/rebuild`" — [spec.md:229-233](spec.md#L229)
- [spec] Rebuild equivalence: "identical authored state, identical deterministic projections (text, chunks, FTS, people, times), and identical citation resolution; model-derived outputs may differ and are reported as such" — [spec.md:944](spec.md#L944)
- [spec] Full export is a maintenance endpoint (`/maintenance/export`) — [spec.md:478](spec.md#L478)
- [spec] Data layout: `/srv/secondbrain/{vault,state,index,keyring,cache,staging,trash,backups,logs}`, a separate `/srv/secondbrain-incoming/{inbox,…}` owned by the sync user, and `/etc/secondbrain/{config.yaml,secrets}` — [spec.md:319-337](spec.md#L319)
- [spec] Managed note format: YAML frontmatter with `id`, `type`, `title`, `created`, `updated`, `tags`, `aliases`, `source`, `source_url`, `occurred_at`, `props` — [spec.md:344-357](spec.md#L344)

**Typed documents, people, time**
- [spec] D11: "One document table with a registry-backed `type`, schema-validated `properties`, nullable `occurred_at` with basis and precision" — [spec.md:60](spec.md#L60); D7: "Structured SQL queries for who, when, and which-type; hybrid keyword plus vector for topics, with filters applied before scoring" — [spec.md:56](spec.md#L56)
- [spec] v1 types: `note`, `article` (author, published_at, url, site), `transcript` (participants, started_at, duration_ms…), `calendar_event` (uid, starts_at, ends_at, attendees, organizer…), `file` fallback — [spec.md:276-280](spec.md#L276)
- [spec] People: role-qualified references (`author`, `organizer`, `attendee`, `participant`, `speaker`), normalized identifiers — [spec.md:299](spec.md#L299)
- [spec] Structured query contract (`POST /query`, `brain_query`, assistant `query_records`): typed predicates on indexed fields only, operators `eq neq in lt lte gt gte exists`, role-qualified people, half-open windows, limit ≤ 200, signed cursors, `coverage` for calendar — [spec.md:612-625](spec.md#L612); RET-10 "no embedding call is made" — [spec.md:605](spec.md#L605)

**Hybrid retrieval**
- [spec] Flow: filters → SQL candidate set C; FTS5 BM25 over C (≤3 chunks/doc, top 50); exact cosine over C's vectors in memory (SIMD, top 50); RRF k=60; optional rerank of top 20; top k=8; neighbor expansion — [spec.md:577-584](spec.md#L577)
- [spec] "Filters are applied before scoring… there is no approximate index in v1"; per-leg document diversity; segmented in-memory arrays (64k vectors/segment) with a dense slot map; candidate cap `retrieval.max_exact_candidates` default 1,000,000 chunks → `degraded: exact-cap` — [spec.md:587-590](spec.md#L587)
- [spec] RET-4 rerank modes `none` (default), `llm` (enrich role), `provider`; failure degrades to fused order with `degraded: rerank` — [spec.md:599](spec.md#L599); RET-13 every response reports `degraded` reasons (`vector-pending`, `embed-unavailable`, `rerank`, `exact-cap`, `coverage-partial`) — [spec.md:608](spec.md#L608)

**Chat assistant**
- [spec] CHAT-1 every claim carries a citation resolving to a document revision and excerpt; CHAT-2 says so when nothing is found, says "degraded"/"partial" instead when retrieval failed, "never reports 'not in your brain' for a failed search" — [spec.md:635-636](spec.md#L635)
- [spec] CHAT-5 tool set (`search`, `query_records`, `read_document`, `list_recent`, `get_related`, `create_document`, `update_document`, `tag_document`, `link_documents`); `ask` surfaces read-only; no shell, no network; per-turn exposure caps — [spec.md:639](spec.md#L639)
- [spec] CHAT-6 every assistant write is a pending operation with an immutable payload; "Only an interactive UI session approves (Approve, Edit, Discard…); API keys and the bridge can never approve"; auto-approve is session-only, creates/appends into `notes/` only, and only in turns with no retrieved content — [spec.md:640](spec.md#L640)
- [spec] Read caps: at most `assistant.max_read_documents` (default 12) newly retrieved documents and `assistant.max_read_bytes` (default 200 KB) of tool-result bytes per turn; "The UI shows an egress manifest per turn listing which documents went to which provider" — [spec.md:652](spec.md#L652); CHAT-7 at most 8 tool calls per turn — [spec.md:641](spec.md#L641)
- [spec] Citation object `{document_id, revision, locator, excerpt, excerpt_hash, granularity}`; invalid `[n]` markers removed and counted; a citation to a vanished revision resolves to `deleted`/`changed` with the stored excerpt — [spec.md:655](spec.md#L655)
- [spec] Harness: `Microsoft.Extensions.AI`'s function-invoking client with an engine-owned executor middleware; allowed-tool set fixed at turn start — [spec.md:651](spec.md#L651); `/chat` is SSE with persisted, replayable events — [spec.md:498](spec.md#L498)

**MCP server**
- [spec] Transports: stdio bridge `brain mcp` on the laptop with "Its own API key, `read` only by default"; stateless HTTP `POST /mcp` per the MCP 2026-07-28 revision (no protocol sessions, no SSE resumption) — [spec.md:506-511](spec.md#L506)
- [spec] "Authorization is per tool, not per route": `initialize`/`tools/list` any credential; `resources/list` read; `brain_search`, `brain_query`, `brain_get`, `brain_list_recent`, `brain_tags`, `resources/read`, `prompts/get` read; `brain_ask` read+infer; `brain_remember` write (direct create); `brain_update` write (always a proposal) — [spec.md:513-522](spec.md#L513)
- [spec] Tools and annotations table; resources `brain://document/{id}`, `brain://note/{path}`; prompts `brain_daily_review`, `brain_topic_brief` — [spec.md:526-539](spec.md#L526)

**Vendor-neutral models**
- [spec] D5 "No built-in default. Roles `chat`, `enrich`, `embed`, `rerank` bind to any provider and model in config"; D6 `Microsoft.Extensions.AI` abstractions with capabilities per binding — [spec.md:54-55](spec.md#L54)
- [spec] Adapters at v1: OpenAI-compatible (vLLM, Ollama, LM Studio, LiteLLM, OpenRouter, most hosted vendors), Anthropic (official C# SDK; native citations, prompt caching, batch), OpenAI, Ollama native (OllamaSharp); later Google, ONNX, llama.cpp — [spec.md:767-773](spec.md#L767)
- [spec] Capabilities per `(provider, model)` binding: `streaming`, `tools` (required for chat), `native_citations`, `reasoning_control`, `prompt_caching`, `structured_output`, `batch`, plus required limits (`context_tokens`, `max_output_tokens`, `embed_dimensions`…); "no unqualified model-name entries or built-in vendor defaults" — [spec.md:749-763](spec.md#L749)
- [spec] Reference hardware: Linux x64 server ≥ 32 GB RAM + NVMe running the daemon in Docker "plus a separate vLLM server with an RTX 5090 on the same private network serving the chat and embedding models" — [spec.md:953](spec.md#L953)

**Privacy enforcement**
- [spec] D12 `local_only`: "local means in-process or on an explicit trusted-service list; enforced before every provider call" — [spec.md:61](spec.md#L61); D16 all provider traffic through one policy-owned transport; shipped units carry the host egress allowlist; a canary detects a missing rule and under `local_only` blocks provider calls, not capture or keyword search — [spec.md:65](spec.md#L65)

### Inferences
- The combination that is unusual relative to typical "chat with your notes" tools is the enforcement stance: write approval by an interactive human session only, per-turn outbound caps with a manifest, and a privacy switch backed by both an in-process transport policy and a host firewall canary. These are mechanisms, not prompts, and the spec says so explicitly (principle 4, SEC-14).
- The "typed documents answered by SQL" differentiator (D7/D11) is what lets the design promise who/when/which-type correctness without embeddings; it is also where the reviews found the most unfinished semantics (calendar occurrences, reclassification; see the risks section).

### Gaps
- None of the retrieval, chat, MCP, sandbox-parsing, purge, or backup differentiators can be observed in running code at this commit; everything in this section is design intent unless restated as [implemented] in the matrix below.

## What is the reference stack and the deployment burden; what must a user do to run it?

### Takeaway
[spec] C# on .NET 10, ASP.NET Core/Kestrel, Blazor Web App with Interactive Server rendering, SQLite (bundled `e_sqlite3` with FTS5), `Microsoft.Extensions.AI`, self-contained `linux-x64` binaries, Docker Compose or systemd, cloudflared. [implemented] The pinned toolchain is .NET SDK 10.0.105 / runtime 10.0.12; running it requires root-level provisioning of three Unix identities (daemon 1654, extractor 1655, sync 1656), a hand-written YAML config with explicit provider/model/limit declarations, an external OpenAI-compatible model server, and either the one-command disposable Docker smoke run or a ~70-line shell sequence on a host with sudo.

### Inferences
- The deployment burden is high for a personal tool: three Unix identities, a root provisioning step, a firewall helper container with `NET_ADMIN`, numeric IP:port allowlists maintained by hand, and a GPU host running two vLLM containers. The project is explicit that this is a security design choice (fail-closed egress, separate sync UID), not an oversight.
- The implemented stack is a strict subset of the §18 reference stack: only the OpenAI-compatible adapter and none of the parser, MCP, sanitizer, or backup-encryption libraries are referenced yet.

### Gaps
- No measured binary size, idle RSS, or startup time appears in the repo; the only footprint numbers are the stack-research estimates.
- The README does not describe a from-scratch Linux bare-metal install beyond pointing to `deploy/README.md`'s systemd section, which itself depends on self-contained binaries placed under `/usr/local/lib/secondbrain` and on operator-pinned IPs.
