## 2. Architecture: where it runs, gateways, the "cloud computer" question

### Takeaway
Hermes is a single-tenant Python process that runs on the user's Linux/macOS/Windows/Termux machine, a VPS, Docker, or serverless sandboxes, with one background "gateway" process connecting 20+ messaging platforms; Nous additionally sells hosted "Hermes Cloud" instances managed through Nous Portal, so the "cloud computer" option exists but is optional.

### Cited Findings
- Install: curl one-liner for Linux/macOS/WSL2, PowerShell installer for native Windows, signed APT repo for Android/Termux (aarch64, `stable` and `canary`), Dockerfile and compose files in repo; README says run it on "a $5 VPS, a GPU cluster, or serverless infrastructure"; terminal backends "local, Docker, SSH, Singularity, Modal, Daytona, and Vercel Sandbox"; Daytona/Modal "hibernate when idle" — [README](https://github.com/NousResearch/hermes-agent)
- SECURITY.md defines it as "a single-tenant personal agent" whose "Agent process" is "the Python interpreter running Hermes Agent, including any Python modules it has loaded (skills, plugins, hook handlers)" — [SECURITY.md](https://github.com/NousResearch/hermes-agent/blob/main/SECURITY.md)
- Gateway: "a single background process that connects to all your configured platforms"; run via `hermes gateway start|stop|status`, systemd user/system service on Linux, launchd on macOS, Scheduled Task on Windows; intro lists Telegram, Discord, Slack, WhatsApp, Signal, SMS, Email, Home Assistant, Mattermost, Matrix, DingTalk, Feishu/Lark, WeCom, Weixin, BlueBubbles (iMessage), QQ, Yuanbao, Microsoft Teams, LINE, ntfy, browser, plus Google Chat, WhatsApp Cloud API, Photon, Raft, IRC, Buzz, SimpleX in the table; "By default, the gateway denies all users who are not in an allowlist or paired via DM" — [Messaging Gateway docs](https://hermes-agent.nousresearch.com/docs/user-guide/messaging/)
- Docs tree on 2026-10-09 contains 34 messaging adapter pages (a2a, bluebubbles, buzz, dingtalk, discord, email, feishu, google_chat, homeassistant, irc, line, matrix, mattermost, msgraph-webhook, ntfy, open-webui, photon, qqbot, raft, relay, signal, simplex, slack, sms, teams, teams-meetings, telegram, webhooks, wecom-callback, wecom, weixin, whatsapp-cloud, whatsapp, yuanbao) — [website/docs/user-guide/messaging](https://github.com/NousResearch/hermes-agent/tree/main/website/docs/user-guide/messaging)
- Other surfaces: web dashboard (port 9119, loopback by default), OpenAI-compatible API server (port 8642, off by default), ACP editor adapter, TUI gateway over local IPC, Hermes Desktop app (macOS 12+, Windows 10/11, Linux via terminal) that can "connect to a remote Hermes gateway over OAuth or username/password" — [Web dashboard docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/web-dashboard); [Docker docs](https://hermes-agent.nousresearch.com/docs/user-guide/docker); [Desktop page](https://hermes-agent.nousresearch.com/desktop); [Release v2026.6.5](https://github.com/NousResearch/hermes-agent/releases/tag/v2026.6.5)
- Hermes Cloud: "runs hosted Hermes Agent instances for you", managed from the `/agents` page in Nous Portal; a Nous-hosted MCP server at `https://portal.nousresearch.com/mcp` exposes `agents` (list/status/cost_estimate) and `agent` (start/stop/restart/create/destroy/update env/update image); "Access requires a Portal account with Hermes Cloud access" — [Manage Hermes Cloud with MCP](https://hermes-agent.nousresearch.com/docs/guides/manage-hermes-cloud-with-mcp)
- Desktop page: signing in to Nous Portal adds "always-on cloud agents", free/discounted models and bundled tool credits; the base app "needs no account" — [Desktop page](https://hermes-agent.nousresearch.com/desktop)
- Official Docker image: gateway runs as non-root `hermes` (UID 10000), "Starting `hermes gateway run` as root inside the official image is refused by default", install tree `/opt/hermes` read-only, mutable state under `/opt/data`; the repo's own `docker-compose.yml` uses `network_mode: host` — [Docker docs](https://hermes-agent.nousresearch.com/docs/user-guide/docker)
- Highly requested architecture change: "Support remote Hermes agent with local tool execution" (#18715, 41 reactions, opened 2026-05-02) — [Issue #18715](https://github.com/NousResearch/hermes-agent/issues/18715)

### Inferences
- The default posture is "agent on your box with your credentials, reachable from chat apps"; the hosted path (Hermes Cloud) moves memory, skills and sessions onto Nous infrastructure, which the docs do not describe in data-handling terms.

### Gaps
- No primary page describes where Hermes Cloud instances run, their pricing, or data retention; the docs only describe the management MCP.

## 3. Models and inference backends, the 64k-context requirement, and whether "fully local" is enforced (Key question: local models and egress)

### Takeaway
Hermes is model-agnostic (Nous Portal, OpenRouter, OpenAI/Anthropic/Gemini/Bedrock/Azure/xAI, any OpenAI-compatible endpoint including Ollama, vLLM, llama.cpp, SGLang, LocalAI, LM Studio, MLX, plus a managed llama.cpp runtime) and documents 64,000 tokens as the minimum context for agentic use; a fully local setup is documented and the FAQ says no telemetry is collected, but there is no in-process "local only" switch; egress restriction is an opt-in Docker-network/Squid or OpenShell configuration, not an enforced mode.

### Cited Findings
- README: "Use any model you want" via Nous Portal, OpenRouter, OpenAI, "your own endpoint" — [README](https://github.com/NousResearch/hermes-agent)
- Provider guides exist for AWS Bedrock, Azure Foundry, Google Gemini, Google Vertex, xAI Grok OAuth, MiniMax OAuth, "run-nemotron-3-ultra-free", local Ollama, local LLM on Mac — [docs tree](https://github.com/NousResearch/hermes-agent/tree/main/website/docs/guides)
- Ollama guide: Hermes "requires at least 64,000 tokens for agentic work with tools"; "By default, Ollama uses a 2048-token context" which is "too small for agentic work"; fix is a Modelfile with `PARAMETER num_ctx 64000`; only `gemma4:31b` in its table is marked as having reliable tool calling; models without tool-call support "can only chat; they can't take actions"; llama.cpp needs `--jinja`, vLLM needs `--enable-auto-tool-choice --tool-call-parser hermes` — [Local Ollama setup](https://hermes-agent.nousresearch.com/docs/guides/local-ollama-setup)
- FAQ: offline config example labels `64000` as "Hermes minimum; set this to match your server's actual context window"; `model.context_length` (example `131072`) and per-model `providers.<p>.models.<m>.context_length`; backends named: Ollama, vLLM, llama.cpp server, SGLang, LocalAI, "any OpenAI-compatible server" (LM Studio in a troubleshooting note); for local endpoints read timeout rises from 120s to 1800s; "Can I use it offline / with local models?" → "Yes"; API calls go "only to the LLM provider you configure" — [FAQ](https://hermes-agent.nousresearch.com/docs/reference/faq)
- Local-models page (managed runtime): "Every recommended model gets at least a 64K context window"; managed runtime is llama.cpp with `backend: auto | cuda | metal | vulkan | hip | cpu`; "Hermes never offers quantizations below 4-bit"; "A GPU with 8 GB+ of memory runs the small catalog models comfortably; 16 GB+ runs the 27–35B models at high quality"; "Nothing leaves your computer: no account, no API key, and no network access after a model is downloaded" — [Local models](https://hermes-agent.nousresearch.com/docs/user-guide/local-models)
- Nous's own Hermes 4 models are "not recommended for use inside Hermes Agent" because they are tuned for chat rather than tool calling — [Nous Portal integration docs](https://hermes-agent.nousresearch.com/docs/integrations/nous-portal)
- Egress: default compose uses `network_mode: host` giving "unrestricted outbound network access"; isolation is opt-in via `docker-compose.override.yml` with an `internal: true` bridge ("no default route, no internet access") plus a Squid proxy allowlist (`acl allowed_hosts dstdomain`, `http_access deny all`) that the gateway reaches through `HTTP_PROXY`/`HTTPS_PROXY`; the page says it is "Not a substitute for sandbox backends" and that DNS on the internal network can still resolve external names unless filtered — [Network egress isolation](https://hermes-agent.nousresearch.com/docs/user-guide/egress/network-isolation)
- "Egress proxy" (iron-proxy) is an "Optional outbound credential-injection firewall for remote terminal sandboxes", a "single-binary TLS-intercepting proxy" so "real API keys never leave the host" — [Egress overview](https://hermes-agent.nousresearch.com/docs/user-guide/egress/)
- SECURITY.md: NVIDIA OpenShell "provides per-session sandboxes with declarative policy across filesystem, network (L7 egress), process/syscall, and inference-routing layers" and is "the supported posture when the agent ingests content from surfaces the operator does not control" — [SECURITY.md](https://github.com/NousResearch/hermes-agent/blob/main/SECURITY.md)
- Local-model experience from HN: one user runs "a fully local stack (self-hosted Matrix plus local inference)" and says "everything is local" — [HN 48419000](https://news.ycombinator.com/item?id=48419000)
- Secondary: a commenter says Nous stated "Qwen3.6-27B is the canonical local model to use Hermes Agent with" — [HN comment (secondary, unverified)](https://news.ycombinator.com/item?id=48558426)

### Inferences
- On an RTX 5090 (32 GB) a 27–35B-class model at 64k+ context is within the documented envelope ("16 GB+ runs the 27–35B models"), so Hermes could share SecondBrain's vLLM server; vLLM needs the `hermes` tool-call parser flag.
- "Local only" in Hermes is a property of the operator's network configuration, not of the software: the hub, taps, plugin catalog, web-search providers, Portal and update probes are all outbound paths that only a Docker `internal` network, Squid allowlist, or OpenShell policy can block. This is the opposite of SecondBrain's enforced `local_only` transport switch plus firewall canary.

### Gaps
- Whether Hermes hard-rejects a model with a window below 64k at startup is not stated in any official page I found (secondary guides claim "rejected at startup"); the docs only describe compression/retry behavior and a startup "Context limit" line.
- I did not read `hermes_cli/source_check.py`/`banner.py` to confirm what the update/release-channel probe contacts; GitHub code search shows those files match "update_check"/"check_for_updates".

## 4. Memory design: where Hermes keeps what it knows, format, limits, export/edit/audit, searchable conversations, external providers (Key question 1)

### Takeaway
Built-in memory is two tiny plain-text files (`~/.hermes/memories/MEMORY.md`, 2,200 chars; `USER.md`, 1,375 chars) injected as a frozen snapshot into the system prompt, written by the model through a `memory` tool (optionally gated by `write_approval`), plus a SQLite `state.db` with FTS5 over every session transcript; nine documented external providers (Honcho, Mem0, Supermemory, Hindsight, OpenViking, Holographic, RetainDB, ByteRover, Memori) can be added one at a time, several of them cloud-hosted; everything is user-readable and editable on disk, but there is no provenance or audit trail for memory writes beyond the transcript.

### Cited Findings
- Files: `~/.hermes/memories/MEMORY.md` ("agent's notes, 2,200 chars, about 800 tokens") and `USER.md` ("user profile, 1,375 chars, about 500 tokens"); non-default profiles use `~/.hermes/profiles/<name>/memories/` — [Memory docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory)
- Injection: "Entries load at session start and are injected into the system prompt as a 'frozen snapshot'"; mid-session writes "are saved to disk immediately but don't appear in the system prompt until the next session" — [Memory docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory)
- Tool actions `add`, `replace`, `remove` (`old_text` substring match); "There is no `read` action"; memory "does not auto-compact", an over-limit write "returns an error" and the agent must consolidate in the same turn; exact duplicates rejected — [Memory docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory)
- Review/edit/audit: inspect with `cat ~/.hermes/memories/MEMORY.md`; `write_approval: true` stages writes for `/memory pending`, `/memory approve`, `/memory reject`; `hermes journey list|delete|edit` manages learned skills and memory chunks, `hermes journey --json` dumps the raw graph; `display.memory_notifications` (off/on/verbose); entries "are scanned for injection and exfiltration patterns, and content with invisible Unicode is blocked"; no bulk export command documented — [Memory docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory)
- Which-file-does-what: `SOUL.md` (persona, user-written, "loaded into the system prompt as slot #1"), `memories/USER.md` and `memories/MEMORY.md` written by the agent through the `memory` tool and gated by `write_approval` or edited with `hermes journey edit`; project context files `.hermes.md`/`HERMES.md`, `AGENTS.md`, `CLAUDE.md`, `.cursorrules` (first match wins) — [Which file does what](https://hermes-agent.nousresearch.com/docs/user-guide/which-file-does-what)
- Session history: "All CLI and messaging sessions are stored in SQLite" at `~/.hermes/state.db` with FTS5; `session_search` "return[s] raw messages without LLM summarization"; `hermes sessions list` — [Memory docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory)
- `state.db` schema: `sessions` (id, source, user_id, model, system_prompt, token counts, `estimated_cost_usd`/`actual_cost_usd`, cwd, git_branch, git_repo_root, profile_name, rewind_count...) and `messages` (role, content, `tool_calls` "stored as a JSON string", `tool_name`, reasoning fields, `message_uid`, `active`); tool results are tool-role rows; no approvals, cron-run or audit tables; export only through the Python API (`db.export_session`, `db.export_all`); `db.prune_sessions(older_than_days=90)`; "Batch runner and RL trajectories are NOT stored here" — [Session storage (developer guide)](https://hermes-agent.nousresearch.com/docs/developer-guide/session-storage)
- FAQ: "Your conversations, memory, and skills are stored locally in `~/.hermes/`"; full backups "include `.env` and `auth.json`" (credentials); profile exports strip credentials — [FAQ](https://hermes-agent.nousresearch.com/docs/reference/faq)
- Dashboard can "Choose the memory provider and reset the built-in `MEMORY.md` and `USER.md` stores", edit `config.yaml`, read/write `.env`, delete and export sessions — [Web dashboard docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/web-dashboard)
- External providers page documents nine: Honcho (catalog; cloud or self-hosted), OpenViking (catalog; self-hosted), Mem0 (catalog; platform cloud, self-hosted server, or local OSS), Hindsight (catalog; cloud or local), Supermemory (catalog; cloud or self-hosted), Holographic (bundled, local SQLite, no key), ByteRover (bundled, local by default with optional cloud sync), RetainDB (bundled, cloud, key required), Memori (external `hermes-memori`, cloud); the three bundled ones "leave core Oct 15, 2026"; the intro says Hermes "ships with 5 external memory provider plugins" — [Memory providers](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory-providers)
- "Only **one** external provider can be active at a time"; built-in memory stays active; Hermes "Prefetches relevant memories before each turn (background, non-blocking)", syncs turns after each response, extracts at session end, and "Mirrors built-in memory writes to the provider" — [Memory providers](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory-providers)
- Privacy notes: everything sent to a provider passes a secret scrub (even with `security.redact_secrets: false`) but "Credentials without a recognizable shape, such as an arbitrary password, are not detected"; "Cloud providers send conversation data to the vendor's servers"; "The Mem0 SDK sends anonymous PostHog usage telemetry unless `MEM0_TELEMETRY=false` is set"; a locally spawned OpenViking server "inherits the Hermes process environment, including any bot or gateway tokens" — [Memory providers](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory-providers)
- Honcho (Plastic Labs) is opt-in (`hermes plugins install honcho`, `memory.provider: honcho`), cloud key from honcho.dev or self-hosted with JWT; after each turn (per `dialecticCadence`) it "analyzes the exchange and derives insights about the user's preferences, habits, and goals", injecting a "user representation" and a dialectic supplement capped by `dialecticMaxChars` (default 600) into the system prompt; no privacy or retention statement on the page — [Honcho docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/honcho)
- README advertises "FTS5 session search with LLM summarization for recall across sessions, plus Honcho dialectic user modeling" — [README](https://github.com/NousResearch/hermes-agent)
- Mem0's own integration page confirms Hermes runs built-in file memory alongside one external provider — [Mem0 docs (third-party primary)](https://docs.mem0.ai/integrations/hermes)
- Community reaction to the memory model: "MEMORY.md summaries of what a session did" (sshine), "it's markdown all the way down" (verdverm) — [HN 48419000](https://news.ycombinator.com/item?id=48419000)
- Highest-reacted memory-related issue: "add mempalace for external memory support" (#6323, 29 reactions, closed); #12238 "Built-in Automatic Backup & Version Control for Agent Data (~/.hermes/)" has 40 reactions and is open (2026-04-18) — [Issue #12238](https://github.com/NousResearch/hermes-agent/issues/12238); [issue search](https://github.com/NousResearch/hermes-agent/issues?q=memory+in%3Atitle+sort%3Areactions)

### Inferences
- "What it knows about the user" is ~3.5 KB of unstructured prose plus full transcripts; there is no typed schema, no revision history (unless the user puts `~/.hermes` under their own VCS), and no record of which credential or channel caused a memory write except by reading the transcript rows in `state.db`.
- Export and audit are feasible but manual: the files are plain text and `state.db` is ordinary SQLite, so a user can `cp`, `git`, or `sqlite3` them; the gaps are provenance and tamper-evidence, not accessibility.
- The frozen-snapshot design plus the small cap pushes "knowledge" into either session search (raw transcript recall) or an external provider, several of which are cloud services that receive the conversation stream.

### Gaps
- No documentation of a memory-write audit log with actor/credential attribution; `state.db` has no approvals table.
- The providers page's "5 bundled" vs nine listed is unreconciled.

## 5. The self-learning skills loop, skills hub and supply-chain record

### Takeaway
Hermes's headline feature is that the model writes its own `SKILL.md` procedures into `~/.hermes/skills/` (unapproved by default), while a Skills Hub pulls third-party skills from eight sources (including ClawHub, the marketplace hit by ClawHavoc) behind a regex "Skills Guard" scanner that Nous itself says is "a review aid", not a boundary; no mass-malicious-skill incident specific to Hermes was found, but a CVE sits in the guard itself.

### Cited Findings
- "The system prompt asks the agent to record a non-trivial workflow with `skill_manage` for future reuse" after multi-step workflows, dead ends that led to a working path, and user corrections; tools `skill_manage` (create, patch, delete, write_file, remove_file), `skills_list`, `skill_view`; a background review "can suggest or stage skill changes" — [Skills docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)
- Storage: `~/.hermes/skills/` is "the primary directory and source of truth"; `SKILL.md` with YAML frontmatter (`name`, `description`, `version`, `platforms`, `metadata.hermes`) plus optional `references/`, `templates/`, `scripts/`, `assets/`, `examples/`; "compatible with the agentskills.io open standard"; also `skills.external_dirs`, project-local `.hermes/skills/` or `.agents/skills/` — [Skills docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)
- Approval: "By default, `skills.write_approval: false` means writes happen freely"; `true` stages writes for `/skills pending|approve|reject` — [Skills docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)
- Hub sources: `official`, `skills-sh`, `well-known`, `url`, `github`, `clawhub`, `lobehub`, `browse-sh`; default GitHub taps include openai/skills, anthropics/skills, huggingface/skills, NVIDIA/skills, garrytan/gstack and two scientific-skill repos ("~480" skills); commands `hermes skills browse|search|inspect|install|check|update|audit|uninstall|publish`, `hermes skills tap add owner/repo` — [Skills docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)
- Skills Guard scans for "data exfiltration, prompt injection, destructive commands, supply-chain signals, and other threats"; downloads staged in `~/.hermes/skills/.hub/quarantine/`; audit log `~/.hermes/skills/.hub/audit.log`; provenance in `skills/.hub/lock.json` ("source URL, content hash, scanner version, and findings"); "`--force` does not override a `dangerous` scan verdict"; trust levels `builtin`, `official`, `trusted`, `community`; optional SkillEvaluator second opinion is "advisory only" and "Without the binary on PATH the scan is silently skipped" — [Skills docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)
- SECURITY.md: "Skills Guard scans installable skill content for injection patterns. It is a review aid; the boundary for third-party skills is operator review before install. Reviewing a skill means reading its Python code and scripts, not just its SKILL.md description — skills execute arbitrary Python at import time"; "Community-contributed skills and plugins" are out of scope: "A skill or plugin doing something malicious is the expected failure mode of one that wasn't reviewed" — [SECURITY.md](https://github.com/NousResearch/hermes-agent/blob/main/SECURITY.md)

## 7. MCP support: client to arbitrary servers (stdio or HTTP + bearer), and whether it exposes an MCP server (Key question 3)

### Takeaway
Hermes is a full MCP client: `mcp_servers` entries in `~/.hermes/config.yaml` support stdio subprocesses and remote Streamable HTTP/SSE endpoints with arbitrary headers (including `Authorization: Bearer ${TOKEN}` resolved from `~/.hermes/.env`), custom CA bundles, mTLS, OAuth 2.1/PKCE, per-server tool allow/deny lists and a `trust: untrusted` mode that forces approval on write-capable tools — so SecondBrain could be its knowledge backend; Hermes also runs a small stdio-only MCP server (`hermes mcp serve`, 10 tools) that exposes its conversations, not its memory.

### Cited Findings
- Hermes "connects *to* external MCP servers and registers their tools automatically at startup"; tools register as `mcp_<server>_<tool>` and a toolset `mcp-<server>`; discovery at startup, `/reload-mcp`, and a config watcher; `mcp.discovery_concurrency` default 4; `lazy: true` connects on first call; `hermes import-agent claude-code` migrates Claude Code's `mcpServers` — [MCP docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp)
- Stdio example `command: "npx"`, `args: [...]`; "Only explicitly configured `env` plus a safe baseline is passed to the process"; HTTP example `url: "https://mcp.internal.example.com"` with `headers: Authorization: "Bearer ***"` — [MCP docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp)
- Config reference for `url` servers: `transport: sse` (otherwise Streamable HTTP), `headers`, `protocol: auto|stateless|legacy`, `ssl_verify` (true / false / path to PEM CA bundle), `client_cert` and `client_key` for mTLS, `timeout` 300, `connect_timeout` 60, `keepalive_interval` 180, `enabled`, `lazy`, `supports_parallel_tool_calls`, `tools.include`/`tools.exclude` (globs; include wins), `tools.resources`/`tools.prompts`, `auth: oauth` (tokens in `~/.hermes/mcp-tokens/<server>.json`), `sampling`, `elicitation`, and `trust: full|untrusted` where "On untrusted servers, write-capable tools need user approval"; `${VAR}`/`${env:VAR}` in `headers` and `url` resolve from the profile secret scope then process env and "fail closed" if unset — [MCP config reference](https://hermes-agent.nousresearch.com/docs/reference/mcp-config-reference)
- OAuth: discovery, PKCE, token exchange and refresh; tokens cached with 0o600; device-code, paste-back and SSH port-forward flows for headless hosts; refresh tokens dropped if the authorization server changes — [MCP docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp)
- Security notes: Unicode TAG characters stripped from tool results; MCP error messages sanitized (`ghp_...`, `sk-...`, bearer tokens → `[REDACTED]`); sampling defaults `max_rpm: 10`, `max_tool_rounds: 5`, "Set `sampling: enabled: false` for untrusted servers"; catalog manifests should be read before install ("Nous PR review is not a substitute") — [MCP docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp); [Security docs](https://hermes-agent.nousresearch.com/docs/user-guide/security)
- MCP stdio subprocesses receive only PATH/HOME/USER/LANG/TERM-type variables plus `XDG_*` and the server's own `env` block — [Security docs](https://hermes-agent.nousresearch.com/docs/user-guide/security)
- Server role: "`hermes mcp serve` runs a **stdio-only** server exposing 10 tools, including `conversations_list`, `messages_read`, `messages_send`, and `events_poll`" and needs the gateway running for sends — [MCP docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp)
- CLI: `hermes mcp` (picker), `hermes mcp catalog|install|configure|login [--flow device]|add --preset codex|test|serve` — [MCP docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp)
- SECURITY.md: MCP subprocesses are "spawned from the agent's environment" and are not confined by terminal-backend isolation; "Hermes Agent includes supply-chain guards for MCP server launches and for dependency / bundled-package changes in CI" — [SECURITY.md](https://github.com/NousResearch/hermes-agent/blob/main/SECURITY.md)
- Secondary: an advisory feed item recommends ≥0.19.0 and pinning "mutable MCP branch references to verified commit SHAs" after an MCP-catalog dependency concern — [Crafted Signal feed (secondary, partial)](https://feed.craftedsignal.io/products/hermes-agent--0.19.0/feed.xml)

### Inferences
- A SecondBrain deployment reachable over Tailscale/WireGuard could be registered as `url: https://secondbrain.tailnet/mcp`, `headers: {Authorization: "Bearer ${SECONDBRAIN_TOKEN}"}`, `ssl_verify: /path/to/internal-ca.pem`, `trust: untrusted`, `tools.include: [search, get_document, ...]`; a Cloudflare Access front door would need a service-token header, which the `headers` map also supports. Hermes's per-server approval on `trust: untrusted` complements but does not replace SecondBrain's own proposal/approval model.
- Because Hermes's own MCP server exposes chat plumbing, not memory, SecondBrain cannot read Hermes memory over MCP; it would have to read `~/.hermes/memories/*.md` or `state.db` directly.

## 8. Tool permissions, approvals, sandboxing, write safety, unattended operation and audit (Key question 4)

### Takeaway
By default Hermes runs shell and file tools on the host as the operator's user; a dangerous-command regex gate (default mode `smart`, where an auxiliary LLM rates risk) prompts via CLI or chat reply, `--yolo` disables everything but a tiny hardline blocklist, unattended contexts (cron/webhook/API) deny dangerous commands by default, memory and skill writes are unapproved unless `write_approval` is set, file rollback checkpoints are opt-in, and Nous's policy states flatly that nothing inside the process is a security boundary; the only provenance is the transcript in `state.db`, the skills-hub lock file, and the dashboard auth log.

### Cited Findings
- SECURITY.md: "**The only security boundary against an adversarial LLM is the operating system.** Nothing inside the agent process constitutes containment — not the approval gate, not output redaction, not any pattern scanner, not any tool allowlist"; the approval gate "catches cooperative-mode mistakes, not adversarial output"; "Prompt injection per se" is out of scope; default local backend with untrusted input is "operating outside the supported security posture"; no bug bounty; 90-day coordinated disclosure — [SECURITY.md](https://github.com/NousResearch/hermes-agent/blob/main/SECURITY.md)
- Approval modes `approvals.mode`: `smart` (default; "An auxiliary LLM rates risk. Low-risk commands are approved for that one command, dangerous ones are auto-denied, and uncertain ones escalate to a manual prompt"), `manual`, `off` (= `--yolo`); CLI options `[o]nce`, `[s]ession`, `[a]lways` (saved to `config.yaml`), `[d]eny` default; over messaging "Hermes posts the command and waits for a text reply" (yes/approve vs no/deny); `approvals.timeout` 300 s fail-closed — [Security docs](https://hermes-agent.nousresearch.com/docs/user-guide/security)
- Dangerous patterns live in `tools/approval.py` (recursive `rm`, `mkfs`, `dd if=`, SQL `DROP`/`TRUNCATE`, `DELETE FROM` without WHERE, `systemctl stop/...`, `chmod 777`, `curl ... | sh`, `docker stop/kill`); hardline blocklist (`rm -rf /`, fork bomb, `mkfs.*` on mounted root, `dd if=/dev/zero of=/dev/sd*`, piping untrusted URLs to `sh` at rootfs) "refused regardless of YOLO" with "no override flag"; `approvals.deny` globs; `command_allowlist`; `hermes approvals suggest` mines past approvals (never proposes recursive deletes, `sudo`, pipe-to-shell) — [Security docs](https://hermes-agent.nousresearch.com/docs/user-guide/security)
- YOLO: `hermes --yolo`, `/yolo`, `HERMES_YOLO_MODE=1`; "saved with the session, so it survives gateway restarts"; status-bar `⚠ YOLO` indicator — [Security docs](https://hermes-agent.nousresearch.com/docs/user-guide/security)
- Backends: `local` (no isolation, checks on), `ssh` (checks on), `docker`/`singularity`/`modal`/`daytona`/`vercel_sandbox` (dangerous-command checks "skipped"; container is the boundary); Docker hardening `--cap-drop ALL`, `no-new-privileges`, `--pids-limit 256`, tmpfs; defaults `container_cpu` 1, `container_memory` 5120 MB — [Security docs](https://hermes-agent.nousresearch.com/docs/user-guide/security)
- File writes: `write_file`/`patch` to `~/.ssh/` (except `~/.ssh/config`, which prompts), `~/.aws/`, `~/.kube/`, `/etc/sudoers`, `~/.netrc`, `.env`, `vault/`, `pairing/`, `mcp-tokens/` are blocked with "**no approval prompt**"; `HERMES_WRITE_SAFE_ROOT` restricts write prefixes (`/opt/data` in the official image); the docs say this "does not sandbox a hostile or compromised agent" because the terminal tool runs as the same OS user; no delete-specific tool or approval is documented (terminal `rm` goes through the command gate) — [Security docs](https://hermes-agent.nousresearch.com/docs/user-guide/security)
- Unattended: `cron_mode`, `single_query_mode`, `unattended_mode` all default `deny` (block dangerous commands rather than wait); `approve` auto-approves in cron; an `api_server` client can answer approval cards via `POST /v1/runs/{id}/approval`; gateway hooks in `~/.hermes/hooks/` "load in-process at gateway startup with no consent prompt" — [Security docs](https://hermes-agent.nousresearch.com/docs/user-guide/security)
- Memory/skill writes: `write_approval: true` (memory) and `skills.write_approval: true` stage writes for `/memory|/skills pending|approve|reject`; defaults are unapproved — [Memory docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory); [Skills docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)
- Checkpoints: "opt-in as of v2 and default to off" (`hermes chat --checkpoints` or `checkpoints: enabled: true`); shadow git repo at `~/.hermes/checkpoints/store/`, snapshots before `write_file`/`patch` and before `rm`, `mv`, `sed -i`, `dd`, `shred`, `>` redirects, `git reset/clean/checkout`; `/rollback <N>`, `/rollback diff <N>`; limits `max_snapshots` 20/project, `max_total_size_mb` 500, `max_file_size_mb` 10, `retention_days` 7; no checkpoints on container backends; skips `$HOME`, `/`, repos over 50,000 files — [Checkpoints and rollback](https://hermes-agent.nousresearch.com/docs/user-guide/checkpoints-and-rollback)
- Logging: `~/.hermes/logs/` ("Monitor" for unauthorized access attempts), `gateway.log`; dashboard auth events in `$HERMES_HOME/logs/dashboard-auth.log` "with sensitive fields redacted"; the approval-history miner masks credentials "but the session database still stores commands as executed"; skills-hub `audit.log` and `lock.json`; `state.db` stores every tool call and result but has no approvals table — [Security docs](https://hermes-agent.nousresearch.com/docs/user-guide/security); [Web dashboard docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/web-dashboard); [Session storage](https://hermes-agent.nousresearch.com/docs/developer-guide/session-storage)
- Gateway auth: default deny, per-platform `*_ALLOWED_USERS`, DM pairing with 8-char codes (1-hour expiry, 3 pending per platform, lockout after 5 failures, files `chmod 0600`), admin vs regular user tiers; SECURITY.md: "Within the authorized set, all callers are equally trusted. Hermes Agent does not model per-caller capabilities inside a single adapter" — [Security docs](https://hermes-agent.nousresearch.com/docs/user-guide/security); [SECURITY.md](https://github.com/NousResearch/hermes-agent/blob/main/SECURITY.md)
- Open feature request "Gateway Permission Tiers — Role-Based Access Control (Owner/Admin/User/Guest)" (#527, 24 reactions, 2026-03-06) — [Issue #527](https://github.com/NousResearch/hermes-agent/issues/527)
- Credential scoping strips KEY/TOKEN/SECRET/PASSWORD-named variables from `terminal`/`execute_code` children; "Any component running inside the agent process (skills, plugins, hook handlers) can read whatever the agent itself can read, including in-memory credentials" — [SECURITY.md](https://github.com/NousResearch/hermes-agent/blob/main/SECURITY.md)
- Real-world consequence: a threat actor "ran Hermes in unattended 'YOLO' mode to automate post-exploitation activity" against Thailand's Ministry of Finance (July 2026) — [BleepingComputer, 2026-07-24](https://www.bleepingcomputer.com/news/security/hermes-ai-agent-used-to-automate-attack-on-thai-finance-ministry/)

### Inferences
- Unattended edits and deletes of files and memories are possible by default: in cron/webhook contexts only regex-matched "dangerous" shell commands are blocked, while `write_file`/`patch` to ordinary paths, `memory` writes and `skill_manage` writes proceed without a human unless the operator sets `write_approval` flags and enables checkpoints. There is no equivalent of SecondBrain's "every write becomes a proposal that only a human in an interactive session can approve".
- Provenance is partial: one can reconstruct who/what caused a write by reading `state.db` message rows (source/user_id on the session, tool_calls on the message), but nothing records a credential identity on the artifact itself and nothing is tamper-evident.

### Gaps
- Whether `write_approval` prompts are delivered over messaging gateways or only in the CLI is not documented on the pages fetched.
- The `managed-scope` page (likely enterprise policy controls) was not fetched.

## 14. Versus SecondBrain: replace, compete, or complement; MCP client potential; what Hermes lacks for a privacy-conscious technical user

### Takeaway
Hermes Agent is an always-on action agent, not a knowledge daemon: it competes with SecondBrain's planned chat assistant on "ask my assistant" convenience and on messaging reach, but it has no typed knowledge store, no retrieval index, no citations, no revisioned files, no enforced local-only mode and no human-approved write pipeline; its strongest relationship to SecondBrain is as an MCP client that would gain exactly those properties by querying SecondBrain as its knowledge backend.

### Cited Findings
- Hermes is an MCP client supporting remote HTTP servers with bearer headers, custom CA, mTLS, OAuth, tool allowlists and `trust: untrusted` write approval — [MCP config reference](https://hermes-agent.nousresearch.com/docs/reference/mcp-config-reference)
- Hermes's knowledge is ~3.5 KB of prose plus transcripts with FTS5; no vector or typed index; RAG proposal #844 open at P3 — [Memory docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory); [Issue #844](https://github.com/NousResearch/hermes-agent/issues/844)
- Document reading is on-demand extraction with no indexing, no OCR and no citation — [Document extraction](https://hermes-agent.nousresearch.com/docs/user-guide/features/document-extraction)
- Writes to memory/skills are unapproved by default; file/command gates are heuristics; "The only security boundary against an adversarial LLM is the operating system" — [Memory docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory); [SECURITY.md](https://github.com/NousResearch/hermes-agent/blob/main/SECURITY.md)
- No in-process egress policy; Docker `internal` network/Squid allowlist or OpenShell is the documented route; default compose is host networking with unrestricted egress — [Network egress isolation](https://hermes-agent.nousresearch.com/docs/user-guide/egress/network-isolation)
- Checkpoints (opt-in, 7-day retention, not on container backends) are the only revisioning, and they cover the working directory, not `~/.hermes` memory — [Checkpoints and rollback](https://hermes-agent.nousresearch.com/docs/user-guide/checkpoints-and-rollback)
- Per-turn exposure to the model is not capped or reported (the frozen snapshot plus prefetch from providers is injected without a manifest); community reports of ~20k-token requests — [Memory providers](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory-providers); [r/hermesagent mirror (secondary)](https://r.datuan.dev/r/hermesagent/controversial)
- Nous itself recommends an operator-side allowlist, Tailscale/VPN, non-root containers and a container backend for production gateways — [SECURITY.md](https://github.com/NousResearch/hermes-agent/blob/main/SECURITY.md); [Security docs](https://hermes-agent.nousresearch.com/docs/user-guide/security)

### Inferences
- Replace? No. Hermes answers "what did we talk about" (transcript search) and "what do I prefer" (USER.md), not "which documents of type X mention person Y in period Z" with a cited revision. It would not replace a vault with typed properties, a rebuildable index, or SQL-answerable who/when/which questions.
- Compete? Partly, on the chat-assistant surface and on reach (Telegram/Discord/Signal/etc.), where SecondBrain's planned Blazor UI and MCP-client-only model are narrower. A user who wants one always-on bot may choose Hermes and never build the knowledge layer.
- Complement? Yes, strongly. Hermes as an MCP client of SecondBrain (over Tailscale with a bearer token, `trust: untrusted`, read-only `tools.include`) would get typed retrieval, citations and degraded-state reporting, while SecondBrain's proposal/approval and per-credential provenance would govern any writes Hermes attempts. The reverse integration (SecondBrain ingesting Hermes memory) is possible only by reading `~/.hermes/memories/*.md` and `state.db` from disk.
- What Hermes lacks for the privacy-conscious technical user, in SecondBrain's terms: typed knowledge (none), citations to a document revision and excerpt (none), revisioned files (opt-in shadow-git for the working directory only), enforced local-only (none; configuration-dependent), human-approved writes with provenance (opt-in `write_approval` flags, no credential attribution, no tamper-evident log), capped and visible per-turn egress (none), distinction between "nothing found" and "retrieval degraded" (none).
- Risk lesson for SecondBrain's design from both projects' 2026 record: exposed control panels and unattended modes, not model quality, caused the real incidents; SecondBrain's choices (no public listener without Access/Tailscale, interactive-only approvals, `local_only` enforced at transport plus a firewall canary) address exactly the failure modes documented for Hermes and OpenClaw.

### Gaps
- No benchmark or user report compares Hermes's transcript recall quality against a structured retrieval system; the comparison above is architectural.
- Whether Hermes would honor SecondBrain's "proposal" semantics (treating a write tool result as pending rather than done) depends on SecondBrain's tool design; Hermes has no native concept of a remote proposal.
